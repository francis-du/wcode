# 不打开 IDE 也能观测工程工作

wcode 的目标是让操作者理解仓库、查看 Agent 活动、定位问题、审查变更并判断证据，而不必打开 IDE。首先要把已有信息连到源码和下一步动作。单纯增加状态卡片，无法完成这条操作路径。

这份 2026-09-30 的调研对照了有代表性的编辑器、Git 工具、CI 系统、终端工作台和可观测性平台的官方文档。它是能力对照，不代表穷尽了所有产品、复现了性能基准，也不表示 wcode 已经替代 IDE 的全部功能。

## 多 Agent 与 token 的市场取舍

| 一手来源 | 已确认的行为 | 本轮采用的原则 |
| --- | --- | --- |
| [Claude Code Agent teams](https://code.claude.com/docs/en/agent-teams) | 独立会话通过共享任务和领取机制协作；额外上下文及协调增加 token 开销。 | 只并行足够大且独立的工作，串行执行同文件修改；交接范围、版本和简短结果。 |
| [OpenCode Agents](https://opencode.ai/v2/docs/agents) | 主 Agent 使用子会话执行专项任务，子 Agent 有自己的权限和模型配置。 | 宿主启动模型，wcode 协调有租约的任务；领取不会授予文件权限。 |
| [Cursor Worktrees](https://prod.cursor.com/docs/configuration/worktrees) 与 [Cloud Agents](https://cursor.com/docs/cloud-agent) | 独立 checkout 或远程 VM 隔离 Agent 的文件和运行环境，提供可检查的产物。 | 共享工作区用明确不重叠范围；需要环境隔离时使用已有宿主 Worktree，检查合并后的版本。 |
| [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching) | 缓存复用提示前缀；实际效果由模型、请求和缓存计量决定。 | 工具目录保持稳定，任务路由在上下文内渐进披露；字节下降不等于计费或缓存收益。 |

`worklist_claim` 与 `worklist_submit` 给模型提供标准领取和提交入口。租约、依赖、当前版本和范围冲突保护协作；主 Agent 对组合结果独立验证。多 Agent 提高并行度与减少总 token 是两个需要分别测量的目标。

领取、续租和提交回复携带 Worklist 摘要，明确标记 `items_included: false`，保留当前版本、状态计数和可运行任务。当前领取项仍在 `handoff.item`，提交结果仍在 `result`。需要完整保留清单时读取 `worklist_status`（`items_included: true`）。这样避免每次单任务交接重复无关历史，不删除持久化任务，也不改变归属和证明规则。单任务交接在上下文预算和行动规划之前移除全局 Worklist 与 Execution 进度，避免无关任务错误要求子任务重复并行。待处理指令、强制验证级别和重新规划要求仍保留，普通协调者的 Agent Context 仍提供 Worklist 发现。交接上下文在精简后重新计算字节数和字节/4的 token 估算。序列化回复字节只是本地测量，不代表提供方 token 或计费节省。

## 已有基础

当前观测台已经展示架构与 Code Graph、任务活动、持久化 Execution、验证证据、变更影响、需求、语言提供方覆盖和有界文件树，也已有命令面板和项目导航。TUI 已有运行时与端点状态、工作区、资源压力、任务活动、工程摘要和授权界面。

[变更检查](../change-inspection/) 已经提供只读的工作树、暂存和未暂存比较，改前与改后语法映射、变更行定位，以及从图节点进入受保护源码窗口。源码身份、仓库版本、精度、脱敏和截断都是这些视图的一部分。新增文件浏览入口复用这些边界，进入受保护的源码导航。

这些信息的证据强度不同。架构声明表达意图，语法关系仍是语法，实时语言提供方可能提供语义，检查输出是执行数据，而版本绑定 Evidence 按自己的规则提供证明。放在同一个工作台里，也必须保留这种区分。

### 架构证据与有界观测

实现映射已解析，说明 Design 引用在源码中的位置已找到；依赖已观测，说明当前保留的源码端点之间存在一条关系；验证已执行，则有独立的版本和运行结果。这是不同的观测：实现映射不等于测试通过，声明依赖未被观测也不代表对应能力未实现。

Observatory 保持原有 5,000 个源码符号预算。Design 中的实现 Symbol 引用按文件批量解析，使精确入口定义优先于无关声明；已有请求调用者保留优先级，直接相邻的一跳调用目标仅按既有解析规则使用剩余名额，之后再在各文件间分配普通定义。Design 引用变多不会提高上限。未解析引用、存在歧义的同名定义和类型未知的接收者，都不能成为制造调用边或提高精度的理由。

组件归属来自精确 Symbol 引用、显式 File 引用及其已解析 trace 映射。Symbol 引用先匹配限定名称，再匹配短名称，不会顺带占有无关的同文件定义。名称有歧义、图或扫描被截断，或者规范 trace 查询明确未解析时，直接匹配仍保持不确定；仅靠这种来源，即使列表里只有一个组件也不能确认 owner。显式 File 引用可以覆盖该文件的节点；已解析的 file trace 只绑定其 File 节点，唯一解析的 symbol trace 则独立确认其精确定义。只有两端各自无歧义地归属于一个不同组件，且关系精度为 syntax、semantic、deterministic 或 runtime，才进入 actual 依赖。syntax 仍然只是 syntax；阻断性漂移继续受原有更强精度规则限制。多归属、单端有归属，以及 declared/heuristic/mixed 关系都保留为候选，不计入 actual、aligned 或 blocking，也不会把 owner 组合笛卡尔展开成虚构组件关系。两端都没有 Design owner 的边不属于这个候选投影。

源码检查器保留原始两端节点 ID、路径、符号、关系类型、provider、precision 和 revision。归属说明区分 `symbol_reference`、`ambiguous_symbol_reference`、`file_reference`、`trace_symbol`、`trace_file`，并明确 unique/ambiguous/unowned 状态。每个已确认组件对最多保留 8 条原始边，配合 `evidence_total` 和 `evidence_truncated`；架构视图最多保留 128 条 `dependency_candidates`，配合 `dependency_candidates_total` 和 `dependency_candidates_truncated`。每个端点最多保留 16 个 owner 样本，同时报告完整 owner 数。这些计数描述有界的观测输入，不代表仓库全部依赖。

把候选当作架构事实之前，应检查原始源码与归属解释。缺失或截断证据持续可见；没有新增证据字段的旧快照仍可阅读，但字段缺失不能补造原始边，也不能证明观测完整。查看图谱或解析测试映射，都不会记录一次实际执行，也不产生验收结论。

| 界面 | 已实现的改进 | 边界 |

操作者路径是：选择工作区 → 选择待处理问题 → 查看详情 → 打开相关源码、活动、提供方、变更或证据视图 → 通过 Agent 或已授权操作解决原因 → 检查新证据。TUI、WebUI 与 Menu Bar 可以采用不同布局，但应解释同一份底层运行时事实。

Menu Bar 是独立 accessory UI 进程，不是第二套 wcode daemon，也不会作为普通 Dock App 抢前台；原生状态项只在 macOS 主线程事件循环已经运行后创建。HTTP/MCP 与 stdio 进程在受保护的本机 authority state root 下发布短生命周期心跳；超过活动窗口的记录不会继续算在线。菜单直接展示 transport 数量、最新 runtime 版本与 Workspace ID、最近 MCP 活动、任务/队列数量和覆盖状态。损坏、别名、超量或覆盖不完整都保持 partial/unknown。非 macOS 平台目前还没有原生托盘，但 `wcode menu-bar --json` 保留跨平台状态契约，供后续 Windows/Linux tray 复用。

任务队列先用完整观测列表解析依赖，再筛选并按八行翻页。缺失、格式异常和不完整依赖保持可见；依赖满足不授予执行权。当前可运行标记必须来自后端报告的 ID，并具有新鲜、完整的观测。Worker 完成仍是报告，不是验证。工作区／所属会话变化清空本地筛选，轻量版本轮询重新判断租约到期，后台刷新保留搜索焦点与中文组合输入。

隔离诊断 `node tests/unit/ui/worklist_ablation.cjs .` 在独立 VM 中加载生产脚本，每次移除一条功能路径，不修改生产文件：

| 移除的功能 | 基线 | 隔离消融 | 恢复 |
| --- | --- | --- | --- |
| 未完成工作优先 | 八项完成历史之后的 2/2 未完成任务可见 | 0/2 可见 | 2/2 可见 |
| 完整观测依赖索引 | 隐藏的已完成前置任务能正确解析 | 前置任务被误认为缺失 | 正确解析 |
| 工作区／所属会话／epoch 重置 | 3/3 身份边界清空旧筛选 | 0/3 清空 | 3/3 清空 |
| 过期／部分／历史状态约束 | 3/3 不确定观测不显示当前可运行 | 0/3 保持约束 | 3/3 保持约束 |

这是可复现的合成行为对照，不是模型基准，也不表示耗时、Token 成本或整体工程效率提升。浏览器交互和项目检查仍需单独验证。新控制台投影不增加模型调用、依赖、执行权限或自动任务状态转换。

### 保留输出定位（第二轮）

现有 Jobs 检查器新增本地输出搜索：输入最多 256 个字符，按字面区分大小写匹配；可选择 stdout／stderr，每页最多 25 个匹配保留行。行号相对于各自保留片段，两个流不构成时间线。截断和脱敏的省略范围持续显示，零命中只表示当前保留文本没有匹配。清空搜索后可查看原始输出块，搜索不读取更多内容或重放命令。

搜索状态绑定精确任务、工作区、所属会话和 epoch。切换任务在请求返回前就撤回旧输出；失败或无效详情清除旧匹配。同任务更新保留查询、有效分页、焦点和中文组合输入。`tests/unit/ui/job_output.cjs` 验证这些行为，并在独立 VM 中分别移除字面匹配、身份边界与覆盖说明：匹配行 2/5→误匹配 5/5→恢复 2/5，任务／owner 边界 2/2→0/2→2/2，覆盖说明 4/4→0/4→4/4。它们是功能对照，未测量耗时或模型成本收益。

### 一手研究复核（2026-10-30 UTC）

初次源码核查之后，联网检索恢复。现已复核以下一手资料；这是有界调研，不表示穷尽最新研究。

- [AgentRewind（2026-08-14）](https://arxiv.org/html/2608.14380v1) 评估上下文与工作区协同恢复，并提供组件消融；外部服务副作用不在恢复范围内，文件系统和 Git 历史也有边界。这里的工程取舍是保留精确任务、输入和失败上下文；不能据此给共享脏工作区增加无限制回滚。
- [SWE-Marathon（2026-06-05）](https://arxiv.org/html/2606.07682v1) 研究长程软件工作与多层独立验证。失败分析和论文说明的评测成本支持实际行为检查与精确运行来源；诊断子集不能推导普遍失败率，完整基准也不适合作为每次改动的开发门禁。
- [OpenAI 编码评测审计（2026-07-08）](https://openai.com/index/separating-signal-from-noise-coding-evaluations/) 在 SWE-Bench Pro 中发现过度约束与覆盖不足等测试问题。修复夹具应保留产品契约：静态资源检查现在比较完整编译脚本，隔离运行夹具补上生产代码使用的渲染依赖。

这些资料用于选择优先级，不代表已经测得 wcode 或 wteam 的效果提升。继续复用现有事实做有界展示、记录实际 CI 评估身份，并执行独立检查。额外规划器、自动无限重试、通用回滚和新的遥测存储仍需具体需求与可复现对照才能进入实现。

## 从设计、实现和任务进入检查器

当前源码接通了两条已有的观测路径：

| 入口 | 操作 | 打开的内容 |
| --- | --- | --- |
| 需求 → 实现引用或验收测试引用 | **检查映射文件** | 受保护 Code Graph 源码检查器中的映射文件，绑定观测时的代码与 Design 版本。 |
| 工程架构 → 组件实现或已观测变更文件 | **检查映射文件** | 同样经过快照与 SHA 校验的精确文件。 |
| 任务活动 → 具有当前持久化 Job 关联的 `run_command` 行 | **查看输出** | 此精确任务的来源、生命周期、报告结果及有界 stdout/stderr。 |
| 任务活动 → 命令任务 | 选择保留任务，再搜索或筛选输出流 | 已返回输出的本地检查；不会启动或重新执行命令。 |

已解析的设计映射可以提供文件路径，即使该文件没有出现在另行限量返回的文件树中。`Dockerfile`、`Makefile` 等无扩展名文件保留精确身份。源码入口不可用只表示当前观测无法提供该路径，不表示文件不存在。旧工作区、旧选择或旧版本的响应不能替换当前源码检查内容。打开验收测试文件不等于执行测试，也不会生成证明。

任务列表和每个输出流可独立滚动。搜索按字面匹配，支持标点和中文，可切换是否区分大小写；可以选择 **stdout**、**stderr** 或两者。匹配行号相对于保留窗口。两个流合计每页最多显示 25 个匹配行，可翻页检查所有保留匹配。原有每流 32 KiB 的保留上限和脱敏规则继续生效；隐藏某个输出流后，截断与脱敏提示仍然可见。保留输出中无匹配，不能说明被省略的日志中没有匹配。

刷新同一任务会保留阅读位置、输出流的展开／折叠状态和键盘焦点；**跳到末尾**由操作者主动触发，轮询不会把正在阅读旧输出的人拉走。输入搜索词时保留焦点。选择另一个任务或切换工作区／会话，会立即清除上一任务的输出和查询。没有有效当前关联的活动行不提供输出跳转，也不会改用另一个任务。任务完成、命令成功、验证通过和 Acceptance 仍分别呈现。

## 后续优先级与取舍

1. **先验证关联上下文的问题入口。** 复用已有数据生产者与源码边界，能直接减少切换成本。保留稳定记录身份、键盘焦点、覆盖不完整提示和真实空状态。刷新失败不等于没有问题。
2. **继续完善结果与输出检查。** 保留命令输出已有本地搜索、流筛选、稳定滚动和活动到精确任务的关联。后续补充原生检查／测试身份、失败位置、生产者信息与真实覆盖率；当前观测契约尚未导出完整命令程序、参数和 cwd。重放命令与查看输出仍是不同操作。
3. **接入提交绑定的外部检查。** CI/PR 观测要区分本地改动、提交 SHA、检查套件、任务、步骤、执行尝试、平台和结论。认证和轮询限制属于集成范围；上一次成功不能证明当前工作树。
4. **关联运行信号。** 先统一已有执行、任务和证据身份。应用 traces、logs、metrics 和 profiles 需要明确采集、保留、脱敏、资源身份与时钟处理。wcode 运行健康度不能代替应用可观测性。
5. **按真实需求加入调试与交互终端协议。** 断点、单步、栈帧、监视变量和局部变量需要调试会话及相应适配器。终端会话需要进程与 PTY 生命周期、输入归属、取消和跨平台验证，无法从普通命令执行推断。

## 仍然存在的缺口

本轮没有建立完整的调试器界面、断点与变量监视流程、任意交互终端会话、外部 CI/PR 日志浏览器或外部链路接入。全面的测试发现、逐测试结果历史、覆盖率可视化、完整历史源码浏览和安全的 Git 冲突解决也仍需后续工作。

文件树和图谱是有界观测。可见快照里没有某个文件，不代表它不存在；已映射测试不代表已执行；历史通过可能过期；缺失提供方不代表诊断干净。所有界面继续受 Workspace、保护路径、命令授权、OAuth 和版本规则约束。

## 验收标准

操作者应能辨认当前工作区与新鲜度，选择真实问题，理解生产者与原因，进入相关上下文，并判断哪些证据属于当前版本。键盘与窄屏流程、工作区切换、过期响应、刷新失败、提供方不可用和数据截断，都需要对实际实现验证。

使用项目验证门禁，并检查原生 TUI 渲染和 WebUI 交互。文档与静态检查不能单独证明端到端可用性、跨平台行为，或所有流程都不再需要 IDE。
