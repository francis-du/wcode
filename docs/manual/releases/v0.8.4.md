# v0.8.4 — Scoped concurrent writers and unified MCP transport policy

v0.8.4 extends wcode's IDE-free engineering runtime with safe concurrent implementation lanes. Multiple authenticated agents can now modify one Git mutation domain concurrently when an approved Reconciliation plan gives them explicit non-overlapping write scopes. The release also unifies MCP protocol-era routing across stdio and HTTP so transport adapters no longer maintain divergent payload-version rules.

## Scope-isolated concurrent writers

- Approved Design/Implementation tasks may declare normalized workspace-relative `write_scopes`.
- Multiple authenticated MCP owners may hold writer leases in the same Git mutation domain only when their scopes are pairwise non-overlapping by equality or ancestor/descendant relationship.
- Unscoped writer tasks preserve the previous whole-domain exclusive behavior.
- One MCP owner may hold only one writer lease at a time, preventing separate task scopes from collapsing into an owner-wide write union.
- Direct file/create/move/delete operations are checked against the claimant's scopes and retain normal SHA preconditions.
- Workspace-mutating commands remain whole-domain operations and are rejected for scoped writers.
- Nested Workspace roots share the same mutation-domain path space; linked worktrees remain separate stronger isolation domains for broad or uncertain lanes.

## Stable remote writer identity

- OAuth ownership is now grant-scoped instead of client-registration-scoped, so separate authorization grants from the same client application receive distinct writer identities.
- Refresh rotation preserves the same grant owner across reconnects and process restarts.
- Legacy persisted token records without an owner identifier preserve the previous client-bound ownership fallback.
- Malformed persisted owner identifiers fail closed during OAuth state loading.

## One MCP protocol policy across transports

- stdio and HTTP now share one payload-level protocol selection policy.
- `server/discover` and modern `_meta` routing are interpreted consistently across transports.
- HTTP keeps its transport-specific header validation, but a modern request body cannot be silently downgraded by a conflicting legacy protocol header.
- Header/body mismatches remain fail-closed.

## Reconciliation and recovery

- Reconciliation execution updates are transactionally persisted so concurrent scoped claims do not overwrite one another.
- Writer status exposes multiple active/pending owners and their sanitized scopes without exposing reservation tokens.
- Submission and failure release only the matching owner/plan/task lease.
- After restart, durable claimed writers without matching runtime ownership remain blocked until ownership is reconciled rather than being treated as permission to write.

## Stable runtime and discovery contracts

The primary bounded coding entry remains `agent_context`. Resource presets remain `balanced`, `fast`, and `light`, and JavaScript behavior CI uses Node 24. Command results continue to expose `timed_out` and `output_incomplete` instead of converting bounded execution failures into success.

CLI discovery remains side-effect free:

```text
wcode help-all
wcode help-all setup
wcode help-all --json
```

The hardened inspection-only combination remains `--read-only --no-exec --no-semantic`. Final Rust release verification includes:

```text
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

## Release verification

The v0.8.4 candidate must pass locked format/check/clippy/test/release-build gates, Design/traceability/drift/risk review, release metadata and installer contracts, revision-bound Verification Mesh stages, runtime canaries, blind reviewers, policy-required human approval, and the clean-worktree 300-round adversarial audit before tagging.

The release flow remains: reviewed release-prep commit → non-force push → exact-SHA green CI → `v0.8.4` tag → cross-platform artifacts, checksums, and GitHub Release publication.
