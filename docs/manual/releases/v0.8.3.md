# v0.8.3 — Capability-aware MCP and edit-ready Agent Context

v0.8.3 continues the IDE-free engineering-runtime work by making a large MCP surface easier for models to use without weakening the execution boundary. The release adds capability-aware progressive disclosure, tighter task-scoped `agent_context` packing, isolated Jev policy, modern MCP task compatibility, and a stronger 300-round adversarial release audit.

## Capability-aware MCP discovery

- The MCP catalog keeps the complete tool surface available while exposing a compact core and bounded on-demand capability groups.
- `agent_context` now carries task-scoped recommended tools and actions so models can discover the next useful capability instead of reasoning over the full catalog on every turn.
- Core safety controls remain non-negotiable: Workspace boundaries, authorization, SHA preconditions, writer leases, and verification authority are not delegated to model guidance.
- MCP discovery and server instructions remain model-neutral and preserve compatibility rather than hiding tools behind client-specific behavior.

## Tighter edit-ready Agent Context

- Tight budgets yield advisory prose, large relationship overlays, duplicate source-backed map metadata, and optional tool metadata before edit-critical source.
- Multiple explicit targets retain complete source bodies and matching current SHA preconditions through the 2K path when the requested sources fit the budget.
- The strongest repository-map evidence is retained through ordinary compaction, while redundant relationship-free entries can yield only when the same current identity and complete source are already present.
- Compaction is bounded and must make real serialized-byte progress; compact execution state is never replaced by a larger summary.

## Jev and verification authority

- Jev routing policy is separated from its transport/runtime plumbing and remains advisory-only.
- Jev can promote additional bounded retrieval or verification work, but it cannot remove deterministic checks, grant mutation authority, or lower an existing verification floor.
- Verification Mesh keeps deterministic, property, mutation, fuzz, runtime-canary, blind-review, and explicit human-approval stages revision-bound.

## MCP task and runtime reliability

- Modern MCP task capability is negotiated per request and durable tasks remain pollable, cancellable, owner-scoped, and recoverable without replaying completed effects.
- Cancellation retains real worker/admission capacity until the underlying work has actually stopped.
- Command results continue to expose `timed_out` and `output_incomplete` rather than converting bounded execution failures into false success.
- Resource governance keeps foreground engineering work responsive while retaining host-wide and per-Workspace limits.

## Release audit

The release audit now requires 300 distinct adversarial rounds. Every round must execute non-zero Rust tests and report stable inputs; shard and full-suite evidence must bind to the same exact revision and input digest before release approval.

The primary bounded coding entry point remains `agent_context`. Resource presets remain `balanced`, `fast`, and `light`, and JavaScript behavior CI uses Node 24.

CLI discovery stays side-effect free:

```text
wcode help-all
wcode help-all setup
wcode help-all --json
```

The hardened inspection-only combination remains `--read-only --no-exec --no-semantic`. Final Rust release verification includes:

```text
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

## Release verification

The v0.8.3 candidate must pass locked format/check/clippy/test/release-build gates, Design/traceability/drift/risk review, release metadata and installer contracts, Verification Mesh stages, runtime canaries, blind reviewers, explicit human approval where policy requires it, and the clean-worktree 300-round adversarial audit before tagging.

The release flow remains: reviewed release-prep commit → non-force push → exact-SHA green CI → `v0.8.3` tag → cross-platform artifacts, checksums, and GitHub Release publication.
