# wcode v0.5.2

v0.5.2 is a governance and agent-experience release. It reduces MCP call noise, makes independent work easier to execute concurrently, gives local users a one-command Agent setup path, completes human authorization for stdio MCP, and tightens revision/target-aware verification without weakening existing Workspace or authorization boundaries.

## Cleaner MCP calls

- Model-facing Tool schemas no longer advertise server-default values. Runtime defaults are unchanged.
- Low-frequency tuning fields such as limits, timeouts, result counts, graph sizing, and body sizing are hidden from the advertised model schema while explicit legacy callers remain accepted by the runtime.
- The optional `workspace` argument now explicitly says to omit it unless switching away from the default Workspace.
- Server instructions and the portable Agent Skill tell models to send only required arguments and omit inferable path/limit/timeout/budget values.
- `parallel_tools` remains available for compact fan-out, but large nested argument payloads are no longer the recommended way to express concurrency.

The result is a smaller tool-call surface in MCP Hosts without changing the underlying safety or execution capabilities.

## Dependency-aware parallel agent work

- `agent_context.readiness.parallelism` now exposes a strategy and candidate-lane count.
- Single-target work reports `single_lane`; independent multi-target work can report `top_level_concurrent_calls`.
- The workflow explicitly asks the model to split work by dependency first, execute independent discovery/read/review/file-local lanes concurrently when the Host supports it, and serialize only real dependencies.
- Bulk primitives such as `read_files`, `search_many`, `apply_file_edits`, and `create_files` remain preferred when the inputs are already known because they reduce round trips without creating nested MCP noise.
- Parallel model agreement remains model evidence, not deterministic proof.

## One-command setup and CLI lifecycle

The normal local path is now:

```bash
cd /path/to/repository
wcode setup
wcode
```

- Interactive `wcode setup` offers Global (recommended) and Current project scopes. Global mode writes only verified user-level Host paths after local confirmation; non-interactive setup defaults to project scope.
- Local Host entries use only `wcode mcp-stdio`; the Host working directory is the default Workspace, so installation no longer bakes repository paths into MCP configuration.
- `wcode setup --dry-run` previews changes without writing; `--json` keeps the structured automation path.
- The canonical package source is now the shorter `plugin/` directory, and the installed binary embeds it; users do not need any plugin directory in their project for setup to work.
- The installed Skill is simply named `wcode` and includes lifecycle guidance (`wcode setup`, `wcode update`), compact tool-use rules, Worklist recovery, and a preference for wcode repository tools over overlapping generic session tools.
- `agent-plugin` remains available for package export and compatibility, but is hidden from the default command catalog.
- `restart` and `stop` are removed: foreground HTTP/TUI lifecycle is owned by Ctrl-C / SIGTERM, stdio lifecycle is owned by the MCP Host, and upgrades use `wcode update`. The separate runtime control route/token state is removed with them.
- Low-frequency transport, resource-tuning, and broad trust-boundary flags remain accepted but no longer crowd default `--help`.
- The original WCode ASCII logo remains part of CLI help, followed by the compact CLI contract.
- `wcode update` safely updates the current installation through the verified release installer contract.

The Unix and Windows installers now print the shortest next step after installation: run `wcode setup`, then `wcode` from a repository.

## stdio human authorization

Local stdio MCP no longer depends on the TUI/WebUI being the only place a user can approve a gated command.

- MCP 2026 clients use multi-round-trip `input_required` elicitation.
- Compatible 2025-era stdio clients use `elicitation/create` only after form-elicitation capability negotiation.
- Authorization retry state is bound to the pending authorization, MCP client owner, and an opaque random challenge.
- The challenge remains private runtime state rather than a model-facing grant token.
- A Host without form elicitation fails closed. wcode does not expose a model-callable approval Tool and does not read terminal yes/no input from the stdio protocol stream.

## Durable work, source context, and operator access

- A per-Workspace revision-guarded Worklist persists unfinished model tasks across reconnects or model switches. `agent_context` restores the active list; updates cannot silently drop unfinished items, and stale concurrent revisions fail closed.
- `read_file` / `read_files` preserve original source formatting and allow up to 1,000 lines per file/call. The Skill still prefers symbol/outline localization first rather than minifying source or flooding context.
- `parallel_tools` inherits its parent Workspace for child calls unless a child explicitly overrides it, preventing parallel fan-out from silently falling back to the process default root.
- TUI Full Access is an explicit operator confirmation that adds current-user Home and enables otherwise-authorizable runtime capabilities. `--full-access` provides the explicit CLI form. Hard protected paths, symlink/hard-link boundaries, no-shell policy, and filesystem-root restrictions remain enforced.

## Tunnel recovery and stable endpoints

- Managed tunnel health now fails closed without indexing an empty live-tunnel set when the last primary disappears.
- When every public tunnel is down, public-health state returns to pending and the runtime falls back to its local URL while the provider is respawned.
- Provider recovery starts at 5 seconds with bounded exponential backoff and resets the failure history after a verified reconnect, so an old outage does not leave future recovery stuck near the maximum delay.
- Recovery health probes run more frequently while an endpoint is unhealthy.
- Cloudflare Quick Tunnel, localhost.run, and Pinggy remain session-style endpoints: a reconnect may produce a different hostname. wcode can register the new URL locally, but an already-configured remote MCP client cannot discover a changed hostname by itself. Use Tailscale Funnel's stable `ts.net` hostname or an operator-managed stable `--public-url` for durable remote connector configuration.

## Revision and target-aware verification

- Verification Plans bind the complete active revision: code plus Design State.
- A Design-only contract change cannot silently reuse a plan created for an older active specification.
- Historical Evidence stays auditable, while new revision Evidence cannot leak into an older plan.
- Correctness review is contract-first: ambiguous requirements produce `Inconclusive`; `Fail` requires an observable counterexample, invariant violation, or reproducible behavior rather than a preferred patch style.
- New verification plans freeze stage targets such as language targets.
- Property/Mutation/Fuzz/Runtime Evidence declares the targets it actually covers, so one language cannot clear another language's gate.
- Risk reporting now exposes target-specific local automation gaps instead of pretending a declared policy implies an available executor.

## Documentation and release navigation

- README, Getting Started, Agent integration, CLI/MCP reference, website quick start, plugin documentation, and installer output use the same `Install → wcode setup → wcode` path.
- Day-to-day docs no longer lead with advanced tunnel or resource tuning.
- MCP guidance now documents compact arguments and dependency-lane concurrency directly.
- Release history moved behind one stable Releases index. The global sidebar no longer grows by one item for every release.
- English and Chinese release indexes group history by series and keep the latest version prominent.

## Upgrade

Existing installations can update directly:

```bash
wcode update
```

Or use the release installer:

```bash
curl -fsSL https://raw.githubusercontent.com/francis-du/wcode/main/install.sh | sh
```

Then, in a repository:

```bash
wcode setup
wcode
```

Existing project-local MCP configuration, explicit advanced flags, persisted Design State, Verification history, Evidence, and OAuth state remain compatible. The only intentionally removed CLI entries are the low-value `restart` / `stop` controls.

## Release gates

The release revision must pass:

```text
git diff --check
cargo check --locked
cargo fmt --check
cargo test --locked
cargo clippy --locked -- -D warnings
cargo build --release --locked
```

The release workflow also validates version-locked crate/plugin manifests, installer contracts, source/documentation layout, and platform release artifacts.
