# v0.7.4 — Workspace 会话全授权、标准 MCP 多媒体与当前产品文档

v0.7.4 聚焦 Operator Experience 与 MCP 互操作：用户可以为当前 Runtime 中的一个 Workspace 显式开启“全部命令授权”，`read_media` 改为直接使用标准 MCP Image/Audio Tool Result Content，同时 README、官网、产品截图与系统图全部按当前真实能力重新整理。

Release Candidate 先 Commit 并 Push。只有该精确 Commit 的普通 CI 全绿后，才创建 `v0.7.4` Tag。

## 精确批准，或当前 Workspace 本次运行全部授权

TUI、受保护 Engineering Observatory WebUI 与支持 Form Elicitation 的 stdio 现在共享同一份 Workspace 级 Runtime 授权状态。用户可以只批准一个精确请求，也可以选择 `all_commands` 为当前 Workspace 本次运行全部授权，或者拒绝。TUI 授权视图中按 **A** 开启全部授权，命令视图中按 **F** 开关；WebUI Access 面板提供同一个显式开关。

Session Grant 会处理该 Workspace 已经待处理的 `CommandAccess` 与 `RiskyExecution`，并在关闭或 Runtime 退出前消除重复授权提示；不会扩散到另一个 Workspace。文件删除仍保持一次一条的一次性精确授权，永久阻断的命令形态也不会因为全部授权而被放开。

## 标准 MCP Image / Audio Tool Result

`read_media` 继续 Metadata-first。调用方设置 `include_content=true` 就是单次调用的显式 Opt-in，wcode 直接返回标准 MCP `image` / `audio` Content Block，不再要求私有的 `run.francis.wcode/media-content` Extension。PNG/JPEG/GIF/WebP 与支持的音频内容因此可以在请求时通过普通 MCP Tool Result 返回。MCP 没有标准 Video Tool Result Content Block，所以 Video 继续只返回 Metadata。

## 当前截图与活系统文档

官网 Product Tour 现在使用当前 TUI，以及 Engineering Observatory 的 Overview、Engineering architecture、Task activity、Verification evidence、Current changes、Requirements、Project files、Access 和 Setup Hub 截图。已经不存在或不再代表当前产品结构的旧 Observatory / Verification / Workspace Intelligence 截图被清理。

根 README 重构为紧凑的产品入口，不再充当版本与链接索引。四张 SVG 分别解释工程控制闭环、Repository Intelligence Stack、Verification Mesh 与安全边界；英文与中文各自维护，官网把它们作为“活系统模型”展示，产品架构、证明模型或 Trust Boundary 变化时必须同步更新。

## 可靠性与兼容性

`agent_context` 继续作为任务就绪仓库检索主入口。命令结果继续暴露 `timed_out` 与 `output_incomplete` Diagnostics。`balanced`、`fast`、`light` 资源预设保持兼容。Hardened Inspection-only 组合仍为 `--read-only --no-exec --no-semantic`。

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 查看 Parser 定义的完整命令面。Release CI 继续安装 Node 24 运行打包 JavaScript 行为测试。

## 发布门禁

Release Candidate 必须通过 `git diff --check`、`cargo check --locked`、`cargo fmt --check`、`cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 与 `cargo build --release --locked`。同一轮还校验 Design State、Product Scope、中英文文档、当前 UI Contract、Release Metadata 与 Installer/Plugin Manifest。

v0.7.4 Commit 到达 `main` 后，该精确 SHA 的普通 Build & Release 与 Documentation CI 必须全绿，之后才创建 `v0.7.4` Tag。Tag Workflow 再构建并 Smoke-test Linux、macOS Universal 与 Windows 分发包，最终发布 GitHub Release。
