# v0.7.5 — 入口信任与操作界面稳定性

v0.7.5 加固入口所有权、TUI 按键分发、观测台渲染与仓库验证。本地验证不能代替精确发布提交的 CI，也不能代替升级后运行实例的复核。

## 入口所有权与 403 诊断

所有通过实例校验的隧道 URL 现在都是并发 active 入口；自动模式不再把健康 Provider 分成主备。每个 URL 都有身份绑定、单飞的健康 Lease 和独立恢复 Worker。健康入口每三秒探测，异常入口每秒探测，调度器不等待网络请求完成。连续两次失败进入健康隔离，同时在有界的 30 秒原地恢复窗口内保留进程、URL 与 Host 信任；连续两次成功恢复为已验证状态。Cloudflare 限流使用五分钟冷却，其他故障继续使用有界错峰重试。

每次验证注册都会获得新的 Epoch。清理时原子比对 Epoch 后再撤销信任，旧 Provider 不能删除同 URL 的新注册，也不能用重试状态覆盖新遥测。保留的稳定地址按 URL 索引，最多八个；同一 Provider 换地址后，旧地址仍接受独立的实例健康探测。启动失败本身不撤销保留入口，恢复统一进入正常 Connected 生命周期。用于界面复制的默认 URL 只影响展示，不获得独占路由、健康或授权权力。

未注册的 Host、不合法的 Origin 和未授权请求仍然拒绝，历史 OAuth Resource 不会激活 Host。这些修复针对已识别的生命周期竞态，不代表所有 HTTP 403 都应放行，也不保证不健康入口持续可达。

## TUI 快捷键

`A` 只用于可见请求所属 Workspace 的命令全授权，作者主页改为 `B`，帮助和文档同步。统一的上下文解析避免 Ctrl/Alt/Super 组合键误触普通快捷键。文本输入和 Full Access 确认独占按键；重复按键事件不能重复授权、切换开关、提交或打开链接，可见导航和文本编辑仍支持连续输入。

## 观测台布局与刷新

代码统计改用可收缩的名称／数值列，进度条单独占一行，不再因固定列宽覆盖相邻统计。验证预览按内容计算高度，长测试名自动换行，快速失败列表使用独立布局。全宽顶栏现在使用明确且可收缩的行内尺寸；证据网格及其子项抑制固有宽度扩张，受限宽度下检查器回到普通文档流并使用单列。英文说明不再暴露内部翻译键名。

刷新错误区分授权、Host／Origin 拒绝、超时、响应异常和渲染异常，不在页面直接显示内部路径或堆栈。完整项目快照请求使用 120 秒有界等待，轻量缓存请求保持 30 秒。渲染失败不能把新快照版本记为成功；自适应检查仍是只读规划预览，不会从观测台直接执行。

## 仓库完整性与失败关闭的发布门禁

源码与 Design 缓存会识别内容等长、修改时间被恢复的重写。已验证变更存储校验记录完整性并拒绝重复／冲突历史；授权请求去重同时绑定 Workspace 与操作类型。代码约束扫描区分维护中的源码、已声明的构建产物与已初始化子模块。

发布就绪检查拒绝空工作区审计，以及缺失或类型错误的 Convention／Product Scope 结果，不再把缺字段解释成零错误。迁移检查区分确实不存在的禁止路径与被策略阻止、符号链接或无法访问的路径；检查失败不能当作删除成功的证据。两类问题均有修复前失败、修复后通过的回归测试。

## 兼容性

编程入口仍为 `agent_context`，执行诊断 `timed_out` 和 `output_incomplete`、标准 MCP 多媒体和 Workspace 安全边界保持兼容。获得精确授权的 `git ls-remote` 与单分支 `git fetch` 可以同步已配置远端，同时继续禁止任意 URL、通配 Refspec、Prune、Pull 与 Force 模式。性能预设仍为 `balanced`、`fast`、`light`；仅检查会话可使用 `--read-only --no-exec --no-semantic`。CI 的界面行为测试继续使用 Node 24。

完整命令目录无需启动运行实例即可查看：

```sh
wcode help-all
wcode help-all setup
wcode help-all --json
```

## 验证与发布

在同一稳定工作树版本上执行 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings`、格式检查和 `cargo build --release --locked`。新增测试覆盖快捷键上下文／修饰键、保留地址探测、按代次撤销信任及长文本渲染。`node tests/unit/ui/layout.cjs .` 用生产渲染器 HTML、随包 CSS 和合成数据生成测试页；macOS 上再执行 `swift tests/unit/ui/layout_webkit.swift`，用 WebKit 在 375–1920 像素的十二种宽度下检查中英文真实布局。

macOS 上运行 `node tests/release_audit.cjs` 可执行 30 轮不同场景的对抗检查：Rust 与 Web 两条独立验证线并行，每项要求实际命中测试、执行有界，并比对检查前后的输入摘要。结果保存在 `target/wcode-adversarial-30.json`。完整生产页面的 WebKit 审计覆盖十二种宽度（320–1920 像素）、中英文、明暗主题与证据／总览页面的 96 种组合。跨平台渲染故障场景已接入 `cargo test`，macOS CI 也执行真实 WebKit 审计。

发布顺序为审查提交 → 非强制推送 → 精确 SHA 的 CI 全绿 → 版本标签 → 分发包构建与冒烟测试。安装后必须重启正在运行的 wcode、重新连接 MCP 并重新打开观测台；构建新二进制不会自动更新旧服务进程。
