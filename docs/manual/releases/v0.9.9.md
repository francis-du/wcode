# wcode v0.9.9

This version closes three gaps where a verification plan could read as current when it was not, and stops two surfaces from printing absent measurements as zeros.

| Change | User-visible behavior |
| --- | --- |
| Git identity gate | The plan result now requires the evidence's record and receipt Git bindings to match the workspace identity whenever the workspace has one. `git add` or `git commit --allow-empty` leaves the code and design revision unchanged, so a plan could read `ready` after the index or HEAD moved while canonical Acceptance rejected the same evidence as stale. Without a Git identity there is nothing to compare against, so the behaviour is unchanged. |
| Policy binding | Evidence whose recorded policy binding differs from the plan's policy no longer satisfies it, even when the code and design revision are unchanged. |
| Reuse chain | A reused check whose source this snapshot can no longer see no longer reads as a current Pass. Retention may prune the source after the receipt was written; canonical Acceptance already reported Inconclusive for that case. |
| Superseded plans | The design consistency matrix carries the revision each plan's verification is bound to and labels a plan on another revision as superseded, instead of letting its task counts read as the current input's result. Drift ids are stable across revisions, so a stale plan can still claim a current finding. |
| Absent comparison and timing | A decision checkpoint that never produced a candidate next action reports no comparison at all rather than zeros, a session with no call observation reports no elapsed time rather than a measured zero, and the Chinese string that still printed a zero average is fixed. The session token total now states how many checkpoints it spans. |
| Failure memory provenance | Each retained failure-memory lesson names when it was observed and which workspace root it came from, so a lesson recorded many revisions ago no longer reads as a current tally. |
| Reused check count | The verification report separates reused checks from fresh executions, so a run that reused every check no longer reads as if it executed them. |
| TUI pending count | The RECONCILE line keeps an unobserved pending count unknown instead of printing a measured zero before the first refresh. |

The added payload fields are additive: an older client ignores them, and no existing call changes shape.

## Upgrade and reconnect

Use the versioned [release downloads](https://github.com/francis-du/wcode/releases/tag/v0.9.9) and the matching SHA256SUMS for a pinned upgrade. The existing `wcode update` command selects the latest stable release; it has no `--version` option.

After replacing an installation, reconnect the MCP Host or arrange a service restart after inspecting active work. A source release does not replace an already running process. Check the newly started executable's version and its configured path.

## Verification identity

The release workflow records the exact commit, runs three-platform tests and standalone source-package checks, dependency audit, Design/traceability checks, the real WebKit matrix and all 300 distinct adversarial rounds. Publication additionally builds platform archives and verifies fresh downloads. The GitHub release links identify the actual completed runs; older green candidates do not validate a newer commit.

WTeam deployment, database migration, identity configuration and installed-service upgrades have their own acceptance steps.

## Command discovery and bounded execution

Use `wcode help-all`, `wcode help-all setup` and `wcode help-all --json` to inspect the command catalog without starting the runtime. Start coding with `agent_context`; the `balanced`, `fast` and `light` presets retain their execution and authorization boundaries. Passive inspection uses `--read-only --no-exec --no-semantic`.

Command policy and authorization are permissive by default. `--no-exec` overrides session command grants, and the explicit hardening flags are documented in the security reference rather than implied by the default.

For an interrupted or incomplete check, retain `timed_out`, `output_incomplete` and the original task ID. Read its result before requesting another execution. Maintainer gates include `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings` and the current online audit. JavaScript regressions use Node 24.
