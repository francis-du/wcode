# v0.7.3 — Autonomous development, broader polyglot quality, and stronger reliability

v0.7.3 is a reliability and developer-flow release. It makes bounded repository development commands autonomous by default, expands native polyglot quality coverage, hardens context and cache correctness, and fixes regressions across Engineering Observatory and Verification without weakening permanent safety boundaries.

The release candidate is committed and pushed first. The `v0.7.3` tag is created only after normal CI for that exact commit is green.

## Development commands stop asking for repetitive approval

Known repository development tools now use the autonomous development lane for normal build, test, lint, format, code-generation, package-manager, and project-runner workflows. Common Cargo, Make, Node package managers, Deno, Dart/Flutter, Maven/Gradle, .NET, and other catalogued language toolchains no longer create repetitive RiskyExecution prompts.

This does not turn the workspace into an unrestricted shell. Shell interpreters, protected or escaping paths, credential flows, registry publication/ownership, and explicitly host-wide or destructive operations remain hard boundaries. Make variable assignments, external clang-format style-file redirection, and exact read-only verification shapes also receive stricter classification.

## Broader language quality and stronger repository intelligence

Deno receives native quality-provider coverage. Flutter projects use Flutter analysis and tests while retaining Dart formatting. The quality registry continues to represent all indexed languages with explicit capability gaps rather than a binary support claim.

Agent Context, repository-map, convention/profile discovery, graph/provider state, evidence/experience storage, and intelligence snapshots received another correctness pass. Shared flights and caches reject stale publication after invalidation, preserve workspace/revision isolation, and reduce repeated scanning without allowing old source state to masquerade as fresh context.

## Observatory, verification, and runtime reliability

Engineering Observatory refresh, runtime, quality, and engineering surfaces were hardened around current endpoint state, scoped responses, incremental refresh, and multilingual presentation. Bundled JavaScript behavior tests keep UI regressions inside the release gate. Verification routing is more precise about repository test executors and advanced-stage evidence, while tunnel lifecycle handling is more resilient to jitter, stale health probes, and failover races.

## Diagnostics and operator compatibility

`agent_context` remains the primary task-ready retrieval entrypoint. Command results retain explicit `timed_out` and `output_incomplete` diagnostics. The `balanced`, `fast`, and `light` resource presets remain compatible and do not change authorization policy. The hardened inspection-only combination remains `--read-only --no-exec --no-semantic`.

Use `wcode help-all`, `wcode help-all setup`, and `wcode help-all --json` to inspect the complete parser-defined command surface without executing the selected command. Release CI continues to install Node 24 for bundled JavaScript behavior tests.

## Release gate

The release candidate must pass `git diff --check`, `cargo check --locked`, `cargo fmt --check`, `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings`, and `cargo build --release --locked`. Design State, Product Scope, documentation/release contracts, installers, and repository conventions are checked in the same preparation.

After the v0.7.3 commit reaches `main`, the exact SHA must pass normal Build & Release and documentation CI before the `v0.7.3` tag is created. The tag-triggered workflow then builds and smoke-tests Linux, macOS Universal, and Windows distributions before publishing the GitHub Release.
