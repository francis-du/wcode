# wcode v0.9.13

This version makes the Plan → Worklist association an explicit, validated contract, stops an unparseable diagnostic line from reading as line zero, and recovers the steering replan contract so a scope or objective directive against any bound plan reports `replan_required` and a replacement stays behind its own approval gate.

| Change | User-visible behavior |
| --- | --- |
| Plan → Worklist association | `reconciliation_plan` accepts an optional `worklist_item_ids` argument, persists it on the plan and validates every id against the durable Worklist before the repository scan runs; an unknown id fails closed. The Design consistency matrix names the declared items and says "no Worklist item" when a plan declares none. |
| Diagnostic line identity | A diagnostic location whose line cannot be read no longer leaves the projection as `line: 0`; a valid `path:line:column` location is unchanged. |
| Steering replan recovery | Scope/objective steering against any bound Reconciliation plan — approved or not — reports `replan_required` and never mutates the bound snapshot. After the Worklist advances, refresh replaces the binding only with a current-revision plan from the same workspace; without a replacement the directive stays pending. Reopening unfinished work preserves the pending directive, the verification floor and the Execution identity. |
| Release contract | The release metadata check now requires `crates/core-types` to match the package version. |
| Documentation | The manual records the plan association and the recovered steering semantics; the paper validation record carries a dated verification state. |

## Upgrade and reconnect

Use the versioned [release downloads](https://github.com/francis-du/wcode/releases/tag/v0.9.13) and the matching SHA256SUMS for a pinned upgrade. The existing `wcode update` command selects the latest stable release; it has no `--version` option.

After replacing an installation, reconnect the MCP Host or arrange a service restart after inspecting active work. A source release does not replace an already running process. Check the newly started executable's version and its configured path.

## Verification identity

The release workflow records the exact commit, runs three-platform tests and standalone source-package checks, dependency audit, Design/traceability checks, the real WebKit matrix and all 300 distinct adversarial rounds. Publication additionally builds platform archives and verifies fresh downloads. The GitHub release links identify the actual completed runs; older green candidates do not validate a newer commit.

WTeam deployment, database migration, identity configuration and installed-service upgrades have their own acceptance steps.

## Command discovery and bounded execution

Use `wcode help-all`, `wcode help-all setup` and `wcode help-all --json` to inspect the command catalog without starting the runtime. Start coding with `agent_context`; the `balanced`, `fast` and `light` presets retain their execution and authorization boundaries. Passive inspection uses `--read-only --no-exec --no-semantic`.

Command policy and authorization are permissive by default. `--no-exec` overrides session command grants, and the explicit hardening flags are documented in the security reference rather than implied by the default.

For an interrupted or incomplete check, retain `timed_out`, `output_incomplete` and the original task ID. Read its result before requesting another execution. Maintainer gates include `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings` and the current online audit. JavaScript regressions use Node 24.
