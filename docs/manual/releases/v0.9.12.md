# wcode v0.9.12

This version lands the three-column investigation layout, makes a signal kill readable as distinct from an unobserved exit code, and closes four honesty gaps in the graph, learning and decay surfaces. It also removes three repeated costs from the graph query path.

| Change | User-visible behavior |
| --- | --- |
| Investigation layout | The main area arranges the loaded objects in a left navigator, the page in the centre and the selected object's summary in a right inspector, with the shared Problems/Jobs/Logs/Evidence panel at the bottom. The identity bar sits outside that grid, so narrowing the window reflows the columns instead of hiding the workspace, revision or connection state. |
| Command outcome identity | A command killed by a signal now reads `signal` in the Jobs detail, distinct from an exit code that was never observed; a missing code keeps the em dash. The projection adds an optional `signaled` field, so older clients ignore it. |
| Object inspector | Selecting a code symbol names its kind, path, provider, precision, direction and relation count. A selected requirement or component lists the changed files that name it. A selected change reports its hunk count and added/removed line counts from the retained diff. A value with no retained data stays unknown instead of reading as zero. |
| Graph freshness | A latest code graph that the newest capture replaced carries a stale marker and names the snapshot that is current now; a deliberately pinned historical snapshot stays labelled by its own selector and is not reported as stale. The repository overview applies the same rule. |
| Session readout | The drawer-head session record's elapsed time follows the session instead of freezing at the last recorded jump. |
| Verified learning | A learning metric whose denominator is zero keeps its value, baseline and percentage-point delta unknown instead of rendering as a measured zero. The acceptance criterion states the behaviour. |
| Experience decay | Renormalizing the lazy decay factor no longer revives stale confidence: the old code inflated every true weight by `1/scale²` at each renormalization, and an underflowed scale produced infinities. Fully decayed evidence now expires without non-finite weights. |
| Graph query efficiency | Cached snapshots are shared rather than deep-cloned for every query, history listings reuse the derived entry instead of reparsing every snapshot, and file-scoped path evidence is scored once per query instead of once per symbol. |
| Adversarial coverage | Three fault-injection rounds cover the new inspector branches and the graph freshness rule; the release audit stays at 300 distinct rounds. |
| Documentation | The manual corrects the `import-ci-receipt` invocation, records the investigation layout, and documents the two proof-signal cards for the first time. |

## Upgrade and reconnect

Use the versioned [release downloads](https://github.com/francis-du/wcode/releases/tag/v0.9.12) and the matching SHA256SUMS for a pinned upgrade. The existing `wcode update` command selects the latest stable release; it has no `--version` option.

After replacing an installation, reconnect the MCP Host or arrange a service restart after inspecting active work. A source release does not replace an already running process. Check the newly started executable's version and its configured path.

## Verification identity

The release workflow records the exact commit, runs three-platform tests and standalone source-package checks, dependency audit, Design/traceability checks, the real WebKit matrix and all 300 distinct adversarial rounds. Publication additionally builds platform archives and verifies fresh downloads. The GitHub release links identify the actual completed runs; older green candidates do not validate a newer commit.

WTeam deployment, database migration, identity configuration and installed-service upgrades have their own acceptance steps.

## Command discovery and bounded execution

Use `wcode help-all`, `wcode help-all setup` and `wcode help-all --json` to inspect the command catalog without starting the runtime. Start coding with `agent_context`; the `balanced`, `fast` and `light` presets retain their execution and authorization boundaries. Passive inspection uses `--read-only --no-exec --no-semantic`.

Command policy and authorization are permissive by default. `--no-exec` overrides session command grants, and the explicit hardening flags are documented in the security reference rather than implied by the default.

For an interrupted or incomplete check, retain `timed_out`, `output_incomplete` and the original task ID. Read its result before requesting another execution. Maintainer gates include `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings` and the current online audit. JavaScript regressions use Node 24.
