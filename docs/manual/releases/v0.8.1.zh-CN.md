# v0.8.1 — Jev Decision Plane 加固

v0.8.1 是基于 v0.8.0 的一次集中加固版本。确定性 Decision Plane 继续拥有最终行为权限；Jev 被收窄为明确的语义判断；此前混杂的命名被彻底统一；同时修复两类在对抗检查中暴露出的 WebUI 状态真实性问题。

## Jev 命名与配置

外部语义决策 Provider 现在统一叫 **Jev**。本地无模型的确定性层统一叫 **Decision Plane**，主大模型统一叫 **Reasoning Model**。

运行时只认：

- `JEV_API_KEY`
- `JEV_BASE_URL`
- `JEV_DEFAULT_MODEL`

不再保留旧命名 alias。默认模型仍是 `jev-latest`，默认 Jev endpoint 仍是 `https://api.typesafe.ai`。

## 更窄的 Jev 判断

Agent Context 的 Jev question set 升级为 `wcode.agent_context@3`。

原来“semantic navigation 有没有帮助”这类宽问题，被改成带明确 criteria 的窄判断，例如：**语义关系是不是安全修改前的必要证据**。Choice 选项现在同时定义正向和排除边界，并增加 `other_review`，遇到不完整状态时 abstain，而不是假装已经可以编辑。

低集中度 Choice 也不再默认解释成“继续推理”，而是转成“收集更多证据”的 abstain 信号。

## 严格 increase-only 权限

Jev 仍然只是 advisory。它可以要求更多 retrieval、semantic navigation 或 verification，但不能降低确定性的安全边界。

Jev 给出的 `edit_then_verify` 只有在 deterministic baseline 本来就选择同一动作时才允许透传。未知 edit readiness 现在进入 `other_review`，不会再默认坍缩成“可以编辑”。

如果 Jev advisory 会让 Agent Context 超出预算，该块会直接被丢弃；源码、SHA precondition、测试和确定性风险证据永远优先。

## WebUI 状态真实性

Code Graph 现在把每个响应绑定到当前请求语义：只有 `query`、`mode`、`depth`、`snapshot` 全部匹配，响应才允许发布到 UI。

Access 页面现在原子发布 workspaces、commands、authorizations 三路响应。任何一路 shape validation 失败，整组保持 Unknown，不再展示“部分正确”的状态。

## 兼容性与发现入口

`agent_context` 继续作为有界 Coding Context 入口。Command Result 继续显式保留 `timed_out` 与 `output_incomplete`，资源预设仍为 `balanced`、`fast`、`light`。

CLI 发现保持无副作用，可直接使用：

```text
wcode help-all
wcode help-all setup
wcode help-all --json
```

Hardened inspection-only 组合仍为 `--read-only --no-exec --no-semantic`。JavaScript 行为 CI 继续使用 Node 24。

## 验证

发布 gate 继续保持 v0.8 的信任边界：

- `cargo test --locked`；
- `cargo clippy --locked --all-targets -- -D warnings`；
- locked Rust fmt / check 与 release build；
- 确定性 Design State validation；
- release metadata 与 installer contract；
- WebUI browser behavior 与真实 WebKit geometry 检查；
- 对精确 reviewed SHA 的 adversarial release audit。

v0.8.1 只从 clean reviewed commit 发布。流程为：审查后的 commit → 非强推 push → 精确 SHA CI 全绿 → `v0.8.1` tag → 跨平台分发构建与 GitHub Release。
