# wcode v0.9.9

本版补上三处"计划已被取代却仍读作当前"的缺口，并停止两处把缺失测量显示成零。

| 变更 | 用户可见行为 |
| --- | --- |
| Git 身份门禁 | 只要工作区存在 Git 身份，计划结果就要求证据的记录级与回执级 Git 绑定都与之一致。`git add` 或 `git commit --allow-empty` 不改变代码与设计修订，因此过去计划会在索引或 HEAD 移动后仍显示 `ready`，而统一 Acceptance 把同一证据判为 stale。没有 Git 身份时没有可比较的对象，行为不变。 |
| 策略绑定 | 记录的策略绑定与计划策略不同的证据不再满足该计划，即使代码与设计修订未变。 |
| 复用链 | 源在本快照中已不可观测的复用检查不再读作当前通过。保留策略可能在回执写入后裁剪源；统一 Acceptance 早已对该情形报 Inconclusive。 |
| 被取代的计划 | 设计一致性矩阵带上每个计划验证所绑定的修订，并把绑定到其他修订的计划标注为已被取代，而不是让它的任务计数读作当前输入的结果。偏离 id 跨修订稳定，因此被取代的计划仍可能认领当前偏离。 |
| 未比较与未测耗时 | 从未产生候选动作的决策检查点不报告任何比较，而不是报告零；没有调用观测的会话不报告耗时，而不是报告测得的零；中文串中仍在渲染零平均值的问题已修。会话 token 总数现在说明它跨越多少个检查点。 |
| 失败记忆来源 | 每门保留的失败记忆课程都注明观测时间与来源工作区根，因此许多修订之前记录的课程不再读作当前统计。 |
| 复用检查计数 | 验证报告把复用检查与实际执行分开，因此全部复用的运行不再读作全部执行过。 |
| TUI 待处理数 | RECONCILE 行在首次刷新前保持待处理数未知，而不是显示实测零。 |

新增的载荷字段都是附加的：较旧的客户端会忽略它们，现有调用的结构没有变化。

## 升级与重连

使用带版本的[发布下载](https://github.com/francis-du/wcode/releases/tag/v0.9.9)以及对应的 SHA256SUMS 做固定版本升级。现有 `wcode update` 命令会选择最新的稳定版本，它没有 `--version` 选项。

替换安装文件之后，请重新连接 MCP Host，或在检查完正在进行的任务后安排服务重启。源码发布不会替换已在运行的进程。请检查新启动可执行文件的版本及其配置路径。

## 验证身份

发布工作流会记录确切提交，运行三平台测试与独立源码包检查、依赖审计、Design/traceability 检查、真实 WebKit 矩阵以及全部 300 个不同的对抗轮次。发布阶段还会构建各平台归档并校验全新下载。GitHub Release 链接指向实际完成的运行；较早的绿色候选不能证明较新的提交。

WTeam 部署、数据库迁移、身份配置与已安装服务的升级有各自的验收步骤。

## 命令发现与有界执行

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 可以在不启动运行时的情况下检查命令目录。编码工作从 `agent_context` 开始；`balanced`、`fast` 与 `light` 预设保持各自的执行与授权边界。被动检查使用 `--read-only --no-exec --no-semantic`。

命令策略与授权默认是宽松的。`--no-exec` 会覆盖会话级命令授权，显式加固标志记录在安全参考中，而不是由默认值暗示。

对于中断或不完整的检查，请保留 `timed_out`、`output_incomplete` 与原始任务 ID。在请求再次执行之前，先读取它的结果。维护者门禁包括 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 与当前的在线审计。JavaScript 回归使用 Node 24。
