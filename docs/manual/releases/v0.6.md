# v0.6 — Parallel-first agents and authorizable project commands

wcode 0.6 helps coding agents spend less time guessing how a repository works and more time completing independent work safely in parallel.

## Highlights

- `agent_context` now carries an explicit parallel-first execution contract: candidate dependency lanes, recommended concurrency, immediate top-level concurrency guidance, and the small set of conditions that still require serialization.
- Task-ready context is more deliberate about minimal-change strategy, complexity budgets, active Worklists, hot source, semantic-provider readiness, and revision-pinned editable files.
- The semantic runtime is standardized around LSP server discovery, binary identity, bounded warm sessions, source-revision synchronization, and fail-closed authorization when a server has no automatic safety profile.
- Common local inspection commands run with less friction. Unknown or repository-executing operations that pass every hard safety boundary now produce an exact `RiskyExecution` request instead of being rejected permanently.
- The approved command grant remains bound to the exact Workspace, program, arguments, and working directory. Shell interpreters, protected paths, Workspace escapes, credential/config redirection, host-wide tool mutation, package publication/ownership, and destructive infrastructure operations remain blocked.
- The plugin Skill and documentation now tell capable Hosts to launch independent discovery, reads, reviews, checks, and non-overlapping edits concurrently rather than merely mentioning that parallelism exists.

## Why this matters

A model can only act on the context and execution contract it receives. v0.6 makes both more operational: the repository tells the Agent what can run concurrently, what must remain serialized, what evidence is current, and when the user—not the model—must authorize a narrowly fingerprinted operation.
