# v0.7.2 — Clearer observability, model-efficient tools, and precise verification

v0.7.2 is an optimization and clarity release across the surfaces that coding agents and operators use every day. It improves Observatory, TUI, Setup and OAuth UX; makes Agent Context efficiency visible; gives tool-search capable Hosts a compact model-neutral preload hint; and removes false Verification Mesh cross-products without weakening deterministic or security review gates.

The release candidate is committed and pushed first. The `v0.7.2` tag is created only after normal CI for that exact commit is green.

## Observatory and TUI show the state that actually matters

Engineering Observatory now exposes refresh state as a visible operator signal instead of hiding it behind accessibility-only text. Activity surfaces real Agent Context retrieval telemetry: candidate versus delivered context, cache behavior, avoided context and build latency. This makes it possible to distinguish "the agent had no useful context" from "the agent explored too much context" without exposing prompts or chain of thought.

The TUI carries the same retrieval-efficiency signal and makes inner process pressure easier to understand. Queue wait peaks are shown separately from tool-slot occupancy, so `SLOTS`, child processes, Git inspection capacity and queue delay no longer collapse into one vague performance number.

The visual hierarchy remains intentionally compact. Navigation and control surfaces use the stronger translucent material; project state, proof and architecture remain the stable content layer instead of turning the entire UI into a glass card wall.

## Setup distinguishes endpoint health from real MCP activity

Setup now separates two different truths:

- whether the public endpoint is currently healthy; and
- whether wcode has seen recent MCP traffic.

Recent MCP activity is explanatory observability only. An idle connector does not make a healthy tunnel unhealthy and cannot trigger endpoint failover or Host-trust revocation. This is especially useful when diagnosing VPN/Tailscale jitter: a green transport endpoint no longer implies that a client is actively using MCP, while a quiet client is not misdiagnosed as a broken tunnel.

OAuth pages now implement a real light color scheme in addition to the dark theme, while keeping mobile viewport, safe-area, zoom and escaping behavior intact.

## Agent Context and model-host efficiency

The 2026 research follow-up reinforces a simple rule: more context is not automatically better context. Agent Retrieval Bench, ContextBench and CORE-Bench all motivate evaluating repository retrieval as its own problem, including precision, context yield and the gap between explored and actually used context.

wcode therefore keeps `agent_context` adaptive and task-routed instead of adding one larger default budget. The runtime now surfaces candidate→delivery, cache and build-latency telemetry so retrieval quality can be measured directly.

The MCP catalog also exposes `dev.wcode/preloadRecommended=true` only on a small core set: `agent_context`, `search_many`, `read_files`, `apply_file_edits`, `review_changes` and `verify_project`. Tool-search capable Hosts can keep that core immediately available and discover specialist tools on demand. Hosts that ignore the hint receive exactly the same deterministic catalog and behavior.

This is deliberately capability-first rather than vendor-specific. Codex/OpenAI-style prompt caching benefits from stable tool order and definitions; Claude-style deferred tool discovery benefits from a small preload set; Gemini-style implicit caching benefits from stable prefixes. wcode does not branch repository semantics, authorization or verification by model brand.

See [Research-informed improvements](../../research-upgrades/) for the primary sources and implementation limits.

## Verification Mesh targets risk instead of file-extension noise

High and Critical Verification Plans still require their full deterministic profile, Security/Adversarial review and required advanced stages. What changed is the target set used for advanced stage evidence.

When deterministic file review already identifies risk-bearing changed source, High/Critical plans prefer those source languages instead of multiplying Property/Mutation/Fuzz across every unrelated changed UI language. CSS and HTML presentation sources do not become language-level advanced-stage targets unless an explicit configured executor opts them in. If no behavioral language target applies, the required stage remains a global fail-closed blocker rather than falling back to unrelated repository languages.

This removes false gaps without manufacturing evidence. A normal `cargo test` is never relabeled as mutation or fuzz testing, and missing real executors remain visible. On the release-development machine, `cargo-mutants` and `cargo-fuzz` are not installed, so those advanced Rust stages remain explicit Verification Mesh gaps rather than fake passes.

Reconciliation planning now uses the same risk-relevant target selection as direct Verification Plan creation, eliminating the previous broad-language bypass.

## Less friction for safe repository inspection

Bounded `git grep` inspection is admitted through the existing read-only Git policy instead of creating a pointless authorization request. Scope-escaping helpers, unsafe configuration redirection and mutation forms remain blocked.

The change keeps the same principle used across wcode development tooling: common bounded inspection and verification should be autonomous; authority-expanding or destructive operations keep explicit trust boundaries.

## Diagnostics, resource presets, and CLI compatibility

Command timeout/cancellation results retain the explicit `timed_out` and `output_incomplete` fields. A timeout is not proof of rollback and wcode still does not automatically replay an operation whose effects may already have started.

The existing `balanced`, `fast`, and `light` resource presets remain compatible; they change bounded runtime capacity, not authorization policy. The hardened inspection-only combination remains:

```text
--read-only --no-exec --no-semantic
```

Use `wcode help-all`, `wcode help-all setup`, and `wcode help-all --json` to inspect the complete parser-defined command and argument surface without executing the selected command. Release CI continues to install **Node 24** for JavaScript Observatory behavior tests.

## Verification and release gate

The release candidate must pass the complete locked local gate:

```text
git diff --check
cargo check --locked
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo build --release --locked
```

Design State, Product Scope, repository conventions and release/documentation contracts are checked as part of the same preparation. The tool catalog must also stay below its existing compactness bound; the first model-hint implementation exceeded that bound and was deliberately reduced instead of raising the limit.

After the v0.7.2 commit is pushed to `main`, wait for Build & Release and documentation CI on that exact SHA. Create `v0.7.2` only after the main-branch gate is green. The tag-triggered workflow then performs the cross-platform packaging and publication gate.
