# v0.8.2 — Durable execution and Code Graph reliability

v0.8.2 turns the current engineering-control-plane work into a release-ready, independently verifiable flow. It adds durable Execution observability and structured steering, strengthens process/Cargo admission, makes the Code Graph more useful on large repositories, and expands the adversarial release gate from 30 to 100 distinct scenarios.

## Durable Execution and steering

- Engineering Observatory exposes current Execution state without persisting chat transcripts.
- Structured steering is revision-guarded, bounded to one pending directive, and forces Reconciliation replan when objective or scope changes invalidate a frozen plan.
- Handoff creates clean execution lineage while preserving the verification floor and structured pending state.
- Verification strength is monotonic: later steering cannot silently lower an already-required adversarial/full gate.

## Resource and command isolation

- Heavy child-process capacity is isolated per Workspace/subspace with a separate host-wide hard cap.
- Cargo uses a global registry-exclusive lane, a per-Workspace writer lane, and bounded shared test-reader admission.
- Cancelled blocking work remains observable and retains real capacity until the worker actually exits.
- Writer leases and mutation domains keep shared-worktree writes single-owner while linked worktrees remain independent.

## Code Graph and Observatory

- Code Graph search supports source-keyword fallback and keeps user input separate from automatic discovery.
- Global graph symbol budgeting now fills ordinary definitions round-robin across files so large early files cannot leave later modules as file-only single nodes.
- Search clear aborts in-flight graph work and atomically clears remembered query/node state.
- Fullscreen is a dedicated graph workspace with background scroll lock, viewport-filling graph/inspector layout, Escape exit, responsive narrow-screen flow, and dialog semantics.
- Browser/WebKit verification covers 240 production scenarios across width, language, theme and view combinations.

## Verification Mesh

- Repository-local, no-shell Property/Mutation/Fuzz executors cover Rust and JavaScript.
- JavaScript property/fuzz stages each run 2048 generated cases and the mutation stage kills 4/4 source mutants.
- Rust retains the Unicode/CRLF edit property corpus, generated mutant-kill oracle, and bounded deterministic edit fuzzing.
- The release audit now runs 100 distinct adversarial rounds rather than repeating one green suite. The report is written to `target/wcode-adversarial-100.json` and is bound to a clean, stable Git revision.

## Compatibility and discovery

The primary bounded coding entry point remains `agent_context`. Command results continue to expose `timed_out` and `output_incomplete`, and resource presets remain `balanced`, `fast`, and `light`. JavaScript behavior CI uses Node 24.

CLI discovery remains side-effect free:

```text
wcode help-all
wcode help-all setup
wcode help-all --json
```

The hardened inspection-only combination remains `--read-only --no-exec --no-semantic`. Final Rust release verification includes:

```text
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

## Release verification

The v0.8.2 candidate is required to pass locked format/check/clippy/test/release-build gates, Design/traceability/Product Scope validation, release metadata and installer contracts, real WebKit layout checks, Verification Mesh stages, and the clean-worktree 100-round adversarial audit before tagging.

The release flow remains: reviewed release-prep commit → non-force push → exact-SHA green CI → `v0.8.2` tag → cross-platform artifacts and GitHub Release publication.
