# v0.7.5 — Endpoint trust and operator reliability

v0.7.5 hardens endpoint ownership, TUI input routing, Observatory rendering and repository verification. Local verification does not replace CI on the exact release commit or checking the runtime after an upgrade.

## Endpoint ownership and 403 diagnostics

Every instance-verified tunnel URL is now a concurrent active endpoint; automatic mode no longer places healthy providers into primary and standby roles. Each URL has an identity-bound, single-flight health lease and independent recovery worker. Healthy endpoints are probed every three seconds, suspect endpoints every second, and the scheduler never waits for network completion. Two failures quarantine health while preserving the process, URL and Host trust for a bounded 30-second in-place recovery window; two successes restore verified health. Cloudflare rate limits receive a five-minute cooldown, while other failures retain bounded staggered retries.

Every verified registration carries a new epoch. Cleanup compares that epoch atomically before withdrawing trust, so an old provider cannot revoke a newer registration at the same URL or replace new telemetry with a retry row. Retained stable aliases are indexed by URL and bounded to eight, with independent instance-matched probes even after a provider connects elsewhere. Startup failure alone does not revoke an otherwise retained alias, and recovery enters the normal Connected lifecycle. A convenience URL affects display only and grants no exclusive routing, health or authorization authority.

Unregistered hosts, invalid origins and unauthenticated requests still fail closed. Historical OAuth resources do not activate a Host. These fixes address identified lifecycle races; they do not make every HTTP 403 a valid request or guarantee that an unhealthy endpoint stays reachable.

## TUI shortcuts

`A` is reserved for the visible request's Workspace-wide command authorization. The author page moves to `B`, and help/documentation use the same binding. A single context-aware resolver prevents ordinary shortcuts from firing for unrelated Ctrl/Alt/Super chords. Text entry and Full Access confirmation consume keys exclusively. Repeated key events cannot repeat grants, toggles, submissions or external-link actions; visible navigation and text editing retain repetition.

## Observatory layout and refresh

Code statistics use shrinkable label/value tracks and a separate progress row instead of fixed widths that overlap adjacent columns. Verification previews use content-driven height, wrapping long test names and a dedicated fail-fast row layout. The full-bleed global bar now has explicit shrinkable inline sizing, while the proof grid and its children suppress intrinsic-width expansion; at constrained widths the inspector returns to normal flow in a single column. English descriptive copy no longer exposes internal translation keys.

Long evidence identifiers, policy/model chips and diagnostic lines wrap inside the inspector rather than forcing a horizontal scrollbar or extending beyond their grid row. Regression checks cover the inspector's inner sections as well as the outer card; the fix preserves complete text rather than hiding overflow.

Refresh errors distinguish authorization, Host/origin denial, timeout, malformed responses and rendering exceptions without placing internal paths or stacks in page text. Full project snapshots have a bounded 120-second deadline; lightweight cached requests retain 30 seconds. Rendering failure cannot certify the new snapshot revision. Adaptive checks remain a read-only planning preview, not execution from the Observatory.

## Repository integrity and fail-closed release gates

Source and Design caches invalidate same-size rewrites even when modification times are restored. Verified-change storage validates record integrity and rejects duplicate/conflicting history, while authorization deduplication remains Workspace- and operation-kind-bound. Convention scanning distinguishes maintained sources from declared build outputs and initialized submodules.

Release readiness rejects empty Workspace audits and missing or malformed Convention/Product Scope results rather than interpreting missing fields as zero errors. Migration checks distinguish a genuinely missing forbidden path from a blocked, symlinked or inaccessible one; inability to inspect is not proof of removal. Both failure paths have regression tests that failed before the fixes.

## Compatibility

The canonical coding entry remains `agent_context`. Existing `timed_out` and `output_incomplete` execution diagnostics, standard MCP media and Workspace boundaries are preserved. Exact authorized `git ls-remote` and single-branch `git fetch` shapes can synchronize a configured remote without opening arbitrary URLs, wildcard refspecs, prune, pull or force modes. Performance presets remain `balanced`, `fast` and `light`; inspection-only sessions can use `--read-only --no-exec --no-semantic`. Behavior tests continue to use Node 24 in CI.

The complete command catalog remains available without starting the runtime:

```sh
wcode help-all
wcode help-all setup
wcode help-all --json
```

## Verification and publication

Run `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings`, formatting checks and `cargo build --release --locked` against one stable working-tree revision. The new tests exercise shortcut contexts/modifiers, retained-alias probing, generation-safe withdrawal and long-content rendering. `node tests/unit/ui/layout.cjs .` exports production renderer HTML and shipped CSS with synthetic data. On macOS, `swift tests/unit/ui/layout_webkit.swift` checks actual WebKit layout at 12 widths from 375 to 1920 pixels in both languages.

`node tests/release_audit.cjs` runs 30 distinct adversarial rounds on macOS, with independent Rust and Web lanes, nonempty-test checks, bounded execution and a before/after input digest. Results are recorded in `target/wcode-adversarial-30.json`. The full production-page WebKit audit covers 96 combinations of 12 widths (320–1920 pixels), English/Chinese, light/dark and proof/overview. Portable rendering-failure scenarios are included in `cargo test`; the actual WebKit audit also runs in macOS CI.

The full-page runner hosts WebKit in a real window, waits for fonts and animation frames, and validates the requested viewport. Navigation failures and timeouts produce partial failure reports instead of a silent hang. The independent adversarial workflow preserves the synthetic HTML, shipped CSS, layout reports, exact checked-out revision and 30-round results for diagnosis; failed geometry checks are not skipped to publish.

Publication follows reviewed commit → non-force push → successful CI for that exact SHA → version tag → distribution builds and smoke tests. After installation, restart the running wcode process, reconnect MCP and reopen the Observatory; rebuilding a binary does not update an already-running server.
