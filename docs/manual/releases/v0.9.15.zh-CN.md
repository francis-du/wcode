# wcode v0.9.15

本版让观测台的导航跳转落在它指名的对象上，让结构文件树有界渲染，使大型仓库不会淹没 DOM，并把三个存在漏洞的传递依赖升级到已修补版本。

| 变更 | 用户可见行为 |
| --- | --- |
| 导航文件跳转 | 在项目导航中选择文件，现在会把该文件条目滚动到视野内并在文件树中聚焦，而不是只展开文件区域。当残留的结构筛选会让目标不可见时，会清空筛选；当有界首页不包含目标时会展开首页，使代码阅读器与文件树对当前打开的文件保持一致。 |
| 有界结构树 | 结构视图只渲染 200 条的有界首页，并说明已显示的文件数量，同时提供显式控件展开其余条目。新查询或切换工作区会重新收起展开状态，因此搜索不会把匹配项藏在过期的展开背后。 |
| 依赖审计 | `rustix`、`quinn-proto` 与 `quinn-udp` 升级到已修补版本，`cargo audit` 不再报告漏洞。这三者经 reqwest 与终端 UI 可达。 |
| 发布门禁 | 发布质量门禁现在端到端通过：design→implementation 与 Product Scope 可追溯性契约完整，provider、fan-out、command policy 与 Agent Context 契约各自位于独立模块。 |

## 升级与重连

使用带版本的[发布下载](https://github.com/francis-du/wcode/releases/tag/v0.9.15)与对应的 SHA256SUMS 做固定版本升级。现有 `wcode update` 命令会选择最新稳定版，它没有 `--version` 参数。

替换安装后，请检查正在进行的工作，然后重连 MCP Host 或安排服务重启。源码发布不会替换已在运行的进程。请检查新启动可执行文件的版本及其配置路径。

## 验证身份

发布工作流记录精确提交，运行三平台测试与独立源码包检查、依赖审计、Design/可追溯性检查、真实 WebKit 矩阵以及全部 300 个不同对抗轮次。发布阶段还会构建平台归档并验证新下载。GitHub Release 链接指向实际完成的运行；较早的绿色候选不能验证较新的提交。

WTeam 部署、数据库迁移、身份配置与已安装服务的升级有各自的验收步骤。

## 命令发现与有界执行

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 检查命令目录，无需启动运行时。编码从 `agent_context` 开始；`balanced`、`fast` 与 `light` 预设保留各自的执行与授权边界。只读检查使用 `--read-only --no-exec --no-semantic`。

命令策略与授权默认宽松。`--no-exec` 覆盖会话命令授权，显式加固参数在安全参考中说明，而不是由默认值暗示。

对于中断或不完整的检查，请保留 `timed_out`、`output_incomplete` 与原始任务 ID。请求另一次执行前先读取其结果。维护者门禁包括 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 与当前在线审计。JavaScript 回归使用 Node 24。
