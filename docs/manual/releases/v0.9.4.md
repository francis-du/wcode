# wcode v0.9.4

This version makes the graph queries that feed the model cheaper, and corrects the verified-experience decay so recency keeps ranking evidence properly.

| Change | User-visible behavior |
| --- | --- |
| Bounded chain queries | A bounded chain query indexes incident edges once instead of scanning the full edge list for every visited node, so a component of k nodes costs O(k + incident edges) rather than O(k * total edges). Deduplication and the structural root rules are unchanged. |
| Graph context search | The reconciliation path that assembles model context no longer allocates a lowercased copy per graph node or per ranked candidate, and the MCP `graph_query` label filter compares in place. Scoring, ranking and filtering results are unchanged. |
| Sentinel ranking cost | The cost model computes the later-phase cost once per ranking instead of once per phase-0 candidate. The chosen sentinel and its savings are unchanged. |
| Verified-experience decay | Cochange weights now decay lazily: advancing time is one multiply instead of a pass over every stored weight, with renormalization only when the factor becomes unrepresentable. Confidence is measured against the true decayed weight, and newly learned weights are stored pre-scaled so a later decay cannot inflate them. |
| Release note correction | The v0.9.3 page no longer claims the graph work that was not reachable from its tag; the recovered change lands here. |

The decay correction matters for ranking quality, not just speed. Confidence shrinkage compares a pair weight against a fixed prior, so reading the pre-scaled stored value would have made confidence decay-free and let stale evidence keep the score of fresh evidence. The association ratio cancels the scale factor and is unchanged.

## Upgrade and reconnect

Use the versioned [release downloads](https://github.com/francis-du/wcode/releases/tag/v0.9.4) and the matching SHA256SUMS for a pinned upgrade. The existing `wcode update` command selects the latest stable release; it has no `--version` option.

After replacing an installation, reconnect the MCP Host or arrange a service restart after inspecting active work. A source release does not replace an already running process. Check the newly started executable's version and its configured path.

## Verification identity

The release workflow records the exact commit, runs three-platform tests and standalone source-package checks, dependency audit, Design/traceability checks, the real WebKit matrix and all 300 distinct adversarial rounds. Publication additionally builds platform archives and verifies fresh downloads. The GitHub release links identify the actual completed runs; older green candidates do not validate a newer commit.

WTeam deployment, database migration, identity configuration and installed-service upgrades have their own acceptance steps.

## Command discovery and bounded execution

Use `wcode help-all`, `wcode help-all setup` and `wcode help-all --json` to inspect the command catalog without starting the runtime. Start coding with `agent_context`; the `balanced`, `fast` and `light` presets retain their execution and authorization boundaries. Passive inspection uses `--read-only --no-exec --no-semantic`.

Command policy and authorization are permissive by default. `--no-exec` overrides session command grants, and the explicit hardening flags are documented in the security reference rather than implied by the default.

For an interrupted or incomplete check, retain `timed_out`, `output_incomplete` and the original task ID. Read its result before requesting another execution. Maintainer gates include `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings` and the current online audit. JavaScript regressions use Node 24.
