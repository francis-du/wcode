# v0.6.1 — Faster parallel work and focused tool use

This page accompanies the 0.6.1 release preparation. Versioned source and local verification do not publish a release; tagging and publication remain separate operator actions.

## Parallel execution

`parallel_tools` now dispatches by completion rather than whole-layer barriers. A successor starts when its own predecessors finish, without waiting for an unrelated slow branch. Results retain input order, and the existing global semaphore and response bounds remain in force.

Failed dependencies skip their successors while independent branches continue. Cancelling the parent cancels queued children rather than detaching pending writes; already-running blocking filesystem operations are not rolled back. Parent Workspace and discovered subspace paths are compared against their actual roots so aliases cannot hide conflicting resources.

Same-file, same-SHA edits cannot coalesce across an intervening dependent read or move. The combined transaction is checked against the existing 128-edit limit before execution.

Bulk reads, creates, edits and moves report complete/partial/failed outcomes and preserve each item's result. Partial failures set the MCP error flag and conservatively block dependent batch successors; independent branches still run. Retry only failed items after checking their state, not the whole batch. Cancelling an async caller no longer releases a started blocking worker's semaphore permit early: the real work retains it through completion or panic, while the owned JoinSet aborts workers still queued.

Malformed task definitions or unresolved resource models reject the entire fan-out before any child starts. This preflight rejection is distinct from runtime failures in a valid dependency graph, where independent branches still run.

Durable MCP Task cancellation and TTL expiry detected during polling now abort the owned tool future, not just the outer waiter. Cancelling an isolated ordinary request also reaches queued single-file and fan-out writes. Accepted durable Tasks deliberately outlive their creation request; panic isolation, owner checks and the no-rollback boundary for already-started blocking work remain intact.

Task snapshots are validated for size before directory creation or history pruning, then staged, synced and atomically published. Retries acknowledge only matching regular snapshot files, never corrupt content or symlinks. UTF-8 failure messages share a byte bound across status and error fields. Unpersistable tool results fall back to bounded durable failures; polling detects missing or finished workers instead of leaving them working indefinitely. Creation and worker registration share one state transition. After owner verification, cancellation and detected expiry abort workers even when saving the terminal status fails; storage errors remain explicit, and actual effects must be inspected before retrying. Nested Workspace task lookup, ownership and restart persistence are regression-tested.

## Context and tool use

Tool arguments must be objects. Explicit Workspace selectors are validated rather than silently falling back to the default, including before parallel edit coalescing. Command argument arrays preserve every string and its position, including empty strings; malformed arrays, cwd values and timeouts fail before execution or authorization. Omitted optional fields retain their defaults.

Literal and qualified symbol names are preserved before token expansion. Bounded candidates from all requested source roots are merged and ranked before truncation, so exact definitions become targets and hot source ahead of similarly named helpers, including on warm-cache calls.

Direct target files retain priority over alphabetically earlier Design mappings, preserving relevant SHA edit preconditions in bounded packs. Parallel recommendations account for discovery scopes and active Worklist lanes and respect the runtime concurrency cap instead of a fixed four-lane ceiling. Lane counts remain hints, not proof of independence. Scoped discovery tolerates absent optional source roots in smaller repositories without hiding workspace-identity, permission, or symlink errors.

Context finalization avoids redundant pre-trimming rounds and preserves the truncation flag across subsequent sizing passes. Core tool descriptions fit the compact description limit without cutting off routing instructions. The Skill and workflow prompt favor one discovery step, reuse of supplied source, bulk reads/searches for known inputs, and concurrent top-level calls when supported. `project_context` is not a second mandatory startup call.

## Terminal and observability

The redundant OVERVIEW panel is removed. Short terminals prioritize task activity, throughput appears only when useful and space permits, and multi-tunnel rows stay visible. Unicode truncation, help/footer hit testing, overlay click-through, workspace focus, and command-list resizing are corrected.

Authorization decisions use the request IDs actually rendered and are disabled when another overlay hides the request. Status messages no longer cover approval controls. Terminal initialization failure restores terminal state, and the throughput graph uses the advertised 30-second window with overflow-safe scaling.

Project Observatory distinguishes mapped verification from executed, passed, and fresh proof rather than treating mapping coverage as a passing test result.

MCP GET/POST, legacy SSE and protected WebUI now validate Origin against the same active endpoint registry. Valid non-primary aliases are accepted without admitting retired origins or skipping authentication. Tunnel URLs are registered before publication, closing the brief Host-rejection window during startup/reconnection. Duplicate or malformed Host/Origin headers fail closed, and 403 responses distinguish `untrusted_host` from `untrusted_origin` without exposing credentials.

Full Access changes are staged under the registry lock and published only after capacity and root validation succeed. Failures leave prior permissions and flags unchanged. Existing command approvals/revocations and per-file write locks remain shared; repeated elevation is idempotent and concurrent Workspace additions observe the committed policy. No authorization boundary is bypassed.

## Verification and release

Command and verification Tool Results preserve their reports while setting the MCP error flag when execution fails or no checks were inferred. Incomplete code or Design State revision scans cannot produce whole-workspace verification evidence, even when partial digests match.

Project verification and language-quality runs capture code and Design State revisions before executing checks. Before persisting any report evidence, the runtime rechecks both revisions and rejects stale results instead of attributing an old test run to newer files. This guard is not an isolated snapshot and cannot detect an edit that is reverted before the final check; release verification still requires a stable working tree.

Regression coverage includes ready-successor dispatch, parent/subspace resource aliases, failed dependency propagation, queued-child cancellation, safe coalescing limits, retained target SHA data, bounded concurrency recommendations, and complete compact tool descriptions. Terminal and bilingual documentation contracts remain part of the full suite.

Before publication, run the full repository gate (`git diff --check`, `cargo check --locked`, `cargo fmt --check`, `cargo test --locked`, `cargo clippy --locked -- -D warnings`, and `cargo build --release --locked`) and validate Design State. Cargo and all packaged plugin manifests identify version 0.6.1; dependency versions are unchanged. Cross-platform signing, packaging, and installer smoke tests remain the release workflow's responsibility. No universal speedup percentage is claimed: gains depend on the dependency graph, workload, and Host concurrency support.

After 0.6.1 is published, update with `wcode update`. Current installation and setup instructions are in [Getting started](../../getting-started/).
