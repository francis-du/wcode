# wcode v0.9.0

v0.9.0 让仓库观测更容易转化为行动，并为模型 Worker 提供持久协作协议。既有源码、差异、图谱、Design、运行和版本绑定验证视图通过统一问题列表串联。

## 观测与检查

- 统一问题列表按优先级展示当前失败、矛盾证据、未完成验证、Design 与映射缺口、风险、大型模块和 Provider 覆盖。每项保留版本、来源与精度；有界或不可用输入明确展示。
- WebUI 从问题直接进入对应视图，新增紧凑观测入口；文件树和大型模块选择可打开真实、快照绑定的源码。
- 源码检查支持有界行分页和空文件。每页校验原始源码 SHA；并发编辑、过期响应、非法范围和 Workspace 切换不能静默显示另一版本。
- TUI Observatory 提供概览、问题、任务、Provider 和 Agent 标签，支持键盘导航和保留的任务详情。项目版本、观测时间、待授权操作及观测缺失均明确展示。
- 凭据请求头在进入诊断和观测视图前脱敏。

一手调研、能力矩阵和仍缺少的数据源见[不依赖 IDE 的观测台](../../ide-independent-observatory/)。

## 在工作台中保留当前位置

- 七个页面都显示所选 Workspace、源码版本和快照状态。导航恢复上次支持的页面；页面标题与浏览器标题跟随 Workspace 和语言变化。
- 键盘用户可跳转到当前页面，并通过品牌入口返回 Acceptance。手机上的观测覆盖使用原生展开区，让当前决定或源码视图先获得空间。
- Setup 的复制进度和成功反馈对应实际复制的命令或地址。剪贴板请求等待期间，若内容变化或页面隐藏，迟到结果不会声称新内容已复制，也不会把焦点移到旧的手动选择。剪贴板失败时仍可手动复制。
- 极小终端保留帮助与停止快捷键，并显示包含 Setup 和隧道行的实际尺寸要求。宽屏、紧凑模式、授权和其他操作者视图保留既有控制。

[界面检查](../../workbench-ui-review/)提供生产渲染器生成的当前浏览器和终端图，并明确标记夹具数据。这些图验证呈现效果；真实 Provider、OAuth、隧道、后端和终端输入验收各自保留独立门禁。

## 协调模型 Worker

通过宿主原生模型启动能力创建 Worker，再使用 wcode 协调：

1. 为 Worklist 添加独立任务及明确的 `write_paths`；空数组表示只读通道。
2. 使用当前 Worklist 和仓库版本调用 `worklist_claim` 领取可执行任务，获取私有领取令牌及有界交接包。
3. 每个 Worker 接收自己的范围及交接上下文；版本和 SHA 仍有效时直接复用，仅补齐缺失或过期的 `agent_context`。使用带 SHA 的编辑，在 15 分钟租约到期前续租。
4. 通过 `worklist_submit` 提交有界结果及已有 Evidence ID。主 Agent 检查汇总结果，并对合并后的仓库版本独立审查与验证。

重叠写入范围、过期版本、依赖阻塞、租约过期和错误令牌会使对应操作拒绝。领取仅协调工作，不授予文件或命令权限。Worker 的完成报告仍是报告，不等同于验证通过或人工批准。宿主不具备模型启动能力时，可以串行执行相同通道。`parallel_tools` 继续用于服务端操作批处理。

## 提高上下文效率

任务工具清单保留有序的标准工具名，在源码预算前移除可重建的重复路由信息。公共工具目录保持确定性及 MCP 兼容，缩短重复的默认 Workspace 指引。源码正文、SHA、原生检查、失败状态与授权控制仍然保留。

测量区分序列化字节、基于字节的 token 估算与真实 Provider 计量。这些改进不证明端到端模型成本、缓存命中率、补丁成功率或延迟收益。Engineering Fitness 继续保留原始分母和部分覆盖信息。

## 兼容性与命令发现

编码任务从 `agent_context` 开始；命令超时保留 `timed_out` 和 `output_incomplete` 诊断。`balanced`、`fast`、`light` 预设保持既有边界。被动检查可使用 `--read-only --no-exec --no-semantic`。

使用 `wcode help-all`、`wcode help-all setup` 或 `wcode help-all --json` 发现命令，不启动运行时。开发与 CI 使用 Node 24 运行行为检查，使用 `cargo test --locked` 运行完整测试，使用 `cargo clippy --locked --all-targets -- -D warnings` 检查代码质量。

## 验证与分发

发布门禁覆盖锁定依赖的 Rust 检查、完整行为测试、严格 Clippy、Release 构建、Design 与 Traceability、双语文档、版本一致性、真实 WebKit 渲染，以及针对精确候选提交的 300 轮审计。分发 Linux x86_64、Windows x86_64 与 macOS Apple Silicon、Intel、Universal 归档及 SHA256 校验和；正式发布与原生归档启动单独验收。
