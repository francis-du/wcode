# wcode v0.9.13

本版把 Plan → Worklist 关联变成显式且经过校验的契约，让无法解析的诊断行不再显示为第 0 行，并恢复 Steering 的 replan 契约：针对任意已绑定 Plan 的 scope 或 objective Directive 都会报告 `replan_required`，替换项也保留自己的批准门槛。

| 变更 | 用户可见行为 |
| --- | --- |
| Plan → Worklist 关联 | `reconciliation_plan` 接受可选的 `worklist_item_ids` 参数，将其持久化到 Plan 上，并在仓库扫描前用持久化 Worklist 校验每个 id；未知 id 直接失败关闭。Design 一致性矩阵会列出声明的条目，Plan 未声明时显示 "no Worklist item"。 |
| 诊断行身份 | 行号无法读取的诊断位置不再以 `line: 0` 离开投影；合法的 `path:line:column` 位置保持不变。 |
| Steering replan 恢复 | 针对任意已绑定 Reconciliation Plan（无论是否已批准）的 scope/objective Steering 都会报告 `replan_required`，且绝不修改已绑定的快照。Worklist 前进后，refresh 只能用同一 Workspace 中当前 Revision 的 Plan 替换绑定；没有可替换项时 Directive 保持 pending。重新打开未完成的工作会保留未完成的 Directive、verification floor 与 Execution 身份。 |
| 发布契约 | 发布元数据检查现在要求 `crates/core-types` 与包版本一致。 |
| 文档 | 手册记录 Plan 关联与恢复后的 Steering 语义；论文验证记录带有带日期的验证状态。 |

## 升级与重连

使用带版本的[发布下载](https://github.com/francis-du/wcode/releases/tag/v0.9.13)与对应的 SHA256SUMS 做固定版本升级。现有 `wcode update` 命令会选择最新稳定版，它没有 `--version` 参数。

替换安装后，请检查正在进行的工作，然后重连 MCP Host 或安排服务重启。源码发布不会替换已在运行的进程。请检查新启动可执行文件的版本及其配置路径。

## 验证身份

发布工作流记录精确提交，运行三平台测试与独立源码包检查、依赖审计、Design/可追溯性检查、真实 WebKit 矩阵以及全部 300 个不同对抗轮次。发布阶段还会构建平台归档并验证新下载。GitHub Release 链接指向实际完成的运行；较早的绿色候选不能验证较新的提交。

WTeam 部署、数据库迁移、身份配置与已安装服务的升级有各自的验收步骤。

## 命令发现与有界执行

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 检查命令目录，无需启动运行时。编码从 `agent_context` 开始；`balanced`、`fast` 与 `light` 预设保留各自的执行与授权边界。只读检查使用 `--read-only --no-exec --no-semantic`。

命令策略与授权默认宽松。`--no-exec` 覆盖会话命令授权，显式加固参数在安全参考中说明，而不是由默认值暗示。

对于中断或不完整的检查，请保留 `timed_out`、`output_incomplete` 与原始任务 ID。请求另一次执行前先读取其结果。维护者门禁包括 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 与当前在线审计。JavaScript 回归使用 Node 24。
