# wcode v0.9.16

- **Kimi Code CLI setup:** Global setup previews the executable's absolute path; project setup writes a portable stdio entry. Existing options are preserved. Disabled and remote entries stay unchanged. An empty configuration can be initialized; malformed non-empty JSON is not overwritten.
- **Git worktrees:** Status snapshots recognize `.git` files and preserve Unicode and literal arrow characters in filenames. Observatory uses the same Git path parsing to detect repeated edits.
- **Change review:** Line counts stay attached to the reported path. Incomplete review results cannot claim a clean tree or documentation-only changes.

After installing, run `wcode setup --global` and review the plan. Open a new Kimi session and check `/mcp`, then request a read-only `workspace_info` call. Server discovery alone does not prove the host exposed the tools to its model.

Use `wcode help-all`, `wcode help-all setup` and `wcode help-all --json` to preview the command catalog without starting the runtime. Start repository work with `agent_context`. The `balanced`, `fast` and `light` presets do not change authorization; use `--read-only --no-exec --no-semantic` for passive inspection. For interrupted commands, retain `timed_out`, `output_incomplete` and the task ID before deciding whether to retry.

The release gates include `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings`, Node 24 regressions and platform checks. Use the matching [release downloads](https://github.com/francis-du/wcode/releases/tag/v0.9.16) and checksums once published.
