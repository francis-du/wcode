# wcode v0.4.0

v0.4.0 的核心目标是让 Coding Agent **写得更快、Context 更省、修改质量更稳定**，同时继续保持显式的 Repository Mutation 与 Proof 边界。这一版还把 Project Observatory 改成 Architecture-first、增加免费 Tunnel 自动回退，并为 GitHub 与常用开发 CLI 增加有界命令策略。

## Coding 速度与 Context 效率

- `agent_context` 成为正常 Coding 主入口，用一个有界 Edit-ready Pack 取代固定的多 Tool 启动序列。
- 省略 Budget 时走 Adaptive Range：明确单点任务保持小 Context，模糊或跨模块任务在固定上限内自动获得更多上下文。
- Scope-aware Cold Repo-map 在已知 Direct Ownership 时不再默认构建全仓 Graph。
- Repo-map Structure 按 Revision Cache；每个 Task 的相关性 Ranking 仍重新计算，不把上一次 Query 偏好带到下一次。
- Multi-query Symbol Search 对一个 Source Root 只 Traversal/Index 一次，不再为多个 Query Token 重复扫描。
- 最强 Direct Match 可以携带 Bounded Hot Source，让常见小改动从 Context 直接进入 Edit，减少额外 Source Round-trip。
- Fresh Semantic/Runtime/Deterministic Graph Evidence 可以增强 Caller/Callee/Dependency Ranking；Stale Semantic Revision 自动回退 Syntax。
- Exact SHA Edit Target、Related Test、Working-tree Advisory、`readiness` 与 Deterministic `next_actions` 减少无效 Tool Retry。
- Timing、Cache、Savings Telemetry 移到 Tool Result `_meta`，不再占用 Model-visible Context。
- TUI 直接统计 Agent Context Calls、Average Model Tokens、Repo-map Cache Hit 与 Saved Context。

默认工作流现在是：

```text
agent_context(goal, scopes=...)
  → edit
  → review_changes
  → verify_project
```

更深的 Design / Graph / Risk / Reconciliation Tool 按需调用，不再成为每个任务的固定启动成本。

## Architecture-first Project Observatory

- Project Observatory 现在首先展示**整体 Component Architecture**。
- 声明的 Design Dependency 与代码推导出的 Actual Relationship 在同一张图中叠加，并保留明确 Provider / Precision。
- UI 展示可解释的 `Observed Drift`、`Evidence Coverage`、`Implementation Coverage`，而不是一个无法解释的总健康分。
- Strong Semantic/Runtime/Deterministic Positive Evidence 可以形成 Blocking Observed Drift；弱 Syntax 下“未观测到”仍然只是 Advisory。
- Graph Mode 分成 Overlay、Design、Implementation。
- Component Inspector 展示 Responsibility、Implementation Mapping、Changed Path、Product Scope、Dependency 与 Related Requirement。
- Architecture 之后仍可进入 Requirement Drill-down，并保持 Desired State → Actual State → Change → Proof → Convergence。
- Component Ownership 也会使用 Design State Implementation Reference，不再只依赖 Requirement Traceability，因此没有直接 Requirement 的 Component 仍可进入整体架构。

## Git、GitHub 与开发 CLI 策略

v0.4.0 扩大 Agent 能做的开发操作，但没有把 `run_command` 变成 unrestricted Shell。

- Git Read Operation 继续保持有界直接执行。
- 显式 Path 的 `git add`、Message-only `git commit -m ...`、显式 Remote+Ref 的 Non-force `git push` 进入精确 `RiskyExecution` Authorization。
- 已批准的 SSH Push 只通过 wcode 固定非交互 SSH 命令使用当前 SSH Agent；Force/Delete/Mirror/Reset/Restore 继续阻断，HTTPS Token/Credential Helper 不会被隐式授权。
- Git LFS 支持有界 Status/List，以及精确授权的 Transfer/Update Shape。
- GitHub CLI（`gh`）使用 Command-specific Policy：常见 Read View 可直接执行；显式非交互的 PR/Issue/Comment/Workflow/Release/Merge/Run Mutation 进入精确授权；`gh auth`、`gh api`、Secret/Variable、Extension、Admin/Auto Merge 与 Credential/Config Redirect 继续阻断。
- Known Development CLI Policy 新覆盖 `just`、`task`、`uv`、`ruff`、`biome`、`deno`、`docker`、`kubectl`、`terraform`、`fd`、`jq`、`cmake`、`ninja`、`dotnet`、`mvn`、`gradle`、`swift`、`zig`、`pre-commit`、`act`。
- 严格本地 Read/Check Shape 可直接运行；Repository Code Execution、Docker/Kubernetes External Data Read 与有界 Remote/Source Mutation 需要精确授权；破坏性 Infrastructure 与 Credential-bypass Surface 继续阻断。
- Rust Full Verification 在仓库声明且本机安装 `cargo-nextest` 时可以优先使用；否则继续 `cargo test` 回退。

## 更可靠的 Managed Tunnel

Managed Tunnel 不再只依赖 Cloudflare：

```text
auto: Cloudflare → localhost.run → Pinggy
```

- `--tunnel-provider auto|cloudflare|localhost-run|pinggy` 可显式选择行为。
- Auto 模式下 Cloudflare 缺失时不会自动安装，而是直接尝试零安装 SSH Provider。
- `localhost.run` 与 Pinggy 使用有界 No-shell OpenSSH Reverse Forwarding。
- Candidate Public URL 必须通过当前 Runtime `instance_id` 匹配的 `/healthz`；只拿到 URL 不算成功。
- Owned Tunnel Process 异常退出或 Public Health 连续失败会进入现有 Full Runtime Recovery Path。
- Pinggy URL Parser 覆盖当前免费域名形态。

长期稳定部署仍优先使用 Operator-managed `--public-url`。

## Runtime 可维护性与性能

- Managed Tunnel 从 `main.rs` 下沉到 `src/runtime/tunnel.rs`。
- Project Profile / Cache 逻辑下沉到 `harness_profile.rs`。
- Agent Context 与 Repo-map 分别由 `harness_agent_context.rs`、`harness_repo_map.rs` 承担。
- Monitor State / Metrics 下沉到 `monitor_state.rs`。
- 原本过大的 `main.rs`、`harness.rs` 与 Monitor Production Responsibility Cluster 被收缩，同时保持外部 Runtime Surface 不变。
- `software_context` 在同一次请求中复用已经 Load 的 Design State 给 Traceability，避免重复 YAML Parse。
- Repo-map Enrichment 直接从 Code Index 读取目标 Symbol Metadata，不再为每个 Candidate 构造大 File Outline。
- Working-tree Status Enrichment 与 Agent Context 构建 Fail-soft 并行，并且只返回 Direct Target State。

## Documentation 与 Integration Parity

- 英文与简体中文 Manual 现在拥有 Reciprocal Route，并对每一对 Maintained Page 强制相同的 Top-level Section Structure。
- Critical Technical Fact 在两种语言之间做 Contract Test，包括 Agent Context、Product Scope、Architecture-first Observatory Metric、Maintainability Signal、Development CLI Catalog 与 Verification 术语。
- Getting Started、Docs Index、Agentic Engineering、Reference、Security、Product Scopes、Language Quality、Development、Software Intelligence、Code Agent Integrations 统一使用同一套 0.4 Coding Workflow。
- Code Agent Integrations 两种语言使用同一 Host Compatibility Matrix 与章节集合，不再维护“英文长手册 + 中文简略摘要”两套粒度。
- Claude API Deferred MCP Tool Loading 明确作为 Client Optimization；本地 Coding Agent 继续优先 Project stdio MCP。

## Security 与 Precision 边界

0.4 的效率优化没有移除核心 Trust Boundary：

- 不提供 Shell Execution Primitive；
- Canonical Workspace Isolation 与 Protected Path 保持；
- SHA-guarded Write 与 Exact Destructive Authorization 保持；
- Command-specific Policy + Exact Risky Operation Authorization 保持；
- Model 不能批准自己的 Request；
- Tree-sitter 始终是 `precision=syntax`；
- Semantic Precision 需要真实且 Fresh 的 Provider Response；
- Stale Semantic Fact 不能继续指导 Graph-aware Context / Impact；
- 弱 Syntax 下的 Absence 不能升级成“架构关系不存在”的证明；
- Deterministic Check、Independent Reviewer、Advanced Stage、HumanApproval 是独立 Evidence Producer；
- Release / Convergence Claim 需要当前 Revision Evidence。

## 升级

通过正常 Installer 或平台 Release Artifact 安装：

```bash
curl -fsSL https://raw.githubusercontent.com/francis-du/wcode/main/install.sh | sh
```

只有 Operator 准备让当前实例加载新 Binary / Tool Schema 时才重启：

```bash
wcode restart
```

本地 Coding Agent 的 `mcp-stdio` 配置可以保持不变。Cloud/Web Connector 继续使用 `/mcp`；Managed Tunnel 用户可以按需要显式选择 Provider。

Repository 内 `.wcode/` Desired State 保持 Repository-owned。Evidence、Verification、Semantic、Graph、Reconciliation 与 MCP Task Runtime State 继续保存在用户级 Per-workspace State Directory。

## Release Gate

只有 Tagged Revision 通过 Locked Full Gate 与 Repository Governance 后才应发布 v0.4.0：

```text
git diff --check
cargo check --locked
cargo fmt --check
cargo test --locked
cargo clippy --locked -- -D warnings
cargo build --release --locked
```

同时要求有效 Design State、完整 Traceability、双语 Documentation Parity，以及仓库声明的 Required Convention / Product Scope Gate。Local Green Result 只是发布准备 Evidence；最终 Release Claim 应以 Tagged CI / Release Evidence 为准。
