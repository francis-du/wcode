# v0.7.6 — 可衡量的仓库智能

v0.7.6 让 wcode 的仓库智能改进在没有模型 API 预算时也能被确定性衡量，同时继续收紧有界 Agent Context、多目标检索与对抗式验证。下面的 Engineering Fitness 数字只描述冻结的合成开发语料，不代表模型理解率、Bug 发现率或补丁成功率。

## Engineering Fitness

新增的不依赖模型的 Engineering Fitness 将能力拆成检索、语义关系、上下文交付、编辑输入、Bug 相关证据、鲁棒性与成本。冻结的 60 个 Case 覆盖 Rust、Go、TypeScript、Python，并在 1K、2K、4K 响应预算下分别测量 cold / warm 状态。

评估器验证必需身份、完整原始源码、当前文件 SHA、编辑输入齐备、Non-Gold 身份比例、NDCG、字节密度、预算遵守和明确无答案场景。Delivery 诊断进一步区分正文缺失、已验证的原文部分交付、不可用正文以及查询错误导致的未观测，不再把所有缺口压成一个数字。评分器反例保证失败尝试仍进入分母，拒绝预算不匹配，并将未测量值显示为不可用而不是零。

最终 release trial 实际完成 2,520 次计量查询和 180 次预热，查询错误、预热错误和超预算均为 0。在当前冻结语料上，三个预算档位的必需身份、完整源码和符合条件的编辑输入交付在 cold / warm 下均为 100%。这是当前合成语料的回归结果，不是对任意仓库完整覆盖的声明。

## 更紧凑且可编辑的 Agent Context

多组对抗反例证明：过去可能已经找到身份，却在紧预算下丢掉完整正文或当前 SHA。新的 packing 会更早有界准备关联正文，把源码前置条件与保留正文绑定，在删除源码前先压缩可重建元数据，并保持 cold / warm 检索行为确定一致。

在 1K 下，冻结语料从不完整的身份／正文／编辑输入交付提升到完整交付，同时没有提高请求预算。多目标检索现在会在原有候选上限内，为每个显式 literal 保留一个代表定义，避免 Rust 同名 module 声明占满名额、挤掉后续明确请求的函数；明确请求 module 时仍然优先 module。

上下文过滤也从“高 degree 即相关”改为使用任务、Design、已验证 Experience 作为种子，再依据真实图可达性筛选，避免内部连接很多但与当前任务断开的图岛因为边多而进入上下文。

## 对抗证据与安全边界

新增反例覆盖同名 module／函数、跨文件 caller 正文、长短正文争抢预算、陈旧或不匹配 SHA、脱敏／截断源码、重复身份、部分原始源码、Workspace 边界以及同 SHA 并发编辑。Syntax Mutation Candidate 保持有界、绑定真实源码，并明确不充当 Oracle；隔离 fixture 可以杀死生成的 mutation，而不修改生产源码。

安全边界继续失败关闭：陈旧写入被拒绝，只读 Workspace 不可写，父目录／根目录外访问被拒绝，部分图扫描明确报告 truncation，同一个 SHA 的并发写入不能同时提交。

## 发布验证

本次发布准备执行的是 30 个不同验证维度，而不是重复同一条命令凑次数。覆盖格式、类型检查、Engineering Fitness、adversarial／counterexample、context packing／ranking、repo-map／graph、semantic、MCP、Workspace／授权边界、TUI／Observatory、CLI／文档／release／源码契约、完整测试、Clippy、release build、manifest-lock 一致性、CI 同款 intelligence check、安装器语法契约、release JavaScript audit、browser fixture、真实 WebKit，以及 release-profile Engineering Fitness。

真实 WebKit 审计的 96 个生产页面组合全部通过，覆盖宽度、语言、明暗主题和 proof／overview。仓库 release workflow 仍在 CI 中执行 RustSec 依赖审计；本次本地发布准备环境没有安装可选的 cargo-audit 子命令，因此不声称存在本地 RustSec 通过结果。

## 兼容性与操作命令

规范的 Coding 入口仍为 `agent_context`，现有执行诊断 `timed_out` 与 `output_incomplete` 保持兼容。性能预设仍为 `balanced`、`fast`、`light`；仅检查会话仍可使用 `--read-only --no-exec --no-semantic`。CI 行为测试继续使用 Node 24。

无需启动运行实例即可查看完整命令目录：

```sh
wcode help-all
wcode help-all setup
wcode help-all --json
```

发布门禁需要在审查后的 Revision 上运行 `cargo test --locked` 与 `cargo clippy --locked --all-targets -- -D warnings`。

发布顺序保持：审查提交 → 非强制推送 → 精确 SHA 的 CI 全绿 → 版本 Tag → 分发构建与冒烟测试。
