# wcode v0.9.12

本版落地三栏调查布局，让信号终止与未观测退出码在读取上可以区分，并修复图谱、学习与衰减界面上的四处诚实性缺陷。同时移除图查询路径上的三处重复开销。

| 变更 | 用户可见行为 |
| --- | --- |
| 调查布局 | 主区域把已加载对象放在左侧对象导航，页面位于中央，选中对象的摘要位于右侧对象检查器，共享的 Problems/Jobs/Logs/Evidence 面板在底部。身份栏位于该网格之外，因此收窄窗口只会重排列，不会隐藏工作区、revision 或连接状态。 |
| 命令结果身份 | 被信号终止的命令现在在 Jobs 详情中显示 `signal`，与从未被观测到的退出码区分开；缺失的退出码保留破折号。投影新增可选 `signaled` 字段，旧客户端会忽略它。 |
| 对象检查器 | 选中代码符号时给出类型、路径、provider、精度、方向与关系数。选中的需求或组件列出指向它的变更文件。选中的变更给出保留 diff 的块数与新增／删除行数。没有保留数据的值保持未知，而不是读成零。 |
| 图谱新鲜度 | 以"最新图谱"加载的图谱一旦被更新的采集取代，会带上过期标记并指出当前对应的快照；刻意固定的历史快照仍由自己的选择器标注，不报告为过期。仓库概览采用同一规则。 |
| 会话读数 | 抽屉头的会话记录耗时跟随会话，而不是冻结在最后一次记录的跳转。 |
| 验证学习 | 分母为零的学习指标，其值、基线与百分点差保持未知，而不是渲染成已测量的零。验收标准写明了该行为。 |
| 经验衰减 | 重整化惰性衰减因子不再复活过期置信度：旧代码在每次重整化时把每个真实权重放大 `1/scale²`，scale 下溢时还会产生非有限值。完全衰减的证据现在直接过期。 |
| 图查询效率 | 缓存快照改为共享，不再为每次查询深拷贝；历史清单复用派生条目，不再重复解析每个快照；文件级路径证据每次查询只计算一次，而不是每个符号一次。 |
| 对抗覆盖 | 三个故障注入轮次覆盖新增的检查器分支与图谱新鲜度规则；发布审计仍为 300 个不同轮次。 |
| 文档 | 手册修正了 `import-ci-receipt` 的调用方式，记录了三栏调查布局，并首次记录了两张验证信号卡片。 |

## 升级与重连

使用带版本的[发布下载](https://github.com/francis-du/wcode/releases/tag/v0.9.12)与对应的 SHA256SUMS 做固定版本升级。现有 `wcode update` 命令会选择最新稳定版，它没有 `--version` 参数。

替换安装后，请检查正在进行的工作，然后重连 MCP Host 或安排服务重启。源码发布不会替换已在运行的进程。请检查新启动可执行文件的版本及其配置路径。

## 验证身份

发布工作流记录精确提交，运行三平台测试与独立源码包检查、依赖审计、Design/可追溯性检查、真实 WebKit 矩阵以及全部 300 个不同对抗轮次。发布阶段还会构建平台归档并验证新下载。GitHub Release 链接指向实际完成的运行；较早的绿色候选不能验证较新的提交。

WTeam 部署、数据库迁移、身份配置与已安装服务的升级有各自的验收步骤。

## 命令发现与有界执行

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 检查命令目录，无需启动运行时。编码从 `agent_context` 开始；`balanced`、`fast` 与 `light` 预设保留各自的执行与授权边界。只读检查使用 `--read-only --no-exec --no-semantic`。

命令策略与授权默认宽松。`--no-exec` 覆盖会话命令授权，显式加固参数在安全参考中说明，而不是由默认值暗示。

对于中断或不完整的检查，请保留 `timed_out`、`output_incomplete` 与原始任务 ID。请求另一次执行前先读取其结果。维护者门禁包括 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 与当前在线审计。JavaScript 回归使用 Node 24。
