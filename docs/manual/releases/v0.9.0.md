# wcode v0.9.0

v0.9.0 makes repository observation easier to act on and gives model workers a durable coordination protocol. It retains the existing source, diff, graph, Design, runtime, and revision-bound verification views while connecting them through one attention feed.

## Observe and inspect

- The shared attention feed ranks current failures, contradictory evidence, incomplete verification, Design and mapping gaps, risks, large modules, and provider coverage. Every item retains revision identity, provenance and precision; bounded or unavailable inputs remain explicit.
- WebUI connects attention to the relevant view and adds a compact observation strip. File-tree and large-module selections open the real snapshot-bound source inspector.
- The source inspector supports bounded line paging, including empty files. Every page checks the original source SHA; edits, stale replies, invalid ranges and Workspace switches cannot silently show a different file revision.
- The terminal Observatory offers Summary, Attention, Tasks, Providers and Agents tabs with keyboard navigation and retained task details. Project revision, observation age, pending authorizations and missing observations remain visible.
- Sensitive credential headers are redacted before diagnostics enter an observation view.

See [IDE-independent observability](../../ide-independent-observatory/) for the primary-source research, capability matrix, and remaining data-provider gaps.

## Keep your place across the workbench

- All seven pages show the selected workspace, source revision and snapshot state. Navigation restores the last supported page; the page heading and browser title follow workspace and language changes.
- Keyboard users can skip to the active page and return to Acceptance from the brand link. On phones, observation coverage opens as a native disclosure so the current decision or source view has space first.
- Setup reports copy progress and success for the command or endpoint actually copied. If it changes or the page becomes hidden while the clipboard request is pending, a late result cannot claim success for the new value or move focus to stale manual selection. Manual copy remains available when the clipboard fails.
- Tiny terminal windows retain help and stop shortcuts and display the actual dashboard size requirement, including setup and tunnel rows. Wide, compact, authorization and other operator views keep their existing controls.

The [interface review](../../workbench-ui-review/) includes current browser and terminal images from the production renderers with explicit fixture data. These images verify presentation; live provider, OAuth, tunnel, backend and terminal input acceptance keep separate gates.

## Coordinate model workers

Use the Host's native model-spawn facility, then coordinate workers through wcode:

1. Add independent Worklist items with explicit `write_paths`; use an empty array for a read-only lane.
2. Claim a runnable item with `worklist_claim` using current Worklist and repository revisions. The response carries a private claim token and a bounded handoff.
3. Give each worker its own lane and reuse its handoff context while revision and SHAs match; fetch `agent_context` only for missing or stale context. Use guarded edits and renew the 15-minute lease before it expires.
4. Submit a bounded result and existing Evidence IDs through `worklist_submit`. Inspect all results and independently review and verify the combined repository revision.

Overlapping write scopes, stale revisions, dependency blockers, expired leases and incorrect tokens reject the corresponding operation. A claim coordinates work; it never grants filesystem or command authorization. A worker report remains a report, not passing Verification or HumanApproval. Hosts without model-spawn capabilities can execute these same lanes serially. `parallel_tools` continues to batch server operations rather than creating model workers.

## Use context efficiently

The task manifest keeps ordered canonical tool names while removing reconstructible routing duplicates before source budgeting. The deterministic public tool catalog keeps MCP compatibility and shortens repeated default-Workspace guidance. Source bodies, SHA guards, native checks, failure states and authorization controls remain available.

Measurements distinguish serialized bytes and byte-based token estimates from actual provider token accounting. These changes do not establish end-to-end model cost, cache-hit rate, patch success or latency improvements. Engineering Fitness continues to expose its denominators and partial coverage.

## Compatibility and command discovery

Start coding work with `agent_context`; command timeouts retain `timed_out` and `output_incomplete` diagnostics. The `balanced`, `fast` and `light` presets keep their existing boundaries. Use `--read-only --no-exec --no-semantic` for passive inspection.

Use `wcode help-all`, `wcode help-all setup` or `wcode help-all --json` to discover commands without starting the runtime. Development and CI use Node 24 for behavior checks, `cargo test --locked` for the complete suite and `cargo clippy --locked --all-targets -- -D warnings` for lint validation.

## Verification and distribution

The release gates cover locked Rust checks, complete behavior tests, strict Clippy, release builds, Design and Traceability, bilingual documentation, version consistency, real WebKit rendering, and the 300-round audit against the exact candidate commit. Linux x86_64, Windows x86_64 and macOS Apple Silicon, Intel and Universal archives include SHA256 checksums. Publication and native archive startup are checked separately from local tests.
