# v0.6.2 — 更快执行、更简配置、更清楚的可观测性

本页对应 0.6.2 发布准备。同步源码版本和完成本地构建不等于已经发布 GitHub Release；跨平台 CI、安装包冒烟检查与正式发布是独立门禁。不重写已有 v0.6.1 标签及其附件。

## 聚焦仓库理解

带明确文件与行号的诊断，在 `agent_context` 中先于广域符号检索处理。保留源码原文、行范围和 SHA 编辑前置条件，也支持适用的非代码文件。目标缺失或不可访问时明确报告，不把无关结果提升为编辑目标。简单位置查询暂缓不必要的仓库图扩展；调用方、影响范围和显式 Scope 查询仍保留深入路径。

精确符号优先于宽泛关键词，同一候选不再因匹配多个关键词而重复复制。同一文件的并发冷查询共享索引构建，不同文件仍可独立执行。`symbol_context` 核对符号信息与返回原文是否属于同一文件版本；旧索引最多重新获取一次，持续变化无法得到稳定结果时明确失败。

## 有效并行与命令诊断

协调阻塞线程池上限、前台资源预算与有界文件 I/O 工作线程，而不是把外层工具槽位当作实际吞吐。执行请求排队时，为非执行工具保留受控余量。固定形式的 Git 查询使用独立有界进程队列，不再因等待编译器名额而一并阻塞。

独立文件修改使用共享有界 I/O 池，保留 SHA 校验、原始编辑范围、逐文件原子写入和有序的部分失败结果。没有保留实测无收益的宽线程池读取实验。不承诺通用提速百分比，也不把占满峰值槽位当作性能目标。

命令超时保留已收集诊断，并返回 `timed_out`、`output_incomplete` 和重试提示。取消操作继续管理子进程与输出读取任务；超时不等于回滚，也不会自动重放修改。输出仍有容量限制；超大命令日志完整的头尾同时保留不属于本版已实现能力。

## 验证与证据

全量验证记账覆盖全部推导检查，不再静默截断混合语言检查计划。默认失败阶段阻止后续工作；相应 Schema 也提供完整诊断模式。验收检查未执行完整时不能生成通过证据，单个语言质量检查不能代替整项目验证。

验证历史在一次请求中共享代码版本与证据快照，不再逐计划重复扫描；空历史不扫描源码或证据。后续新请求仍识别代码修改和新增证据，没有加入跨请求沿用旧结果的缓存。展示为当前计划时，必须同时匹配代码与 Design State。

观测台区分历史记录与当前版本的有效结果。重试替代受目标、类型、来源、模型、置信度、目标集合与策略约束；相同时间戳发生冲突时保留失败。窄范围检查不能消除宽范围失败。有界证据明细展示检查、来源、证据属性、时间与已记录的诊断摘要。证据缺失和扫描截断不能证明通过。

## 简化配置与明确审批

`wcode help-all` 展示全部内置 CLI 命令和参数，包括隐藏的高级选项、短参数、别名、声明默认值与枚举可选值。用 `wcode help-all setup` 聚焦一个命令，或用 `wcode help-all --json` 输出机器可读目录。目录来自真实解析器定义，标明全局参数及兼容行为，不启动服务，也不执行被查询命令。普通帮助保持简洁并提供该入口；它不是 MCP 工具目录，也不授予外部程序执行权限。

`balanced`、`fast`、`light` 三档组合常用资源设置，同时保留高级覆盖参数。先预览安装，不写配置：

```bash
wcode setup --performance fast --dry-run
wcode --show-config
```

执行 `wcode setup --performance fast` 才会保存所审核的启动选项。面向不同宿主的 JSON/TOML 安装器保留这些参数及无关服务器配置；文件被并发修改时，原始 SHA 前置条件拒绝覆盖，而不是静默重新规划。无效或互相矛盾的参数在写入前失败。

常见且受支持的 Git 生命周期操作可进入精确人工批准，不再永久拒绝；批准不会授予 Full Access。文件只读模式不代表命令没有副作用；仅查看的组合为 `--read-only --no-exec --no-semantic`。

## 更清楚的项目观测台

首屏分开显示执行、待批准请求、工作树变更与有效验证结果。可搜索组件卡片与详情检查器为默认架构入口，同时保留 Design / Implementation / Overlay 依赖图。需求、文件、历史和分析器细节按需展开。

活动刷新独立于慢项目刷新，首次打开也不互相等待。有活动时，在本次请求完成后间隔两秒发起下次活动请求；空闲活动与项目检查间隔八秒。隐藏页面停止读取轮询。共享进程资源与当前项目任务分开标记，未采样不等于零或空闲。

所有访问配置修改绑定工作区与选择代次，抑制重复提交并忽略迟到响应。语义刷新也遵守同样的选择代次规则；旧版本轮询不能让新授权列表失效。写操作遇到网络或服务器错误时，需要核对实际状态后再决定重试，不自动重放。仅证据变化也能触发刷新，变更检测使用有界元信息身份，不必解析全部证据正文。

## 升级与兼容

正式发布后使用 `wcode update`，再重启或重新连接对应 MCP 宿主，使其启动新二进制并重新加载工具 Schema。仅构建源码不会替换已安装程序，也不会重启现有进程。工作区隔离、精确审批和持久状态格式保持兼容。

只有运行实例的工具 Schema 已声明时，才能使用 `parallel_tools.dry_run` 等新可选字段。旧实例忽略未知参数不等于安全预览。计划预览只检查调度关系，不证明授权或文件前置条件有效，也不执行任务。

研究路线图不等于已经交付独立模型 CLI、浏览器 Agent 或 PTY 子系统；不宣称已经完整替代其他编程智能体。真实浏览器视觉、无障碍验收与跨平台结果必须来自实际执行，不能由 JavaScript 模拟环境或本地 Rust 测试推断。

## 发布门禁

Cargo、Cargo.lock 和六份市场／插件清单统一为 0.6.2，依赖版本不变。CI 测试矩阵显式安装 Node 24，以执行 JavaScript 行为回归。Windows 打包逐项检查原生命令的构建／冒烟退出码，并在生成压缩包前核对暂存二进制版本。

创建 `v0.6.2` 标签前，执行与 CI 一致的锁定依赖检查：

```text
git diff --check
cargo check --locked
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo build --release --locked
```

检查 Design State、追踪映射与项目约定。独立核对当前版本的持久化证据，不能把命令成功输出与旧证据混为一谈。Linux/macOS/Windows 测试矩阵、发布包签名、校验和及安装器门禁通过后，才能宣布正式发布成功。不移动已发布标签。
