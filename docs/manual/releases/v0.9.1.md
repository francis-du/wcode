# wcode v0.9.1

This maintenance release brings together the retained Jobs workflow and targeted verification and dependency fixes. It does not change command authorization or grant new filesystem permissions.

## Jobs that stay attached to the selected task

The Jobs view provides status and UI/MCP-origin filters over the retained records returned by the server. Matching and retained counts remain visible; filtering neither executes work nor claims that a bounded history is complete. Workspace and session changes clear obsolete preferences and rebind current controls, including when their labels are unchanged.

Refresh and cancellation controls are bound to the workspace, session and task that created them. A callback retained from task A cannot cancel a subsequently selected task B. Queued polls recheck their task, observation sequence, visibility and polling budget before reading. Cancellation still follows server-owned task authority; an uncertain response does not authorize an automatic retry.

## Verification discovery and dependencies

Explicit nested Cargo workspaces remain independent verification islands, including manifests using valid inline `workspace = {}` tables. Ordinary members continue to be covered by their owning workspace. Discovery refreshes after the manifest boundary changes rather than silently retaining an incomplete check plan.

The locked TLS verification dependencies are updated to the reviewed patch versions. The macOS menu-bar event loop keeps native window-handle support while disabling unused X11/Wayland default features and their font/rendering dependency chain. The actual native startup and cleanup tests remain in place.

Broad-command sandbox regression tests initialize their own private authority and intelligence roots inside fresh child processes. Missing protected roots still fail closed in production; test isolation does not relax that behavior or alter the parent environment.

## Compatibility and verification

Start coding work with `agent_context`. Command timeouts continue to expose `timed_out` and `output_incomplete`; a completed process is not automatically passing Acceptance. The `balanced`, `fast` and `light` presets retain their existing boundaries. Use `--read-only --no-exec --no-semantic` for passive inspection.

Use `wcode help-all`, `wcode help-all setup` and `wcode help-all --json` for command discovery without starting the runtime. Development behavior tests use Node 24. The release candidate must pass `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings`, dependency audit, Design checks, native WebKit and the full 300-round audit. These are release requirements, not claims inferred from earlier local test results.

Official archives and SHA256SUMS are published only by the gated release workflow. Linux, macOS and Windows downloads are then exercised separately by native archive-verification jobs. Check the exact tag and workflow results for publication status; the presence of this document alone does not establish a published or validated binary.

WTeam development, customer identity integrations, payment configuration and production database operations are outside this Wcode release.
