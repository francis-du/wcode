# v0.8.2 — 持久执行与代码图谱可靠性

v0.8.2 把这一轮工程控制面能力收口成可发布、可独立验证的完整流程：加入持久 Execution 观测和结构化 Steering，强化进程／Cargo 准入，在大型仓库里让 Code Graph 更稳定可用，并把发布对抗门禁从 30 个场景扩展为 100 个不同场景。

## 持久 Execution 与 Steering

- Engineering Observatory 可展示当前 Execution 状态，同时不持久化聊天记录。
- Structured Steering 受 revision guard 保护，只允许一个待处理 directive；目标或 scope 改变使冻结计划失效时必须进入 Reconciliation replan。
- Handoff 生成干净的 Execution lineage，同时保留验证强度下限和结构化待处理状态。
- Verification strength 单调增强，后续 Steering 不能静默降低已经要求的 full／adversarial 证明。

## 资源与命令隔离

- 重型子进程容量按 Workspace／subspace 隔离，同时保留独立的 Host 全局硬上限。
- Cargo 使用全局 registry-exclusive lane、每 Workspace writer lane 与有界共享 test reader。
- 已取消的 blocking work 在真实 worker 退出前仍保持可观察，并继续占用真实容量。
- Writer lease 与 mutation domain 保证共享 worktree 单 writer；linked worktree 仍可独立。

## Code Graph 与 Observatory

- Code Graph 搜索支持源码关键字 fallback，自动发现不会污染用户搜索框。
- 全局 graph symbol budget 改为跨文件 round-robin 分配普通定义，前面的大文件不会再把后面模块挤成只剩一个 file 节点。
- 清除搜索会取消在途请求，并原子清空旧 query／selected node 状态，不再复活旧图。
- 全屏模式升级为独立 graph workspace：锁定背景滚动、图谱／Inspector 填满视口、Esc 退出、窄屏纵向布局，并提供 dialog 语义。
- 真实 Browser／WebKit 门禁覆盖 240 个宽度、语言、主题和视图组合。

## Verification Mesh

- 仓库内 no-shell Property／Mutation／Fuzz executor 同时覆盖 Rust 与 JavaScript。
- JavaScript Property 与 Fuzz 各执行 2048 个生成式 case，Mutation 杀死 4/4 source mutant。
- Rust 保留 Unicode／CRLF edit property corpus、generated mutant-kill oracle 与有界 deterministic edit fuzz。
- 发布审计现在运行 100 个不同的 adversarial round，而不是重复一套绿色测试；结果写入 `target/wcode-adversarial-100.json`，并绑定 clean、稳定的 Git revision。

## 兼容性与发现

主要的有界编码入口继续是 `agent_context`。命令结果继续暴露 `timed_out` 与 `output_incomplete`，资源预设仍为 `balanced`、`fast`、`light`；JavaScript 行为 CI 使用 Node 24。

CLI 发现保持无副作用：

```text
wcode help-all
wcode help-all setup
wcode help-all --json
```

强化后的纯检查组合仍为 `--read-only --no-exec --no-semantic`。最终 Rust 发布验证包含：

```text
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

## 发布验证

v0.8.2 候选版本必须通过 locked fmt/check/clippy/test/release-build、Design／Traceability／Product Scope、release metadata 与 installer contract、真实 WebKit、Verification Mesh，以及 clean-worktree 100 轮 adversarial audit，之后才允许打 tag。

发布流程保持：reviewed release-prep commit → 非强推 push → 精确 SHA CI 全绿 → `v0.8.2` tag → 跨平台产物和 GitHub Release。
