# wcode v0.9.11

This version extends the "never print an absent measurement as a measured zero" contract across every counter the TUI shows, closes four Observatory honesty gaps, and fixes a silent loss of recorded reconciliation progress.

| Change | User-visible behavior |
| --- | --- |
| TUI counters | Drift findings, the three evidence counters, verification blockers, the eight graph counters, the semantic and provider groups, and the design, policy and scope groups now stay unknown until their own event is observed. A failed refresh leaves them unknown instead of printing zero forever. |
| Unobserved design | An empty design-consistency matrix says that no design object was observed and that an empty matrix is not an all-clear, instead of attributing the emptiness to the active filter. |
| Zero-denominator rates | The fail-fast frontier and the cost-model replay no longer print `0.0%` over zero samples or a zero baseline. The numerator and denominator stay visible and the rate reads "not measured". |
| Failure location | The verification report states that check rows retain no structured failure location and that no line is inferred, so an operator does not expect a jump the data cannot support. |
| Investigation label | The identity bar carries the operator's investigation label, so a shared link's label is readable with the drawer closed. |
| View switches | Switching main views restores the place the operator left; hiding a panel clamps the document scroll, which previously lost it. |
| Reconciliation pruning | Pruning keeps the newest snapshot of every plan. Evicting all of a plan's snapshots made the next update recreate it with every task Pending, silently discarding claimed, completed and failed state. |
| Standalone gate | The OSS source-package gate gives the git baseline stages room on a scanned Windows filesystem; the stage had failed twice while neighbouring stages stayed fast. |

The added payload fields are additive: an older client ignores them, and no existing call changes shape.

## Upgrade and reconnect

Use the versioned [release downloads](https://github.com/francis-du/wcode/releases/tag/v0.9.11) and the matching SHA256SUMS for a pinned upgrade. The existing `wcode update` command selects the latest stable release; it has no `--version` option.

After replacing an installation, reconnect the MCP Host or arrange a service restart after inspecting active work. A source release does not replace an already running process. Check the newly started executable's version and its configured path.

## Verification identity

The release workflow records the exact commit, runs three-platform tests and standalone source-package checks, dependency audit, Design/traceability checks, the real WebKit matrix and all 300 distinct adversarial rounds. Publication additionally builds platform archives and verifies fresh downloads. The GitHub release links identify the actual completed runs; older green candidates do not validate a newer commit.

WTeam deployment, database migration, identity configuration and installed-service upgrades have their own acceptance steps.

## Command discovery and bounded execution

Use `wcode help-all`, `wcode help-all setup` and `wcode help-all --json` to inspect the command catalog without starting the runtime. Start coding with `agent_context`; the `balanced`, `fast` and `light` presets retain their execution and authorization boundaries. Passive inspection uses `--read-only --no-exec --no-semantic`.

Command policy and authorization are permissive by default. `--no-exec` overrides session command grants, and the explicit hardening flags are documented in the security reference rather than implied by the default.

For an interrupted or incomplete check, retain `timed_out`, `output_incomplete` and the original task ID. Read its result before requesting another execution. Maintainer gates include `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings` and the current online audit. JavaScript regressions use Node 24.
