# v0.7.6 — Measurable repository intelligence

v0.7.6 makes wcode's repository-intelligence improvements measurable without requiring model API budget. It also tightens bounded Agent Context delivery, multi-target retrieval and adversarial verification. The Engineering Fitness numbers below describe the frozen synthetic development corpus; they are not model understanding, bug-finding or patch-success scores.

## Engineering Fitness

The new model-free Engineering Fitness suite separates retrieval, semantic relationships, context delivery, edit inputs, bug-relevant evidence, robustness and cost. Its frozen 60-case corpus covers Rust, Go, TypeScript and Python at 1K, 2K and 4K response budgets in cold and warm phases.

The evaluator verifies required identities, complete original source, current file SHA, edit-input readiness, non-Gold identity fraction, NDCG, byte density, budget compliance and explicit no-answer cases. Delivery diagnostics distinguish absent, verified partial-original, unusable and unobserved-on-error bodies instead of collapsing every miss into one number. Scorer counterexamples keep failed attempts in denominators, reject mismatched budgets and render unavailable measurements as unavailable rather than zero.

The final release trial completed 2,520 measured queries plus 180 warmups with zero query, warmup or over-budget errors. On this corpus, required identity, complete source and eligible edit-input delivery are 100% at all three budgets in both cold and warm phases. This is a regression result for the current synthetic corpus, not a claim of universal repository coverage.

## Tighter bounded Agent Context

Several adversarial cases showed that identities could be found while their complete bodies or current SHA were lost under tight budgets. Packing now prepares bounded related bodies earlier, preserves source prerequisites with retained bodies, compresses reconstructible metadata before deleting source, and keeps cold/warm discovery behavior deterministic.

At 1K, the frozen corpus moved from incomplete identity/body/edit delivery to complete delivery without increasing the requested budget. Multi-target cases now preserve a representative definition for every explicit literal within the existing candidate cap, so same-name Rust module declarations cannot consume all slots ahead of later requested functions. Explicit module queries still prefer modules.

Context filtering also uses task/design/verified-experience seeds and graph reachability rather than treating high degree alone as relevance. This keeps disconnected but internally busy graph islands from winning merely because they have many edges.

## Adversarial evidence and safety

New counterexamples cover same-name modules and functions, cross-file caller bodies, long and short bodies competing for space, stale or mismatched SHA evidence, redacted/truncated source, duplicate identities, partial original source, workspace boundaries and concurrent same-SHA edits. Syntax mutation candidates remain bounded, source-bound and explicitly non-oracular; isolated fixtures can kill a generated mutation without modifying production source.

Safety boundaries remain fail closed: stale writes are rejected, read-only workspaces stay read-only, parent/outside-root access is denied, partial graph scans report truncation, and concurrent writes against one SHA cannot both commit.

## Release verification

Release preparation ran 30 distinct verification dimensions rather than repeating one command to inflate a count. They included formatting, type checking, Engineering Fitness, adversarial/counterexample suites, context packing and ranking, repo-map and graph checks, semantic and MCP stacks, workspace/authorization boundaries, TUI and Observatory tests, CLI/docs/release/source contracts, full tests, Clippy, release build, manifest-lock consistency, the CI intelligence check, installer syntax contract, release JavaScript audit, browser fixture audit, the real WebKit audit and release-profile Engineering Fitness.

The real WebKit audit covers all 96 production-page combinations across width, language, theme and proof/overview modes. Its default CI path still runs the full matrix. For tool hosts with a shorter synchronous-call ceiling, the release audit accepts `--rounds=START-END` and the WebKit runner accepts `--cases=START-END`, so the same coverage can be executed in bounded shards without changing the default CI contract. The repository release workflow still performs RustSec dependency auditing in CI; the local environment used for this release preparation did not have the optional cargo-audit subcommand installed, so no local RustSec result is claimed.

## Compatibility and operator commands

The canonical coding entry remains `agent_context`. Existing execution diagnostics `timed_out` and `output_incomplete` are preserved. An explicit Workspace all-command grant or Full Access now has one consistent meaning through the MCP command lane: command-shape filters, executable allowlists, Git hardening and the normal no-shell command policy no longer create secondary authorization friction inside the selected Workspace. Filesystem-root, protected-path, symlink/hard-link and guarded file-tool boundaries remain independent. Performance presets remain `balanced`, `fast` and `light`; inspection-only sessions can still use `--read-only --no-exec --no-semantic`. CI behavior tests continue to use Node 24.

`run_command` and `verify_project` accept command/check timeouts up to 1800 seconds. Modern MCP clients that advertise Tasks receive a durable task immediately for `verify_project` and poll it instead of holding one synchronous request open; clients without Tasks support retain the synchronous compatibility path. `workspace_info.mcp.server_version` reports the version of the binary actually serving the connection, making a stale pre-upgrade MCP process visible instead of looking like a regression in the newly built source.

The complete command catalog remains available without starting the runtime:

```sh
wcode help-all
wcode help-all setup
wcode help-all --json
```

For the release gate, run `cargo test --locked` and `cargo clippy --locked --all-targets -- -D warnings` on the reviewed revision.

Publication remains reviewed commit → non-force push → successful CI for that exact SHA → version tag → distribution builds and smoke tests.
