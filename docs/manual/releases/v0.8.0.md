# v0.8.0 — Engineering Digital Twin

v0.8.0 moves wcode closer to its core goal: understand and supervise a software system without depending on a traditional code editor. The Engineering Observatory becomes a bounded Engineering Digital Twin, repository scanning becomes ignore-aware, heavy browser-driven Observatory refresh loops are removed, the TUI becomes task-first, and the calibrated Decision Plane remains behind deterministic safety authority.

## Engineering Digital Twin

Engineering Architecture now contains an internal Code Graph workbench beside System Map, Components and Dependencies. It is deliberately not an eighth top-level workspace: architecture remains the primary mental model and code relationships are a deeper observable layer.

The graph supports bounded Calls, Impact and All Evidence modes. Symbol search can trace callers, callees, references, dependencies, implementation ownership, tests, requirements and verification/proof context. Exploration has hard depth/node/edge limits and uses upstream → focus → downstream lanes rather than an unbounded node-ball.

Every retained node and edge preserves provenance and precision. Declared, syntax, semantic/LSP, runtime, deterministic and heuristic relationships are never flattened into one confidence claim. The inspector explains why a selected node is related, including direction, relation kind, provider and precision, and marks source files that are part of the current working-tree change.

Graph History is available directly in the Code Graph workbench. Selecting a stored snapshot performs read-only graph time travel so callers, dependencies and proof context can be inspected at an earlier graph revision without rebuilding the repository.

## Faster, calmer Observatory

Per Workspace, the server now allows at most one background Observatory snapshot rebuild at a time. Cached responses are revision-stamped and explicitly report cached/current/refreshing state. Browsers render usable cached state immediately and use lightweight bounded probes rather than fan-out heavy snapshot rebuilds.

The WebUI keeps exactly seven primary workspaces. Code Graph is an Engineering Architecture workbench mode, not a new top-level tab. v0.8 capability cards are driven by Harness runtime capabilities rather than hard-coded product promises.

All observability workspaces now share one visual grammar. Project Pulse and status are first-glance signals; bounded metrics, relations and timelines are second-glance context; evidence and inspectors are third-glance detail. Overview, Digital Twin, Task Activity, Verification Evidence, Current Changes, Requirements and Runtime use consistent semantic beacons and state edges. Supporting/status metadata is kept at 12px or larger, and stale, unknown, inconclusive, failed or unverified states never receive the same visual treatment as current passing proof.

## Ignore-aware repository intelligence

Repository-wide source, search, index, status and subspace discovery share ignore-aware walking. .gitignore, .ignore, Git global/exclude rules and protected paths are honored by default; known heavy generated trees such as Rust target, node_modules, caches and build outputs are pruned before traversal.

Explicit intent still wins: directly addressed ignored paths remain queryable through bounded read/search operations. Profile and contract discovery keep their own visibility policy so legitimate build/codegen configuration is not hidden by source-scan performance rules.

## Task-first TUI

Wide terminals use a 70/30 layout with Workspace Activity as the main canvas and Engineering/connection state in a compact right-side control rail. The rail is reduced to four independent semantic lines — ARCH, DRIFT, PROOF and MODEL — with policy error/warning state prioritized before truncation. Medium and narrow terminals remove the permanent Engineering Pulse so task rows remain dominant. The I Engineering Console remains the deliberate drill-down for Architecture and Proof/Runtime.

Pairing, authorization, recovery controls, command discovery and tiny-terminal fallbacks remain visible and bounded.

## Calibrated Decision Plane and Shadow A/B

The provider-neutral Decision Plane emits bounded Probability, Choice and Score signals while deterministic authorization, SHA preconditions, evidence and verification remain behavioral authority.

Context sufficiency is calibrated out-of-band against independently authored Engineering Fitness Gold rather than wcode readiness fields. On the current 60-case model-free diagnostic, 1K cold and warm delivery both reach 100% required identity recall, 100% complete-body recall, 100% fresh-SHA recall and 58/58 eligible writable cases with all required edit inputs. The established decision baseline remains Brier 0.018846 with zero false stops and zero false continues.

Provider Shadow A/B compares baseline and candidate batches on the same immutable DecisionRequest and records missing/shared signals, numeric deltas, Choice disagreement, malformed shape and safety-policy violations. Candidate providers remain observational only. No external Jev/System-One provider is enabled in v0.8.0.

## Retrieval, inspection and runtime reliability

Engineering Fitness retains the lower-noise retrieval baseline and explicit distinction between localization, complete source delivery, fresh SHA and edit readiness.

Bounded scan_patterns includes AST-validated Go bug-pattern checks for nil-dereference candidates, swallowed errors, index mismatches, empty tests and unguarded subscripts. Truncated scans never claim repository-wide absence.

Process-executing tools acquire execution admission before consuming global tool capacity so non-command work retains headroom. Cancellation and queue behavior remain fail-closed: cancelled waiters cannot strand capacity, started blocking work owns its permits until completion, and cancellation never implies rollback.

## Compatibility and safety

v0.8.0 does not require a new API key or external decision service. Existing MCP clients continue to use the same deterministic Workspace, authorization, protected-path, SHA and verification boundaries.

The Engineering Digital Twin is read-only observability. It does not create a second mutable project state. Full Access remains an explicit operator decision and cannot be inferred from Decision Plane output or graph relationships.

Compatibility contracts remain explicit and searchable: `agent_context` remains the bounded coding-context entry point; command results retain `timed_out` and `output_incomplete`; the resource presets remain `balanced`, `fast` and `light`; JavaScript behavior CI uses Node 24; the hardened inspection-only combination remains `--read-only --no-exec --no-semantic`; and the reviewed release gate includes `cargo test --locked` plus `cargo clippy --locked --all-targets -- -D warnings`.

Inspection-only sessions can continue to use --read-only --no-exec --no-semantic. The complete command catalog remains available without starting the runtime:

    wcode help-all
    wcode help-all setup
    wcode help-all --json

## Release verification

The pre-release audit replays the historical trust/tunnel, TUI authorization, WebUI refresh/error, real-WebKit geometry and release fail-closed counterexamples. The current Observatory behavior suite passes 44/44 scenarios, TUI console coverage passes 9/9, real macOS WebKit validates 12 layout widths, and the full production browser audit covers 96 width/language/theme/tab combinations. The release audit report binds its input digest to Git HEAD plus clean/dirty worktree state.

Final publication evidence is not accepted from a mutable worktree. The exact reviewed release commit must pass the full locked Rust gate, Clippy with warnings denied, optimized release build, Design State validation, release contract, macOS WebKit audits, 30-round adversarial audit in --require-clean mode, and normal CI for that exact SHA.

The release workflow is reviewed commit → non-force push → green CI for that exact SHA → v0.8.0 tag → cross-platform distribution builds and GitHub Release publication.
