# wcode v0.9.2

本版本完善通过独立 Observatory、TUI 与 MCP 进行工程管理的使用路径。

| 改动 | 实际行为 |
| --- | --- |
| 工程工作队列与 Activity 导航 | 无需 IDE 即可检查保留的工程任务，并跳转到精确任务 ID。 |
| 统一命令输出检查器 | 对 stdout/stderr 进行字面搜索、切换大小写匹配，每页读取 25 条匹配行，同时保留输入法、焦点、滚动和折叠状态。 |
| 观察恢复 | 返回 Activity 或恢复页面可见性时，继续观察选中的运行中任务；刷新历史和隐藏期间返回的请求也能恢复观察。 |
| 源码与图查询 | 受控源码导航保留依赖来源和不确定归属；零节点命中不会带回无关边。 |
| 跨平台验证可靠性 | 受控夹具保留真实 Cargo 竞争、端点并发和 CRLF 断言，并提供有界冷启动协调。 |

观察只读取同一任务 ID，不重跑命令，也不重置原有 120 次观察预算。会话或工作区改变会使旧请求和旧控件失效；错误、取消不确定性、终态和预算上限继续明确显示。

## 升级与重连

固定版本升级请使用 [v0.9.2 发布下载](https://github.com/francis-du/wcode/releases/tag/v0.9.2) 及同一版本的 SHA256SUMS。现有 `wcode update` 选择当时最新稳定版本，没有 `--version` 参数。

替换安装文件后，需要重连 MCP Host；独立服务应在核对活动任务后安排重启。源码发布不会替换已经运行的进程。重新启动后检查可执行文件版本及 Host 配置的实际路径。

## 验证身份

发布流程记录精确提交，运行三平台测试、独立源码包检查、在线依赖审计、Design/追踪契约、真实 WebKit 和全部 300 轮独立对抗验证。发布还会构建各平台归档并重新下载验收。实际完成的运行链接记录在 GitHub Release；旧候选的绿色结果不能验证新提交。

WTeam 部署、数据库迁移、身份配置和运行服务升级分别验收。

## 命令发现与有界执行

使用 `wcode help-all`、`wcode help-all setup` 和 `wcode help-all --json` 可在不启动运行服务的情况下检查命令目录。编码前调用 `agent_context`；`balanced`、`fast`、`light` 预设继续保留各自的执行和授权边界。被动检查使用 `--read-only --no-exec --no-semantic`。

检查中断或输出不完整时，保留 `timed_out`、`output_incomplete` 和原任务 ID，先读取原任务结果再决定后续执行。维护门禁包括 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 和当前在线依赖审计。JavaScript 回归使用 Node 24。
