# wcode v0.9.7

This version makes the heavy detail responses cheap by default and makes change navigation land on the object it names instead of an unfocused section.

| Change | User-visible behavior |
| --- | --- |
| Bounded detail responses | `evidence_status`, `project_context`, `software_context`, `traceability_status`, `risk_status` and `worklist_status` now default to `detail=summary`. Each keeps the identity, counts and provenance an agent acts on and declares every omission; `detail=full` restores the complete projection in one hop. Measured on this repository the six defaults drop from about 2.78M to about 0.68M code units. |
| Actionable worklist | `worklist_status` returns unfinished items by default instead of the whole completion history. In this repository 59 of 64 items were already done; goal, revision, counts, runnable lanes and coordination metadata are unchanged, and the omission is declared. |
| Precise change navigation | Convergence-map cards and attention signals now select and focus the object they name. A drift signal resolves its affected requirement to the owning component through the explicit design mapping instead of revealing an unfocused architecture section. |
| Edit-ready scope | `readiness.edit_scope` qualifies `ready` when only some declared targets have a usable source body, so a multi-target task cannot read as fully prepared while `target_source_coverage_incomplete` is present. The qualifier is emitted only when the scope is not complete, so a fully covered task pays nothing. |
| Graph file bound | `software_graph`'s `max_files` now counts indexable source files rather than every walked path. A bound below the dotfile count no longer returns a design-only graph with no source, and composite snapshots report the source-versus-overlay node and edge counts. |
| Journal overflow recovery | An engineering journal that had already outgrown its retention ring rejected every later append, so `evidence_journal_export` and `change_fingerprint` failed and the directory kept growing. An over-large journal is now pruned back to the 512-milestone ring, readers report the retained window and the real total, and only a scan past the pathological directory bound fails closed. |

The `detail` argument is additive: existing callers that omit it get the bounded response, and `detail=full` keeps the previous payload. Unknown values fail closed.

## Upgrade and reconnect

Use the versioned [release downloads](https://github.com/francis-du/wcode/releases/tag/v0.9.7) and the matching SHA256SUMS for a pinned upgrade. The existing `wcode update` command selects the latest stable release; it has no `--version` option.

After replacing an installation, reconnect the MCP Host or arrange a service restart after inspecting active work. A source release does not replace an already running process. Check the newly started executable's version and its configured path.

## Verification identity

The release workflow records the exact commit, runs three-platform tests and standalone source-package checks, dependency audit, Design/traceability checks, the real WebKit matrix and all 300 distinct adversarial rounds. Publication additionally builds platform archives and verifies fresh downloads. The GitHub release links identify the actual completed runs; older green candidates do not validate a newer commit.

WTeam deployment, database migration, identity configuration and installed-service upgrades have their own acceptance steps.

## Command discovery and bounded execution

Use `wcode help-all`, `wcode help-all setup` and `wcode help-all --json` to inspect the command catalog without starting the runtime. Start coding with `agent_context`; the `balanced`, `fast` and `light` presets retain their execution and authorization boundaries. Passive inspection uses `--read-only --no-exec --no-semantic`.

Command policy and authorization are permissive by default. `--no-exec` overrides session command grants, and the explicit hardening flags are documented in the security reference rather than implied by the default.

For an interrupted or incomplete check, retain `timed_out`, `output_incomplete` and the original task ID. Read its result before requesting another execution. Maintainer gates include `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings` and the current online audit. JavaScript regressions use Node 24.
