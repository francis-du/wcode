# wcode v0.4.0

v0.4.0 focuses on making coding agents **faster, cheaper in context, and more reliable** while keeping repository mutation and proof boundaries explicit. The release also makes Project Observatory architecture-first, adds resilient free tunnel fallback, and expands bounded policies for GitHub and common development CLIs.

## Coding speed and context efficiency

- `agent_context` is the normal coding entry point and replaces a fixed multi-tool startup sequence with one bounded edit-ready pack.
- Omitted budgets use an adaptive range: direct tasks stay compact while ambiguous or cross-module work can receive more context within a hard bound.
- Scope-aware cold repo-map construction avoids scanning the full repository when direct ownership is known.
- Repo-map structure is revision-aware cached; task ranking is still recomputed for each query.
- Multi-query symbol search traverses/indexes a source root once instead of rescanning for every query token.
- The strongest direct match may include bounded Hot Source so common small changes can move from context to edit without another source round trip.
- Fresh semantic/runtime/deterministic graph evidence can strengthen caller/callee/dependency ranking; stale semantic revisions fall back to syntax automatically.
- Exact SHA edit targets, related tests, working-tree advisories, `readiness`, and deterministic `next_actions` reduce avoidable tool retries.
- Timing, cache, and savings telemetry stays in Tool Result `_meta` instead of consuming model-visible context.
- The TUI tracks Agent Context calls, average model-visible tokens, repo-map cache-hit rate, and saved context.

The default workflow is now:

```text
agent_context(goal, scopes=...)
  → edit
  → review_changes
  → verify_project
```

Deeper Design/Graph/Risk/Reconciliation tools remain available on demand rather than being mandatory startup overhead.

## Architecture-first Project Observatory

- Project Observatory now shows the **overall component architecture first**.
- Declared Design dependencies and code-derived Actual relationships share one graph with explicit provider/precision.
- The UI exposes interpretable `Observed Drift`, `Evidence Coverage`, and `Implementation Coverage` instead of a generic health score.
- Strong observed semantic/runtime/deterministic undeclared relationships can become blocking drift; missing weak syntax evidence remains advisory.
- Graph modes separate Overlay, Design, and Implementation views.
- Component Inspector exposes responsibilities, implementation mappings, changed paths, Product Scopes, dependencies, and related Requirements.
- Requirement drill-down remains available after architecture and preserves Desired State → Actual State → Change → Proof → Convergence.
- Architecture ownership now also uses Design State implementation references, not only Requirement traceability, so components without a direct Requirement can still appear in the overall model.

## Git, GitHub, and development CLI policy

v0.4.0 expands what an agent can do without turning `run_command` into an unrestricted shell.

- Git read operations remain direct and bounded.
- Explicit-path `git add`, message-only `git commit -m ...`, and explicit remote+ref non-force `git push` enter exact `RiskyExecution` authorization.
- Approved SSH pushes may use the current SSH Agent only through wcode's fixed non-interactive SSH command. Force/delete/mirror/reset/restore forms remain blocked; HTTPS token/credential-helper access is not silently granted.
- Git LFS has bounded status/list and exact-authorized transfer/update shapes.
- GitHub CLI (`gh`) has command-specific policy: common read views can run directly; explicit non-interactive PR/Issue/comment/workflow/release/merge/run mutations enter exact authorization; `gh auth`, `gh api`, secrets/variables, extensions, admin/auto merge, and credential/config redirection remain blocked.
- Known development CLI policy now covers `just`, `task`, `uv`, `ruff`, `biome`, `deno`, `docker`, `kubectl`, `terraform`, `fd`, `jq`, `cmake`, `ninja`, `dotnet`, `mvn`, `gradle`, `swift`, `zig`, `pre-commit`, and `act`.
- Strict local read/check shapes may run directly; repository code execution, external Docker/Kubernetes data reads, and bounded remote/source mutations require exact authorization; destructive infrastructure and credential-bypass surfaces remain blocked.
- Rust full verification can prefer repository-declared, installed `cargo-nextest`; otherwise it keeps the `cargo test` fallback.

## Resilient managed tunnels

The managed tunnel path is no longer Cloudflare-only.

```text
auto: Cloudflare → localhost.run → Pinggy
```

- `--tunnel-provider auto|cloudflare|localhost-run|pinggy` selects behavior explicitly.
- Auto mode skips missing Cloudflare rather than installing it and immediately tries zero-install SSH providers.
- `localhost.run` and Pinggy use bounded no-shell OpenSSH reverse forwarding.
- Candidate public URLs must pass the current runtime's instance-matched `/healthz`; URL discovery alone is not considered success.
- Owned tunnel process exit and repeated public-health failure enter the existing full runtime recovery path.
- Pinggy URL parsing includes current free-domain forms.

A stable operator-managed `--public-url` remains the preferred long-lived deployment path.

## Runtime maintainability and performance

- Managed tunnel code moved out of `main.rs` into `src/runtime/tunnel.rs`.
- Project profile/cache logic moved into `harness_profile.rs`.
- Agent Context and repo-map logic live in `harness_agent_context.rs` and `harness_repo_map.rs`.
- Monitor state/metrics moved into `monitor_state.rs`.
- The previous oversized `main.rs`, `harness.rs`, and monitor production responsibility clusters were reduced without changing the external runtime surface.
- `software_context` reuses one loaded Design State for traceability instead of reparsing the same YAML in the same request.
- Repo-map enrichment reads targeted symbol metadata directly from the Code Index instead of constructing a large file outline for every candidate.
- Working-tree status enrichment runs fail-soft alongside Agent Context construction and only returns direct-target state.

## Documentation and integration parity

- English and Simplified Chinese manuals now share reciprocal routes and the same top-level section structure for every maintained page.
- Critical technical facts are contract-tested across both languages, including Agent Context, Product Scopes, architecture-first Observatory metrics, maintainability signals, the development CLI catalog, and verification terminology.
- Getting Started, the docs index, Agentic Engineering, Reference, Security, Product Scopes, Language Quality, Development, Software Intelligence, and Code Agent Integrations now use the same 0.4 coding workflow.
- Code Agent Integrations keeps the same host compatibility matrix and section set in both languages rather than maintaining a long English guide and a short Chinese summary.
- Claude API deferred MCP Tool loading is documented as a client optimization, while local coding agents continue to prefer project stdio MCP.

## Security and precision boundaries

The 0.4 productivity changes do not remove the core trust boundaries:

- no shell execution primitive;
- canonical Workspace isolation and protected paths;
- SHA-guarded writes and exact destructive authorization;
- command-specific policy plus exact risky-operation authorization;
- model requests cannot approve themselves;
- Tree-sitter remains `precision=syntax`;
- semantic precision requires a real fresh provider response;
- stale semantic facts cannot guide graph-aware context or impact;
- weak syntax absence is not promoted into proof of missing architecture;
- deterministic checks, independent reviewers, advanced stages, and HumanApproval remain separate Evidence producers;
- release/convergence claims require current-revision Evidence.

## Upgrade

Install the release through the normal installer or platform artifact:

```bash
curl -fsSL https://raw.githubusercontent.com/francis-du/wcode/main/install.sh | sh
```

Restart a currently running instance only when the operator is ready for it to load the new binary and Tool schema:

```bash
wcode restart
```

Local coding-agent configurations can keep the same `mcp-stdio` command. Cloud/web connectors can keep `/mcp`; managed-tunnel users may optionally select a provider explicitly.

Existing repository `.wcode/` Desired State remains repository-owned. Evidence, Verification, Semantic, Graph, Reconciliation, and MCP Task runtime state remains in the user-level per-Workspace state directory.

## Release gates

A v0.4.0 tag should be published only after the tagged revision passes the locked full gate and repository governance checks:

```text
git diff --check
cargo check --locked
cargo fmt --check
cargo test --locked
cargo clippy --locked -- -D warnings
cargo build --release --locked
```

Also require valid Design State, complete traceability, bilingual documentation parity, and the repository's required Convention/Product Scope gates. Local green results are preparation evidence; the actual release claim belongs to the tagged CI/release evidence.
