# wcode v0.5.2

v0.5.2 重点优化治理和 Agent 使用体验：减少 MCP 调用时的参数噪声，让互不依赖的工作更容易真正并行执行，为本机用户提供一条命令完成 Agent 配置，补齐 stdio MCP 的人工授权闭环，并把 Verification 升级为 Revision-aware 与 Target-aware，同时不降低现有 Workspace 和授权边界。

## 更干净的 MCP 调用

- 面向模型的 Tool Schema 不再暴露服务端默认值；Runtime 的默认行为不变。
- Limit、Timeout、Result Count、Graph Size、Body Size 等低频调优字段不再出现在模型可见 Schema 中，但 Runtime 仍兼容旧调用方显式传入这些参数。
- 可选 `workspace` 参数明确提示：只有切换离开默认 Workspace 时才传。
- Server Instructions 与可移植 Agent Skill 都要求模型只发送当前动作真正需要的参数，并省略可推导的 Path / Limit / Timeout / Budget。
- `parallel_tools` 继续用于紧凑 Fan-out，但不再推荐用一个巨大的嵌套 Arguments JSON 来表达并发。

因此 MCP Host 展示的 Tool Call 会更短、更容易读，同时底层安全与执行能力没有缩水。

## 依赖感知的并行 Agent 工作流

- `agent_context.readiness.parallelism` 现在会返回 Strategy 与 Candidate Lane 数量。
- 单目标工作返回 `single_lane`；存在独立多目标时可以返回 `top_level_concurrent_calls`。
- Workflow 明确要求模型先按依赖拆任务：独立的 Discovery / Read / Review / File-local Lane 在 Host 支持时使用多个顶层 Tool Call 并发执行，只有真实依赖才串行。
- 输入已经明确时，继续优先使用 `read_files`、`search_many`、`apply_file_edits`、`create_files` 等 Bulk Primitive，以更少 Round Trip 完成工作，同时避免嵌套 MCP 参数噪声。
- 多个模型意见一致仍然只是 Model Evidence，不是 Deterministic Proof。

## 一键配置与 CLI 生命周期

本机正常路径现在是：

```bash
cd /path/to/repository
wcode setup
wcode
```

- 交互式 `wcode setup` 提供“全局（推荐）/ 当前项目”两种 Scope。全局模式只在本机确认后写入已验证的用户级 Host 路径；非交互调用默认保持项目级。
- 本地 Host 配置统一只写 `wcode mcp-stdio`，由 Host 当前目录决定默认 Workspace，不再在安装配置里固化仓库绝对路径。
- `wcode setup --dry-run` 只预览不写入；`--json` 保留机器可读自动化路径。
- Canonical Package 源目录缩短为 `plugin/`，并由 Binary 内嵌；用户项目里没有任何插件目录也不影响 Setup。
- 安装后的 Skill 直接叫 `wcode`，并包含 `wcode setup` / `wcode update` 生命周期说明、Compact Tool Call、Worklist 恢复，以及同类操作优先使用 wcode Repository Tool、避免被当前会话其他通用工具状态干扰的规则。
- `agent-plugin` 继续用于插件包导出与兼容，但从默认命令目录隐藏。
- `restart` / `stop` 被移除：前台 HTTP/TUI 统一由 Ctrl-C / SIGTERM 管理，stdio 子进程由 MCP Host 管理，升级统一使用 `wcode update`。同时删除独立 Runtime Control Route / Token State，减少一套生命周期维护面。
- 低频 Transport、资源调优和宽 Trust Boundary 参数继续兼容，但不再挤占默认 `--help`。
- 原来的 WCode ASCII Logo 保留在 CLI Help 顶部，下面接紧凑的 CLI Contract。
- `wcode update` 通过已验证的 Release Installer Contract 安全更新当前安装。

Unix 与 Windows 安装器安装完成后也会直接提示最短下一步：在仓库里运行 `wcode setup`，然后运行 `wcode`。

## stdio 人工授权

本地 stdio MCP 不再要求用户只能去 TUI / WebUI 批准受限命令。

- MCP 2026 Client 使用 Multi-round-trip `input_required` Elicitation。
- 兼容 2025 协议的 stdio Client 只在协商到 Form Elicitation 能力后使用 `elicitation/create`。
- 授权重试状态绑定 Pending Authorization、MCP Client Owner 和随机 Opaque Challenge。
- Challenge 保留在 Runtime 私有状态中，不作为模型可见 Grant Token。
- Host 不支持 Form Elicitation 时继续 Fail Closed。wcode 不提供模型可调用的 Approval Tool，也不会抢占 stdio JSON-RPC 流去读取终端 yes/no。

## 持久工作、源码上下文与 Operator Access

- 每个 Workspace 增加 Revision-guarded 持久 Worklist，未完成任务可以跨重连 / 换模型恢复；`agent_context` 自动带回活动清单，更新不能静默删除未完成项，并发旧 Revision 会 Fail Closed。
- `read_file` / `read_files` 保留源码原始格式，每个文件 / 调用最多返回 1,000 行；Skill 仍要求优先 Outline / Symbol 定位，不通过 Minify 源码来省 Token。
- `parallel_tools` 子任务默认继承父调用 Workspace，除非子任务显式覆盖，避免并行 Fan-out 悄悄掉回进程默认 Root。
- TUI Full Access 通过显式二次确认加入当前用户 Home，并启用其他可授权 Runtime 能力；CLI 提供 `--full-access` 显式形式。Protected Path、Symlink/Hard-link、No-shell、Filesystem Root 等硬边界继续保留。

## Tunnel 恢复与稳定 Endpoint

- Managed Tunnel 在最后一条 Primary 消失时不会再对空 Live-tunnel 集合取 index；全部公网隧道掉光后状态回到 Pending，并暂时回退本地 URL，而不是让 Runtime 崩溃。
- Provider 恢复从 5 秒开始做有界指数退避，300 秒封顶；一次通过实例健康校验的重连会清零旧死亡计数，避免历史抖动把未来恢复永久拖到长等待。
- Endpoint 不健康时 Health Probe 会更频繁，恢复后回到正常探测间隔。
- Cloudflare Quick Tunnel、localhost.run、Pinggy 属于 Session-style Endpoint，重连后 hostname 可能变化。wcode 能在本机注册新 URL，但已经配置旧 hostname 的远程 MCP Client 无法自行发现新地址；长期远程连接应使用 Tailscale Funnel 的稳定 `ts.net` 或 Operator 管理的稳定 `--public-url`。

## Revision-aware 与 Target-aware Verification

- Verification Plan 绑定完整 Active Revision：Code + Design State。
- 只有 Design Contract 变化、代码不变时，也不能继续沿用旧活动规格创建的 Plan。
- 历史 Evidence 继续保留审计价值，但新 Revision Evidence 不会串入旧 Plan。
- Correctness Review 采用 Contract-first：规格不确定时返回 `Inconclusive`；`Fail` 需要 Observable Counterexample、Invariant Violation 或可复现行为，而不是“我更喜欢另一种 Patch”。
- 新 Verification Plan 会冻结 Stage Target，例如语言 Target。
- Property / Mutation / Fuzz / Runtime Evidence 明确声明自己实际覆盖的 Target，因此一种语言的 Pass 不能替另一种语言清门禁。
- Risk 会暴露 Target-specific 的本地 Automation Gap，不再把“Policy 已声明”误当成“Executor 已具备”。

## 文档与 Release 导航

- README、快速开始、Agent 集成、CLI/MCP Reference、官网 Quick Start、插件文档与安装器输出统一使用 `Install → wcode setup → wcode`。
- 日常文档不再把高级 Tunnel 或资源调优当成主路径。

## 升级

现有安装可以直接：

```bash
wcode update
```

也可以继续使用 Release Installer：

```bash
curl -fsSL https://raw.githubusercontent.com/francis-du/wcode/main/install.sh | sh
```

然后在仓库里：

```bash
wcode setup
wcode
```

已有项目 MCP 配置、显式高级参数、持久化 Design State、Verification History、Evidence 与 OAuth State 保持兼容；唯一有意移除的 CLI 入口是低价值的 `restart` / `stop`。

## 发布门禁

Release Revision 必须通过：

```text
git diff --check
cargo check --locked
cargo fmt --check
cargo test --locked
cargo clippy --locked -- -D warnings
cargo build --release --locked
```

Release Workflow 还会验证 Crate / Plugin Manifest 版本锁定、Installer Contract、Source / Documentation Layout 与平台 Release Artifact。
