# wcode v0.9.1

本次维护版本整合保留任务的 Jobs 工作流、验证发现修复及依赖维护，不改变命令授权规则，也不授予新的文件系统权限。

## 任务操作始终对应原来的选择

Jobs 页面可以按任务状态和 UI/MCP 来源筛选服务端返回的保留记录，同时显示匹配数与已加载数。筛选不会执行工作，也不会把有界历史说成完整历史。Workspace 或会话改变后，旧偏好失效，即使界面文字相同也会重新绑定当前控件。

刷新和取消按钮绑定生成时的 Workspace、会话和任务。任务 A 的旧回调不能取消随后选择的任务 B；已经进入队列的轮询也会重新检查任务、观察序号、页面可见性和轮询次数限制。服务端的任务归属和取消权限继续保留，结果不确定不能触发自动重试。

## 验证发现与依赖维护

显式嵌套 Cargo workspace 会保持独立验证范围，包括合法的内联 `workspace = {}` 清单。普通成员仍由其所属根工程覆盖，不重复派发。清单中的工程边界改变后重新计算发现结果，不继续沿用缺少子工程的检查计划。

锁定的 TLS 验证依赖更新到已审查的补丁版本。macOS 菜单栏事件循环保留原生窗口句柄支持，关闭未使用的 X11/Wayland 默认特性及其字体、渲染依赖链；真实原生启动与清理测试继续执行。

宽范围命令的 sandbox 回归在新的子进程和私有目录中初始化权限与智能状态根，不依赖其他并行测试先创建目录。生产逻辑仍拒绝缺失的受保护根，测试隔离不会放松这项要求，也不会改变父进程环境。

## 兼容性与验证

编码任务从 `agent_context` 开始；命令超时继续保留 `timed_out` 和 `output_incomplete`。进程完成不等于 Acceptance 通过。`balanced`、`fast`、`light` 预设保持原有边界，被动检查使用 `--read-only --no-exec --no-semantic`。

使用 `wcode help-all`、`wcode help-all setup`、`wcode help-all --json` 发现命令，不启动运行时。开发行为测试使用 Node 24。发布候选必须执行 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings`、依赖审计、Design 检查、真实 WebKit 和完整 300 轮审计；这些是发布要求，不是从历史局部测试推断出的通过结论。

正式归档与 SHA256SUMS 仅由带门禁的发布流程生成，随后分别在 Linux、macOS 和 Windows 原生运行下载验收。发布状态以精确标签及对应工作流为准，这份说明文件本身不证明二进制已经发布或完成验证。

WTeam 的开发、客户身份联调、支付配置和生产数据库操作不包含在本次 Wcode 发布中。
