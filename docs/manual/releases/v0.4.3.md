# wcode v0.4.3

v0.4.3 makes wcode easier to connect, safer to authorize, and clearer to operate. It adds project-local Agent host setup, brings all MCP transports onto one runtime path, keeps OAuth sessions stable while tunnels reconnect, and gives the TUI and WebUI a more useful view of the selected repository.

## Agent setup

- `wcode --workspace "$PWD" agent-plugin --install-all --dry-run` reports detected hosts, evidence, target files, planned merges, and manual steps without writing anything.
- `--install-all` safely configures recognized project-local JSON or TOML formats. Existing MCP servers are preserved, writes are SHA-guarded and atomic, and unknown schemas fail closed.
- Claude Code, Codex, VS Code with GitHub Copilot, Cursor, Gemini CLI, Qwen Code, Kiro, Qoder CLI, and OpenCode have explicit adapters where a safe project format is known. Hosts without a reliable local schema receive concrete manual guidance.
- `wcode-agent-plugin/` is now the single source for the exported README, Skill, manifests, and Agent Plugins 1.0 `mcp.json`. Export profiles cover skill-only, local stdio, and remote Streamable HTTP without storing credentials.

## MCP sessions and tunnels

- Local stdio, preferred remote Streamable HTTP at `/mcp`, and legacy SSE through `/sse` plus `/message` share the same JSON-RPC dispatch, Harness, Workspace policy, and tool catalog.
- Legacy SSE keeps bounded session and channel counts, cleans up disconnected clients, binds each session to its OAuth client and tunnel origin, and retains Origin protection.
- Client registrations and access/refresh tokens no longer age out or disappear on restart. They are stored per configured Workspace-root set; a verified replacement tunnel can continue the session without weakening resource binding.
- OAuth metadata and authorization pages use the registered tunnel that received the request. Connecting through one tunnel no longer sends the browser to another tunnel's URL.
- Client IDs issued before v0.4.3 can be recovered when their next authorization completes, with the same redirect validation and local pairing-code check.

## Workspace authorization

- The WebUI can authorize a directory inside the selected parent Workspace as a controlled derived subspace. Relative paths resolve from the selected Workspace, while symlink escapes and ordinary overlapping Workspace rules remain blocked.
- Executable access and an exact repository operation remain separate grants. WebUI approval is tied to the selected Workspace, denial creates no grant, and changing arguments requires another exact approval.
- Automatic project discovery recognizes common Rust, JavaScript, Python, Go, Java, Gradle, and Swift boundaries without recursively splitting nested crates inside an existing project boundary.

## Operator views

- Press `I` to load Software Intelligence for the selected project and `C` to open the complete command catalog. The pairing code stays visible after OAuth and MCP connect.
- The terminal layout uses the documentation palette, keeps project and help links in a stable footer, and separates executable access from exact-operation approval.
- Project Observatory now includes a bounded file tree, directory depth, largest files, and a visible 1,000-line limit. A truncated index is labeled instead of being presented as complete.

## Repository structure

- Large Rust, JavaScript, CSS, and test modules were split into domain directories. Root tests remain under `tests/`, filenames are bounded, and maintained text files are capped at 1,000 physical lines.
- The `.wcode` Design State now carries those layout rules and the new Agent, transport, authorization, TUI, and WebUI contracts.
- Search paths reuse ASCII-insensitive matching and multi-query finders while preserving overlapping-pattern behavior.

## Upgrade

```bash
curl -fsSL https://raw.githubusercontent.com/francis-du/wcode/main/install.sh | sh
```

No Workspace or Design State migration is required. Replace the binary and run `wcode restart`. Existing pre-v0.4.3 clients may authorize once more so wcode can recover and persist their registration; later restarts retain the session.
