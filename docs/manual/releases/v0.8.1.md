# v0.8.1 — Jev Decision Plane hardening

v0.8.1 is a focused hardening release on top of v0.8.0. It keeps the deterministic Decision Plane as behavioral authority, narrows Jev to explicit semantic judgments, removes the previous mixed naming, and closes two WebUI state-truthfulness gaps discovered during adversarial review.

## Jev naming and configuration

Jev is now the only product name for the external semantic decision provider. The local model-free layer remains the **Decision Plane** and the main large model remains the **Reasoning Model**.

The runtime uses only:

- `JEV_API_KEY`
- `JEV_BASE_URL`
- `JEV_DEFAULT_MODEL`

The previous naming aliases are not retained. `jev-latest` remains the default model and `https://api.typesafe.ai` remains the default Jev endpoint.

## Narrower Jev judgments

The Agent Context Jev question set is now `wcode.agent_context@3`.

Broad questions such as whether semantic navigation is merely "useful" have been replaced by narrower criteria-backed judgments, including whether semantic relationships are **necessary evidence before a safe edit**. Choice options now use explicit positive and negative boundaries and include `other_review` for states that should abstain instead of pretending to be edit-ready.

Low-concentration Choice output no longer means "do more reasoning" by default. It becomes an abstain-and-collect-evidence signal.

## Strict increase-only authority

Jev remains advisory and may increase work by requesting more retrieval, semantic navigation, or verification. It cannot reduce deterministic safety.

A Jev `edit_then_verify` recommendation is now suppressed unless the deterministic baseline already selected the same action. Unknown edit readiness routes to `other_review` instead of silently collapsing into edit readiness.

The Jev advisory block is also dropped when it would exceed the Agent Context budget; source, SHA preconditions, tests, and deterministic risk evidence always take priority.

## WebUI state truthfulness

The Code Graph now binds every rendered response to the current request semantics: `query`, `mode`, `depth`, and `snapshot` must all match before the response can be published.

The Access view now publishes workspaces, commands, and authorizations atomically. If any of the three responses fails shape validation, the whole group remains Unknown rather than exposing a partially truthful UI state.

## Compatibility and discovery

`agent_context` remains the bounded coding-context entry point. Command results continue to expose `timed_out` and `output_incomplete`, and the resource presets remain `balanced`, `fast`, and `light`.

CLI discovery remains side-effect free and available through:

```text
wcode help-all
wcode help-all setup
wcode help-all --json
```

The hardened inspection-only combination remains `--read-only --no-exec --no-semantic`. JavaScript behavior CI continues to use Node 24.

## Verification

The release gate keeps the v0.8 trust boundary:

- `cargo test --locked`;
- `cargo clippy --locked --all-targets -- -D warnings`;
- locked Rust format/check and optimized release-build gates;
- deterministic Design State validation;
- release metadata and installer contracts;
- WebUI browser behavior and real WebKit geometry checks;
- adversarial release audit against the exact reviewed SHA.

v0.8.1 is published from a clean reviewed commit. The release flow is reviewed commit → non-force push → green CI for that exact SHA → `v0.8.1` tag → cross-platform distribution builds and GitHub Release publication.
