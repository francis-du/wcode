# wcode v0.9.3

This version closes the gap between "a change is listed" and "a change can be understood", speeds up the bounded graph queries that back the Observatory, and makes the trust model explicit instead of implicit.

| Change | User-visible behavior |
| --- | --- |
| Code reader symbol outline | The reader lists the definitions the bounded graph observed for the open file, with kind and line range, jumps to a definition, marks the ones whose lines the captured change overlaps, and chips the requirements whose explicit design mappings name that symbol. |
| Changed-definition requirement chips | The change inspector chips each changed definition with the requirements it serves, so a diff can be read without leaving the inspector. |
| Direct line jumps | A bounded line input in the reader toolbar jumps to any line, paging through the revision-bound source. |
| Honest change state | When the working-tree review is unavailable, every change-derived count and pill now says "unknown" instead of rendering zero or "clean". |
| Graph query efficiency | Bounded chain queries index incident edges once instead of scanning the full edge list per visited node; cost-model sentinel ranking computes the later-phase cost once instead of per candidate. |
| Explicit trust boundaries | Command policy and authorization are permissive by default and the hardening flags are documented; `--no-exec` overrides session command grants; workspace roots are inherited from the agent session; the sandbox is opt-in per call. |
| Bounded evidence receipts | Captured CI check-run receipts are retained locally with a repository binding and digest verification, and externally verified stage executors can be admitted as observation-only evidence. |
| Intelligence response headers | Every `/intelligence` response is sent with `Cache-Control: no-store`, `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`. |
| Cross-platform reliability | The Windows runtime and CLI parse on explicit large stacks, transient Windows replace failures are retried, and probe-capacity artifacts are retried with a bounded budget instead of flaking. |

The symbol outline and the changed-definition chips only report what the bounded graph and the explicit design mappings contain. An empty outline is an observation gap, never a claim that the file defines nothing; the changed marker is line overlap, not semantic impact; a symbol without an explicit `path::symbol` mapping shows no requirement chip rather than a guessed owner.

## Upgrade and reconnect

Use the versioned [release downloads](https://github.com/francis-du/wcode/releases/tag/v0.9.3) and the matching SHA256SUMS for a pinned upgrade. The existing `wcode update` command selects the latest stable release; it has no `--version` option.

After replacing an installation, reconnect the MCP Host or arrange a service restart after inspecting active work. A source release does not replace an already running process. Check the newly started executable's version and its configured path.

## Verification identity

The release workflow records the exact commit, runs three-platform tests and standalone source-package checks, dependency audit, Design/traceability checks, the real WebKit matrix and all 300 distinct adversarial rounds. Publication additionally builds platform archives and verifies fresh downloads. The GitHub release links identify the actual completed runs; older green candidates do not validate a newer commit.

WTeam deployment, database migration, identity configuration and installed-service upgrades have their own acceptance steps.

## Command discovery and bounded execution

Use `wcode help-all`, `wcode help-all setup` and `wcode help-all --json` to inspect the command catalog without starting the runtime. Start coding with `agent_context`; the `balanced`, `fast` and `light` presets retain their execution and authorization boundaries. Passive inspection uses `--read-only --no-exec --no-semantic`.

Command policy and authorization are permissive by default. `--no-exec` overrides session command grants, and the explicit hardening flags are documented in the security reference rather than implied by the default.

For an interrupted or incomplete check, retain `timed_out`, `output_incomplete` and the original task ID. Read its result before requesting another execution. Maintainer gates include `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings` and the current online audit. JavaScript regressions use Node 24.
