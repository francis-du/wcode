# v0.7.3 — 开发命令自治、更完整的多语言质量与更强可靠性

v0.7.3 是一次可靠性与开发流程版本：让有界的仓库开发命令默认自治，扩展原生多语言质量能力，强化 Context 与 Cache 正确性，并修复 Engineering Observatory 与 Verification 的一批回归，同时不削弱永久安全边界。

Release Candidate 先 Commit 并 Push。只有该精确 Commit 的普通 CI 全绿后，才创建 `v0.7.3` Tag。

## 开发命令不再反复要求授权

已知仓库开发工具的正常 Build、Test、Lint、Format、Codegen、Package Manager 与 Project Runner 工作流现在直接进入自治开发通道。常见 Cargo、Make、Node Package Manager、Deno、Dart/Flutter、Maven/Gradle、.NET 以及其他已登记语言工具链不再制造重复 RiskyExecution Prompt。

Workspace 仍不是无限制 Shell。Shell Interpreter、受保护或越界路径、Credential Flow、Registry Publish/Owner，以及明确的 Host-wide 或破坏性操作继续保持硬边界。Make Variable Assignment、外部 clang-format Style File 重定向和精确 Read-only Verification Shape 也得到更准确的分类。

## 更完整的语言质量与更可靠的仓库智能

Deno 获得原生 Quality Provider。Flutter 项目使用 Flutter Analysis 与 Test，同时继续使用 Dart Format。Quality Registry 对全部索引语言继续展示真实能力与显式 Gap，而不是简单的支持/不支持布尔值。

Agent Context、Repo Map、Convention/Profile Discovery、Graph/Provider State、Evidence/Experience Store 与 Intelligence Snapshot 又进行了一轮正确性加固。共享 Flight 与 Cache 在 Invalidation 后拒绝陈旧结果回写，保持 Workspace/Revision 隔离，并减少重复扫描，同时不会把旧源码状态伪装成新鲜 Context。

## Observatory、Verification 与 Runtime 可靠性

Engineering Observatory 的 Refresh、Runtime、Quality 与 Engineering Surface 围绕当前 Endpoint State、Scoped Response、Incremental Refresh 与多语言展示进行了加固。打包 JavaScript 的行为测试把 UI 回归纳入发布门禁。Verification 对仓库 Test Executor 与 Advanced-stage Evidence 的路由更精确；Tunnel Lifecycle 对网络抖动、陈旧 Health Probe 与 Failover Race 也更可靠。

## Diagnostics 与 Operator 兼容性

`agent_context` 继续作为任务就绪仓库检索的主要入口。命令结果保留明确的 `timed_out` 与 `output_incomplete` Diagnostics。长时间 Command、Project Verification、Quality Provider 与 Advanced Stage 执行现在可申请最长 30 分钟（1800 秒），默认值仍保持 120 秒，普通失败仍能及时终止。`balanced`、`fast`、`light` 资源预设保持兼容，并且不会改变授权策略。Hardened Inspection-only 组合仍为 `--read-only --no-exec --no-semantic`。

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 查看 Parser 定义的完整命令面，不执行被查询命令。Release CI 继续安装 Node 24 运行打包 JavaScript 行为测试。

## 发布门禁

Release Candidate Push 前必须通过 `git diff --check`、`cargo check --locked`、`cargo fmt --check`、`cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 与 `cargo build --release --locked`。同一轮准备还会检查 Design State、Product Scope、Documentation/Release Contract、Installer 与 Repository Convention。

v0.7.3 Commit 到达 `main` 后，该精确 SHA 的普通 Build & Release 与 Documentation CI 必须全绿，之后才创建 `v0.7.3` Tag。Tag Workflow 再构建并 Smoke-test Linux、macOS Universal 与 Windows 分发包，最终发布 GitHub Release。
