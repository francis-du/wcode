# v0.7.4 — Session command trust, standard MCP media, and current product docs

v0.7.4 is a focused operator-experience and interoperability release. It lets a human explicitly authorize all otherwise-allowable commands for one Workspace for the current runtime session, fixes `read_media` to use protocol-standard MCP image/audio Tool Result content, and refreshes the README, website, screenshots, and system diagrams to match the product that actually ships.

The release candidate is committed and pushed first. The `v0.7.4` tag is created only after normal CI for that exact commit is green.

## Exact approval or all commands for this Workspace session

TUI, protected Engineering Observatory WebUI, and form-capable stdio authorization now share the same Workspace-scoped runtime state. The operator can approve one exact request, choose `all_commands` for the selected Workspace session, or deny. In the TUI, **A** grants all commands for the selected Workspace from the authorization view and **F** toggles that grant from the command view. The WebUI Access panel exposes the same explicit switch.

The session grant resolves pending `CommandAccess` and `RiskyExecution` requests for that Workspace and suppresses repetitive prompts until it is revoked or the runtime exits. It does not cross into another Workspace. Destructive file deletion remains exact and one-shot, and permanently blocked command shapes remain blocked.

## Standard MCP image and audio Tool Results

`read_media` stays metadata-first. `include_content=true` is now the explicit per-call opt-in for standard MCP `image` and `audio` content blocks; clients no longer need the private `run.francis.wcode/media-content` extension. PNG/JPEG/GIF/WebP image content and supported audio content can therefore flow through ordinary MCP Tool Results when requested. Video remains metadata-only because MCP has no standard video Tool Result content block.

## Current screenshots and living system documentation

The product tour now uses current TUI and Engineering Observatory captures for Overview, Engineering architecture, Task activity, Verification evidence, Current changes, Requirements, Project files, Access, and Setup Hub. Historical Observatory/verification/workspace-intelligence screenshots that no longer describe current product surfaces were removed.

The root README was rebuilt as a compact product entrypoint instead of a release/link index. Four SVGs now explain the engineering control loop, Repository Intelligence stack, Verification Mesh, and security boundary. English and Chinese versions are maintained separately, and the website presents them as a living system model that must evolve when the product architecture, proof model, or trust boundaries change.

## Reliability and compatibility

`agent_context` remains the primary task-ready retrieval entrypoint. Command results retain explicit `timed_out` and `output_incomplete` diagnostics. The `balanced`, `fast`, and `light` resource presets remain compatible. The hardened inspection-only combination remains `--read-only --no-exec --no-semantic`.

Use `wcode help-all`, `wcode help-all setup`, and `wcode help-all --json` to inspect the complete parser-defined command surface. Release CI continues to install Node 24 for bundled JavaScript behavior tests.

## Release gate

The release candidate must pass `git diff --check`, `cargo check --locked`, `cargo fmt --check`, `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings`, and `cargo build --release --locked`. The same preparation validates Design State, Product Scope, bilingual documentation, current UI contracts, release metadata, and installer/plugin manifests.

After the v0.7.4 commit reaches `main`, the exact SHA must pass normal Build & Release and documentation CI before the `v0.7.4` tag is created. The tag-triggered workflow then builds and smoke-tests Linux, macOS Universal, and Windows distributions before publishing the GitHub Release.
