# wcode v0.9.2

This version improves engineering management through the standalone Observatory, TUI and MCP interfaces.

| Change | User-visible behavior |
| --- | --- |
| Engineering work queue and Activity navigation | Inspect retained engineering work and navigate to the exact task without an IDE. |
| Unified command-output inspector | Search literal stdout/stderr text, choose case matching and read 25 matching lines per page while preserving IME input, focus, scroll and disclosure state. |
| Observation recovery | Returning to Activity or a visible page resumes the selected working task's bounded observer. History refresh and an in-flight response settling while hidden also recover observation. |
| Source and graph inspection | Guarded source navigation preserves dependency provenance and uncertain ownership. A zero-node graph match does not return unrelated edges. |
| Cross-platform verification reliability | Controlled fixtures retain actual Cargo contention and endpoint concurrency assertions with bounded startup coordination and CRLF coverage. |
| Runtime dependency safety | Tokio is locked to 1.53.3, which addresses the I/O-safety advisory [RUSTSEC-2026-0386](https://rustsec.org/advisories/RUSTSEC-2026-0386.html). |

Observation reads the same task ID. It does not rerun a command or renew the existing 120-observation budget. Session/workspace changes invalidate obsolete requests and controls; error, uncertain cancellation, terminal state and budget limits remain visible.

## Upgrade and reconnect

Use the versioned [release downloads](https://github.com/francis-du/wcode/releases/tag/v0.9.2) and the matching SHA256SUMS for a pinned upgrade. The existing `wcode update` command selects the latest stable release; it has no `--version` option.

After replacing an installation, reconnect the MCP Host or arrange a service restart after inspecting active work. A source release does not replace an already running process. Check the newly started executable's version and its configured path.

## Verification identity

The release workflow records the exact commit, runs three-platform tests and standalone source-package checks, dependency audit, Design/traceability checks, the real WebKit matrix and all 300 distinct adversarial rounds. Publication additionally builds platform archives and verifies fresh downloads. The GitHub release links identify the actual completed runs; older green candidates do not validate a newer commit.

WTeam deployment, database migration, identity configuration and installed-service upgrades have their own acceptance steps.

## Command discovery and bounded execution

Use `wcode help-all`, `wcode help-all setup` and `wcode help-all --json` to inspect the command catalog without starting the runtime. Start coding with `agent_context`; the `balanced`, `fast` and `light` presets retain their execution and authorization boundaries. Passive inspection uses `--read-only --no-exec --no-semantic`.

For an interrupted or incomplete check, retain `timed_out`, `output_incomplete` and the original task ID. Read its result before requesting another execution. Maintainer gates include `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings` and the current online audit. JavaScript regressions use Node 24.
