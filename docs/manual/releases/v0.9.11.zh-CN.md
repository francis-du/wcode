# wcode v0.9.11

本版把"缺失测量不得显示为实测零"的约定扩展到 TUI 展示的所有计数，补上 Observatory 四处诚实性缺口，并修复已记录 reconciliation 进度被静默丢失的问题。

| 变更 | 用户可见行为 |
| --- | --- |
| TUI 计数 | 偏离发现数、三个证据计数、验证阻塞数、八个图谱计数、语义与提供方分组，以及设计、策略与范围分组，在各自事件被观测之前都保持未知。刷新失败后它们保持未知，而不是永远打印零。 |
| 设计未观测 | 空的设计一致性矩阵说明此快照未观测到设计对象、空矩阵不代表一切正常，而不是把空归因于当前筛选。 |
| 零分母速率 | Fail-fast 前沿与成本模型回放不再在零样本或零基线上打印 `0.0%`。分子与分母保持可见，速率显示"未测量"。 |
| 失败位置 | 验证报告说明检查行未保留结构化失败位置，也不会推断行号，避免操作员期待数据无法支持的跳转。 |
| 调查标签 | 身份栏携带操作员命名的调查标签，关闭抽屉也能看到分享链接里的标签。 |
| 视图切换 | 切换主视图会恢复操作者离开的位置；隐藏面板会夹紧文档滚动，过去会因此丢失位置。 |
| Reconciliation 修剪 | 修剪保留每个计划的最新快照。淘汰一个计划的全部快照会让下一次更新以全部任务 Pending 重建它，静默丢弃已认领、已完成与已失败状态。 |
| 独立源码门禁 | OSS 源码包门禁在被杀毒软件扫描的 Windows 文件系统上给 git 基线阶段留出余量；该阶段曾两次失败，而相邻阶段一直很快。 |

新增的载荷字段都是附加的：较旧的客户端会忽略它们，现有调用的结构没有变化。

## 升级与重连

使用带版本的[发布下载](https://github.com/francis-du/wcode/releases/tag/v0.9.11)以及对应的 SHA256SUMS 做固定版本升级。现有 `wcode update` 命令会选择最新的稳定版本，它没有 `--version` 选项。

替换安装文件之后，请重新连接 MCP Host，或在检查完正在进行的任务后安排服务重启。源码发布不会替换已在运行的进程。请检查新启动可执行文件的版本及其配置路径。

## 验证身份

发布工作流会记录确切提交，运行三平台测试与独立源码包检查、依赖审计、Design/traceability 检查、真实 WebKit 矩阵以及全部 300 个不同的对抗轮次。发布阶段还会构建各平台归档并校验全新下载。GitHub Release 链接指向实际完成的运行；较早的绿色候选不能证明较新的提交。

WTeam 部署、数据库迁移、身份配置与已安装服务的升级有各自的验收步骤。

## 命令发现与有界执行

使用 `wcode help-all`、`wcode help-all setup` 和 `wcode help-all --json` 在不启动运行时的情况下检查命令目录。使用 `agent_context` 开始编码；`balanced`、`fast` 和 `light` 预设保留各自的执行与授权边界。被动检查使用 `--read-only --no-exec --no-semantic`。

默认情况下，命令策略与授权是宽松的。`--no-exec` 覆盖会话命令授权，显式加固标志记录在安全参考中，而不是由默认值暗示。

对于中断或不完整的检查，请保留 `timed_out`、`output_incomplete` 与原始任务 ID。在请求另一次执行之前，先读取它的结果。维护者门禁包括 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 与当前在线审计。JavaScript 回归使用 Node 24。
