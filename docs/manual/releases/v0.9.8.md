# wcode v0.9.8

This version closes the gap between the design consistency matrix and the data behind it, and removes a series of stale control states that survived view and workspace switches.

| Change | User-visible behavior |
| --- | --- |
| Design consistency is fed | The project snapshot now carries the declared acceptance criteria and constraints, the reconciliation plans that claim drift, the live execution state of the plan answering a finding, the review truncation flag, the running build version, and the per-check acceptance rows. Before this, the browser fixtures supplied those fields by hand, so the acceptance and constraint rows were dead in a real session: every affected requirement read as having no convergence plan, every constraint read as undeclared, and the navigator never reported a partial review. |
| Acceptance drilldown | Each check that a current verification plan requires, or that a declared acceptance criterion names, is one row with the criteria that declare it, its mapped/executed/outcome/freshness state, the evidence it came from, the code and design revision it applies to, and the policy it ran under. A check with no observation stays `unknown`/`missing` instead of disappearing, so an unexecuted item is visible next to a failed one, and a criterion-declared check that no plan requires is still observable between plans. A declared criterion that no check references remains its own row marked as a missing acceptance item. |
| Honest per-check timing | A verification report separates each check's queue wait from its execution time. The bounded web projection dropped both fields while the report renderer kept printing them, so every check read as "queued 0 ms · ran 0 ms". Absent timings now read as unknown rather than a fabricated zero. |
| Home status entries | The home observation surfaces gain a work queue entry with open and blocked counts beside the runtime state, session status, the approved policy's scope and expiry, and an explicit authorization-requested state. An unavailable execution state is told apart from an absent checkpoint. |
| Coverage keeps its numerator and denominator | Dependency coverage, change-convergence coverage and the context budget each report their own counts, so a percentage can no longer be read without the values it came from. Runtime drift percentages stay beside their own observed, expected and unit. |
| Control state follows the workspace | The requirement filter buttons stay in step with the filter the list actually uses, the system map zoom readout and its fit/full controls reset with the workspace, and the code graph's fullscreen state and inspector no longer follow the operator into the next workspace. |
| Job scope isolation | A drawer job selection is dropped with the job scope, and one job's retained output can no longer appear under another job's header. The retained-output query is cleared when the observed task changes. |
| Change reads are guarded | The change list, acceptance summary and requirement renderers no longer assume every project field is present, so a partial or cached snapshot degrades to an explicit empty state instead of throwing. |
| Session investigation record | The drawer records the session's own investigation path — view switches and object selections, deduplicated, capped at 100 entries with the cap stated. Durations under a minute read in seconds. The record is explicitly session-only, not a persistent baseline. |
| Dependency coverage reporting | The consistency view states dependency coverage with its own counts, keeping confirmed drift edges apart from the observed edge total and never presenting an unobserved declared dependency as missing implementation. |
| Localized monitor and constraint states | The remaining constraint observation states and monitor labels render in Simplified Chinese, so a Chinese session no longer mixes languages. Every copy key the bundle looks up now has Simplified Chinese coverage. |
| Agent skill alignment | The bundled agent skill names the parallelism strategy the readiness pack actually emits (`parallel_required`/`single_lane`) instead of a value that exists nowhere in the code. |

The added payload fields are additive: an older client ignores them, and no existing call changes shape.

## Upgrade and reconnect

Use the versioned [release downloads](https://github.com/francis-du/wcode/releases/tag/v0.9.8) and the matching SHA256SUMS for a pinned upgrade. The existing `wcode update` command selects the latest stable release; it has no `--version` option.

After replacing an installation, reconnect the MCP Host or arrange a service restart after inspecting active work. A source release does not replace an already running process. Check the newly started executable's version and its configured path.

## Verification identity

The release workflow records the exact commit, runs three-platform tests and standalone source-package checks, dependency audit, Design/traceability checks, the real WebKit matrix and all 300 distinct adversarial rounds. Publication additionally builds platform archives and verifies fresh downloads. The GitHub release links identify the actual completed runs; older green candidates do not validate a newer commit.

WTeam deployment, database migration, identity configuration and installed-service upgrades have their own acceptance steps.

## Command discovery and bounded execution

Use `wcode help-all`, `wcode help-all setup` and `wcode help-all --json` to inspect the command catalog without starting the runtime. Start coding with `agent_context`; the `balanced`, `fast` and `light` presets retain their execution and authorization boundaries. Passive inspection uses `--read-only --no-exec --no-semantic`.

Command policy and authorization are permissive by default. `--no-exec` overrides session command grants, and the explicit hardening flags are documented in the security reference rather than implied by the default.

For an interrupted or incomplete check, retain `timed_out`, `output_incomplete` and the original task ID. Read its result before requesting another execution. Maintainer gates include `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings` and the current online audit. JavaScript regressions use Node 24.
