# v0.7.0 — 架构优先观测与更快的工程控制面

本页对应 0.7.0 发布准备。同步源码版本和完成本地构建不等于已经发布 GitHub Release；打 Tag、跨平台 CI、包签名、安装器冒烟与正式发布仍是独立且由操作者控制的门禁。

## Engineering Observatory 围绕系统重新构建

受保护的 Engineering Observatory 不再是一条无限向下铺开的 Dashboard，而是真正的 Workspace。顶部只保留一条 Global Bar，统一承载项目搜索、Workspace、Live、Refresh、语言、主题、Semantic Refresh 与 Access。Overview、Engineering architecture、Task activity、Verification evidence、Current changes、Requirements、Project files 七个一级 Tab 分开主工作区。

Architecture 成为系统主视图。默认 System Map 按语义层自上而下阅读，依赖细节进入 Inspector 与 Ledger，不再把所有边同时画成毛线团。Subsystem Card 展示有界的所有权、状态与规模信息；选中后在 Inspector 查看上游／下游、Evidence 与 Coverage。Component 与精确 Dependency Evidence 保留为下钻视图。Fit 与 Full Map 是真实 Viewport 行为，不再只是视觉缩放按钮。

Verification 改为 Ledger + Inspector，把当前证据、历史结果与诊断分开。Requirements 提供 requirement → component → code → verification → evidence 追踪。Current Changes 把影响分析与收敛结果和原始 Diff 行分离。Activity、Files、Diagnostics 与 Language Quality 统一到同一套可读层级与键盘／焦点契约。

## 更快的项目状态加载

Observatory 首次打开不再先等待 Revision 请求完成后才开始 Project Snapshot；Revision 与 Project Observation 现在并发发起，Activity 继续独立轮询。Harness 内部可独立的 Observatory 工作也拆成并行阶段，不再所有仓库分析都前一个结束后才启动下一个。

这不会削弱新鲜度规则：迟到响应仍绑定选择代次，后续 Revision Poll 发现需要刷新时仍会使完整 Project Snapshot 失效。不宣称没有实测依据的通用提速百分比；重型仓库工作仍受现有 Workspace 与 Harness 资源上限约束。

## Agent Context、有界执行与诊断

`agent_context` 继续作为默认编码入口。紧预算下优先保留精确目标、Design State、代码关系、测试、Revision、SHA 编辑前置条件与 Verification 引用；模糊跨模块任务仍可在固定上限内扩展。多个意图混合时回退到 balanced 路由，不伪造高置信度。

Host 支持时，独立工作应使用并发顶层调用；已知目标继续优先使用 `read_files`、`search_many`、`apply_file_edits`、`create_files` 等低噪声批量接口。`parallel_tools` 仍保持依赖感知调度，而不是无约束地把所有事情一起跑。

命令超时仍保留已采集输出并返回 `timed_out` 与 `output_incomplete`。取消不等于回滚，也不会自动重放修改。人工批准仍绑定精确操作范围。

## 配置与兼容性

`balanced`、`fast`、`light` 三档继续覆盖常见资源配置，高级覆盖参数保持可用。可先预览 Setup 而不写文件：

```bash
wcode setup --performance fast --dry-run
wcode --show-config
```

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 查看由真实 Parser 定义的完整 CLI Surface，不执行所查询命令。

文件只读不等于命令无副作用；仅查看组合仍为：

```text
--read-only --no-exec --no-semantic
```

Workspace 隔离、OAuth 状态边界、精确授权、持久 Evidence 与 Design State 格式保持兼容。更新后应重启或重新连接 MCP Host，使其启动新二进制并重新加载 Schema。

## 发布打包与 CI

Cargo、Cargo.lock 与六份 Marketplace／Plugin Manifest 统一为 0.7.0。Quality Job 还会依据 RustSec Advisory DB 审计 Cargo.lock，仓库通过 `.cargo/audit.toml` 明确声明该安全门禁；已知漏洞会阻断发布，但不会自动创建 Issue。测试矩阵显式安装 Node 24，执行 Observatory JavaScript 回归。Linux、macOS、Windows Artifact 只有在 Quality 与 Test Job 通过后才构建；分发二进制在打包前执行 `--version` 与 `--help` 冒烟。macOS 分发二进制在 Post-link 修改后重新签名；安装器先暂存并冒烟再替换；发布压缩包生成 SHA-256 校验和。

创建 `v0.7.0` 标签前，执行锁定依赖的完整仓库门禁：

```text
git diff --check
cargo check --locked
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo build --release --locked
```

同时校验 Design State、Traceability、Product Scope 与当前变更审查。当前 Revision Evidence 必须与命令成功输出分开核对。本地 Full Gate 通过不能替代真正的 Linux/macOS/Windows 发布工作流结果；已经发布的 Tag 不得移动。
