# v0.7.2 — 更清晰的可观测、更高效的模型工具与更精确的验证

v0.7.2 是一次面向日常真实使用面的优化版本：同时改进 Observatory、TUI、Setup 与 OAuth UX；让 Agent Context 的检索效率真正可见；为支持 Tool Search 的 Host 提供紧凑、Model-neutral 的核心 Preload Hint；并消除 Verification Mesh 中无意义的语言 Cross-product，而不降低确定性检查或安全审查强度。

Release Candidate 先 Commit 并 Push。只有该精确 Commit 的普通 CI 全绿后，才创建 `v0.7.2` Tag。

## Observatory 与 TUI 展示真正重要的状态

Engineering Observatory 的 Refresh State 现在成为正常可见的 Operator Signal，不再只存在于 Accessibility 文本。Activity 会展示真实 Agent Context 检索遥测：候选与最终交付 Context、Cache 行为、避免传入的 Context 与构建耗时。这样可以区分“没有找到有用上下文”和“探索了太多无用上下文”，同时不存储 Prompt 或 Chain of Thought。

TUI 同步展示检索效率，并把内部 Process Pressure 说清楚。Queue Wait Peak 与 Tool Slot Occupancy 分开，因此 `SLOTS`、Child Process、Git Inspection Capacity 与 Queue Delay 不会再混成一个模糊的性能数字。

视觉层级继续保持克制：Navigation／Control Surface 使用更明显的透明材质；项目状态、Proof 与 Architecture 作为稳定内容层承载信息，而不是把整个页面堆成 Glass Card Wall。

## Setup 区分 Endpoint Health 与真实 MCP Activity

Setup 现在明确分开两件事：

- 公网 Endpoint 当前是否健康；
- wcode 最近是否真的收到 MCP 流量。

最近 MCP Activity 只是解释性可观测信号。Connector 暂时空闲不会把健康 Tunnel 判坏，也不能触发 Endpoint Failover 或 Host Trust Revoke。遇到 VPN／Tailscale 抖动时尤其有用：Transport 绿灯不再暗示 Client 一定在调用 MCP，而暂时没有调用也不会被误判成 Tunnel 故障。

OAuth 页面新增真正的 Light Color Scheme，同时保留移动端 Viewport、Safe Area、Zoom 与 HTML Escape 边界。

## Agent Context 与模型／Host 效率

2026 年追加调研再次验证一条简单原则：Context 更大不等于 Context 更好。Agent Retrieval Bench、ContextBench 与 CORE-Bench 都提示应把仓库检索本身作为独立问题衡量，包括 Precision、预算内 Context Yield，以及“探索过”与“真正使用”的 Context 差距。

因此 wcode 继续让 `agent_context` 自适应并按任务路由，而不是简单提高默认 Budget。Runtime 现在直接暴露 candidate→delivery、Cache 与 Build Latency 遥测，便于实际衡量 Retrieval Quality。

MCP Catalog 仅给一小组核心工具增加 `dev.wcode/preloadRecommended=true`：`agent_context`、`search_many`、`read_files`、`apply_file_edits`、`review_changes`、`verify_project`。支持 Tool Search 的 Host 可以常驻这组核心工具，其他专业工具按需发现；忽略 Hint 的 Host 获得完全相同的确定性完整目录与行为。

这条优化以能力而不是厂商为中心。Codex／OpenAI 风格的 Prompt Cache 受益于稳定 Tool Order 与 Definition；Claude 风格的 Deferred Tool Discovery 受益于小型 Preload Set；Gemini 风格的 Implicit Cache 受益于稳定 Prefix。wcode 不会根据模型品牌切换仓库语义、授权或 Verification 真值。

原始资料与实现边界见[论文驱动的改进](../../research-upgrades/)。

## Verification Mesh 对准真实风险，而不是文件扩展名噪声

High／Critical Verification Plan 仍保留完整 Deterministic Profile、Security／Adversarial Review 和要求的 Advanced Stage。变化只发生在 Advanced Stage Evidence 的 Target Set。

当确定性文件审查已经定位到带风险归因的 Changed Source 时，High／Critical Plan 优先使用这些风险源码的语言，不再把 Property／Mutation／Fuzz 机械乘到所有无关 UI 语言上。CSS／HTML 展示源码除非被显式配置的 Executor 选择，否则不会生成语言级 Advanced Stage Target。若没有适用的行为语言 Target，Stage 仍作为 Global Fail-closed Blocker，而不是回退到仓库里无关的已检测语言。

这会减少假 Gap，但绝不制造假 Evidence。普通 `cargo test` 不会被重新命名为 Mutation 或 Fuzz；真实 Executor 不存在时继续明确暴露缺口。在当前 Release 开发机上，`cargo-mutants` 与 `cargo-fuzz` 未安装，因此对应 Rust Advanced Stage 仍是显式 Verification Mesh Gap，而不是假装通过。

Reconciliation Plan 现在复用与直接 Verification Plan 相同的 Risk-relevant Target Selection，堵住此前会重新扩成全仓库语言的旁路。

## 安全仓库检查进一步减少无意义授权

有界 `git grep` 现在进入已有的 Read-only Git Policy，不再制造无意义的授权请求。可能逃离范围的 Helper、危险配置重定向和 Mutation Form 仍然阻断。

原则保持不变：常用、有界的 Inspection 与 Verification 应当自治；扩大 Authority 或具有破坏性的操作继续保留显式 Trust Boundary。

## Diagnostics、资源预设与 CLI 兼容

命令超时／取消结果继续保留明确的 `timed_out` 与 `output_incomplete` 字段。Timeout 不代表回滚，wcode 仍不会自动 Replay 一个可能已经产生副作用的操作。

现有 `balanced`、`fast`、`light` 资源预设保持兼容；它们调整的是有界 Runtime Capacity，不改变授权策略。仅查看的 Hardened 组合仍然是：

```text
--read-only --no-exec --no-semantic
```

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 查看真实 Parser 定义的完整命令和参数面，不执行被查询命令。Release CI 继续显式安装 **Node 24** 运行 JavaScript Observatory 行为测试。

## 验证与发布门禁

Release Candidate 必须通过完整锁定依赖本地门禁：

```text
git diff --check
cargo check --locked
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo build --release --locked
```

同一轮准备还会检查 Design State、Product Scope、Repository Convention，以及 Release／Documentation Contract。Tool Catalog 也必须继续满足原来的紧凑体积上限；第一版 Model Hint 曾触发该门禁，因此最终选择压缩 Hint，而不是抬高限制。

v0.7.2 Commit Push 到 `main` 后，等待该精确 SHA 的 Build & Release 与 Documentation CI 全绿。只有 main Gate 通过后才创建 `v0.7.2`；Tag 再触发跨平台 Packaging 与正式 Publication Gate。
