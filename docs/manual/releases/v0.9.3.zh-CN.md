# wcode v0.9.3

本版把「列出了变更」推进到「看得懂变更」，加快支撑 Observatory 的有界图谱查询，并把信任模型从隐式改为显式。

| 变更 | 用户可见行为 |
| --- | --- |
| 代码阅读器符号大纲 | 阅读器列出有界图谱为该文件观测到的定义（含类型与行范围），可跳转到某个定义，标记捕获变更与其行重叠的符号，并把显式设计映射点名该符号的需求做成 chip。 |
| 变更定义的需求 chip | 变更检查器为每个变更定义标注它服务的需求，读 diff 不必离开检查器。 |
| 直接跳转行号 | 阅读器工具栏的行号输入可跳转到任意一行，并按版本绑定的源码分页。 |
| 诚实的变更状态 | 工作树检查不可用时，所有由变更派生的计数与 pill 现在显示「未知」，而不是渲染成 0 或「干净」。 |
| 图谱查询效率 | 有界链路查询只建立一次邻接索引，不再对每个访问到的节点扫描完整边表；成本模型的前沿排序只计算一次后续阶段成本，而不是每个候选各算一次。 |
| 显式信任边界 | 命令策略与授权默认宽松，硬化开关在文档中写明；`--no-exec` 覆盖会话命令授权；工作区根从 agent 会话继承；沙盒按次选择启用。 |
| 有界证据回执 | 捕获的 CI check-run 回执在本地保留，带仓库绑定与摘要校验；外部已验证的阶段执行器可作为只观察证据被接纳。 |
| Intelligence 响应头 | 每个 `/intelligence` 响应都带 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff` 与 `Referrer-Policy: no-referrer`。 |
| 跨平台可靠性 | Windows 运行时与 CLI 在显式大栈上解析，Windows 瞬时替换失败会重试，探针容量产物按有界预算重试而不是随机失败。 |

符号大纲与变更定义 chip 只报告有界图谱与显式设计映射实际包含的内容。空大纲是观测缺口，绝不表示该文件没有定义；变更标记只是行重叠，不是语义影响；没有显式 `path::symbol` 映射的符号不显示需求 chip，而不是猜测归属。

## 升级与重连

使用带版本的[发布下载](https://github.com/francis-du/wcode/releases/tag/v0.9.3)与对应 SHA256SUMS 做固定版本升级。现有 `wcode update` 命令会选取最新稳定版，没有 `--version` 选项。

替换安装后，请在检查完进行中的工作之后重连 MCP Host 或安排服务重启。源码发布不会替换已在运行的进程。请检查新启动可执行文件的版本与其配置路径。

## 验证身份

发布工作流记录确切提交，运行三平台测试与独立源码包检查、依赖审计、Design/可追溯性检查、真实 WebKit 矩阵以及全部 300 个不同对抗轮次。发布另外构建平台归档并校验全新下载。GitHub release 链接指向真实完成的运行；较早的绿色候选不能验证较新的提交。

WTeam 部署、数据库迁移、身份配置与已安装服务的升级有各自的验收步骤。

## 命令发现与有界执行

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 在不启动运行时的情况下检查命令目录。使用 `agent_context` 开始编码；`balanced`、`fast` 与 `light` 预设保留其执行与授权边界。被动检查使用 `--read-only --no-exec --no-semantic`。

命令策略与授权默认宽松。`--no-exec` 覆盖会话命令授权，显式硬化开关在安全参考中说明，而不是由默认值暗示。

对于被打断或不完整的检查，请保留 `timed_out`、`output_incomplete` 与原始任务 ID，并在请求另一次执行之前先读取其结果。维护者门禁包括 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 与当前的在线审计。JavaScript 回归使用 Node 24。
