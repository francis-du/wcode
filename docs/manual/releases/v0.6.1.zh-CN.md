# v0.6.1 — 更快的并行执行与聚焦工具调用

本页随 0.6.1 发布准备提供。版本化源码与本地验证不等于正式发布；打标签和发布仍是独立的操作者动作。

## 并行执行

`parallel_tools` 从整层等待改为完成驱动调度。后续任务在自身前置任务完成后即可启动，不必等待同层无关的慢分支。结果仍按输入顺序返回，现有全局 Semaphore 和响应大小限制保持不变。

失败依赖会跳过后续分支，独立分支继续执行。取消父任务会取消排队子任务，避免待执行写操作脱离父任务继续；已经运行的阻塞文件操作不会回滚。父 Workspace 与发现的子空间路径按实际根目录比较，避免别名掩盖资源冲突。

同文件、同 SHA 的编辑不能跨过中间的依赖读取或移动操作合并。合并事务会在执行前检查现有的 128 项编辑上限。

批量读取、创建、编辑和移动明确报告 complete/partial/failed，并保留逐项结果。部分失败会设置 MCP 错误标记，保守阻止依赖该批次的后续任务；独立分支继续执行。重试前核对状态，只重试失败项，不要重放整个批次。取消异步调用不再提前释放已启动阻塞工作的并发许可：真实工作持有许可直到结束或异常退出，所属 JoinSet 会取消仍在排队的阻塞工作。

任务定义不合法或无法建立完整资源模型时，在任何子任务启动前拒绝整个并行批次。这与有效依赖图中的运行时失败不同：后者仍允许独立分支继续执行。

取消持久 MCP Task，或轮询检测到 TTL 过期时，现在会取消其拥有的工具执行任务，而不只是外层等待。取消普通隔离请求也会传递到排队中的单文件和并行批量写入。已受理的持久 Task 仍独立于创建请求继续运行；异常隔离、所有者校验，以及已启动阻塞工作不承诺回滚的边界保持不变。

任务快照先校验大小，再创建目录或清理历史；完整写入临时文件、同步后再原子发布。重复保存只认可内容一致的普通快照文件，不认可损坏内容或符号链接。UTF-8 失败消息在状态和错误字段使用相同字节上限。工具结果无法持久化时尝试保存有界失败记录；轮询发现执行器缺失或已结束，会报告失败而不是无限保持运行中。创建记录与注册执行器属于同一次状态转换。确认所有者后，即使终态写盘失败，取消及已检测到的过期仍会中止执行器；存储错误明确返回，重试前需要核对实际副作用。嵌套 Workspace 的任务定位、所有者校验和重启持久性已加入回归测试。

## 上下文与工具使用

工具 arguments 必须是对象。显式 Workspace 选择值先校验类型，不会静默退回默认工作区；并行编辑合并前也会检查。命令参数数组保留每个字符串及其位置，包括空字符串；数组、cwd 或超时值类型不合法时，在执行或请求授权前拒绝。省略可选字段仍使用原默认值。

分词扩展前保留完整符号名和限定名；先合并所有请求源码范围内的有界候选，再排序和截断。精确定义优先于相似名称的辅助函数进入目标和热源码，缓存命中时也保留这一顺序。

直接目标文件优先于按字母顺序靠前的 Design 映射，确保有界上下文包保留相关 SHA 编辑前置条件。并行建议考虑发现阶段的 Scope 和活动 Worklist Lane，并遵守运行时并发上限，不再固定最多推荐四路。Lane 数仍是建议，不是独立性证明。按 Scope 发现源码时，小型仓库缺少可选源码路径不再导致整个请求失败；工作区身份、权限和符号链接错误仍然严格拒绝。

上下文收尾减少重复的预裁剪轮次，并在后续大小计算中保留截断标记。核心工具描述完整落在紧凑描述上限内，不会切掉关键使用指引。Skill 和工作流 Prompt 优先要求一次发现、复用已有源码、已知输入批量读搜，以及 Host 支持时的顶层并发调用。`project_context` 不是第二个必需启动调用。

## 终端与可观测性

移除重复的 OVERVIEW 面板。较矮终端优先展示任务活动，仅在有用且空间充足时显示吞吐量，多隧道保持逐行可见。修复 Unicode 截断、帮助和页脚点击区域、弹窗点击穿透、工作区焦点以及命令列表缩放偏移。

授权决策绑定实际渲染过的请求 ID；其他弹窗遮住请求时，不允许批准隐藏请求。状态消息不再覆盖批准控件。终端初始化失败会恢复终端状态，吞吐曲线使用标示的 30 秒窗口，并避免极大计数导致溢出。

Project Observatory 区分验证映射、已执行、已通过和新鲜证明，不再把映射覆盖率当作测试通过结果。

MCP GET/POST、旧版 SSE 与受保护 WebUI 统一按当前有效入口登记表校验 Origin。有效的非主入口别名可以通过，失效来源仍被拒绝，也不会跳过身份验证。隧道 URL 先登记再公开，消除启动或重连期间短暂的 Host 误拒窗口。重复或畸形 Host/Origin 请求头保持失败关闭；403 响应用 `untrusted_host` 与 `untrusted_origin` 区分原因，不泄露凭据。

Full Access 在注册表锁内准备完整变更，只有容量和各根目录验证成功后才统一提交；失败时原权限与标志保持不变。既有命令批准、撤销记录和逐文件写锁继续共享；重复提升保持幂等，并发添加 Workspace 使用已提交的权限策略，不绕过授权边界。

## 验证与发布

命令和验证 Tool Result 保留完整报告，但执行失败或未发现检查项时会设置 MCP 错误标记。代码或 Design State 的版本扫描不完整时，即使部分摘要一致，也不能生成整个工作区的验证证据。

项目验证和语言质量检查在执行前记录代码及 Design State 版本，写入任何报告证据前重新核对。版本发生变化时拒绝过期结果，避免把旧测试归到新代码。这个保护不是隔离快照，无法识别最终核对前已经还原的中途改动；发布验证仍需保持工作树稳定。

回归覆盖包括就绪后续任务调度、父子空间资源别名、失败依赖传播、排队子任务取消、安全合并上限、目标 SHA 保留、并发建议上限以及完整紧凑工具描述。终端和中英文文档契约仍属于全量测试。

正式发布前运行完整仓库门禁（`git diff --check`、`cargo check --locked`、`cargo fmt --check`、`cargo test --locked`、`cargo clippy --locked -- -D warnings`、`cargo build --release --locked`），并校验 Design State。Cargo 和全部打包插件清单统一为 0.6.1，依赖版本不变。跨平台签名、打包和安装器冒烟仍由发布工作流负责。不宣称通用提速百分比：收益取决于依赖图、工作负载和 Host 的并发支持。

0.6.1 正式发布后可用 `wcode update` 升级。当前安装与设置说明见[快速开始](../../getting-started/)。
