# wcode v0.9.7

本版让重详情响应默认保持有界，并让变更导航落在它所指的对象上，而不是一个没有聚焦的区域。

| 变更 | 用户可见行为 |
| --- | --- |
| 有界的详情响应 | `evidence_status`、`project_context`、`software_context`、`traceability_status`、`risk_status` 与 `worklist_status` 现在默认使用 `detail=summary`。每个响应保留 agent 据此行动的 identity、计数与来源信息，并逐项声明省略；`detail=full` 一跳取回完整投影。在本仓库实测，这六个默认响应从约 278 万降到约 68 万代码单元。 |
| 可执行的工作清单 | `worklist_status` 默认只返回未完成任务，而不是整段完成历史。本仓库 64 项中有 59 项已完成；目标、版本、计数、可运行通道与协作元数据不变，省略会被明确声明。 |
| 精确的变更导航 | 收敛图卡片与 attention 信号现在会选中并聚焦它们所指的对象。漂移信号通过显式设计映射把受影响需求解析到所属组件，而不是只展开一个没有聚焦的架构区域。 |
| 可编辑就绪范围 | 当只有部分已声明目标具备可用源码时，`readiness.edit_scope` 会限定 `ready` 的含义，使多目标任务不会在存在 `target_source_coverage_incomplete` 时仍显示为完全就绪。该限定仅在范围不完整时输出，完全覆盖的任务不付出额外成本。 |
| 图谱文件上界 | `software_graph` 的 `max_files` 现在只计算可索引的源文件，而不是所有被遍历的路径。低于 dotfile 数量的上界不再返回一个没有源码、只有 design overlay 的图谱；composite 快照会分别报告源码与 overlay 的节点和边数量。 |
| 日志溢出恢复 | 已经超出保留环的工程日志会拒绝之后的每一次追加，导致 `evidence_journal_export` 与 `change_fingerprint` 失败、目录持续膨胀。现在超大的日志会被裁剪回 512 条里程碑的保留环，读取方报告保留窗口与真实总量，只有超过病理性目录上界的扫描才失败关闭。 |

`detail` 参数是新增的：省略它的既有调用方得到有界响应，`detail=full` 保留此前的完整载荷。未知取值会以失败关闭处理。

## 升级与重连

使用带版本的[发布下载](https://github.com/francis-du/wcode/releases/tag/v0.9.7)以及对应的 SHA256SUMS 做固定版本升级。现有 `wcode update` 命令会选择最新的稳定版本，它没有 `--version` 选项。

替换安装文件之后，请重新连接 MCP Host，或在检查完正在进行的任务后安排服务重启。源码发布不会替换已在运行的进程。请检查新启动可执行文件的版本及其配置路径。

## 验证身份

发布工作流会记录确切提交，运行三平台测试与独立源码包检查、依赖审计、Design/traceability 检查、真实 WebKit 矩阵以及全部 300 个不同的对抗轮次。发布阶段还会构建各平台归档并校验全新下载。GitHub Release 链接指向实际完成的运行；较早的绿色候选不能证明较新的提交。

WTeam 部署、数据库迁移、身份配置与已安装服务的升级有各自的验收步骤。

## 命令发现与有界执行

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 可以在不启动运行时的情况下检查命令目录。编码工作从 `agent_context` 开始；`balanced`、`fast` 与 `light` 预设保持各自的执行与授权边界。被动检查使用 `--read-only --no-exec --no-semantic`。

命令策略与授权默认是宽松的。`--no-exec` 会覆盖会话级命令授权，显式加固标志记录在安全参考中，而不是由默认值暗示。

对于中断或不完整的检查，请保留 `timed_out`、`output_incomplete` 与原始任务 ID。在请求再次执行之前，先读取它的结果。维护者门禁包括 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 与当前的在线审计。JavaScript 回归使用 Node 24。
