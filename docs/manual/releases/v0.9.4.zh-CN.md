# wcode v0.9.4

本版降低支撑模型的图谱查询成本，并修正已验证经验（verified experience）的衰减，让近因性继续正确地影响证据排序。

| 变更 | 用户可见行为 |
| --- | --- |
| 有界链路查询 | 有界链路查询只建立一次 incident 边索引，不再对每个访问到的节点扫描完整边表：k 个节点的组件代价为 O(k + incident 边数)，而不是 O(k * 总边数)。去重与结构根规则不变。 |
| 图谱上下文搜索 | 组装模型上下文的 reconciliation 路径不再为每个图谱节点或每个候选分配小写副本，MCP `graph_query` 的 label 过滤改为原地比较。评分、排序与过滤结果不变。 |
| 前沿排序成本 | 成本模型每次排序只计算一次后续阶段成本，而不是每个 phase-0 候选各算一次。选中的前沿与节省量不变。 |
| 已验证经验衰减 | 共变权重现在惰性衰减：推进时间只需一次乘法，而不是遍历全部已存储权重，只有在因子小到无法表示时才重归一化。置信度按真实衰减后的权重度量，新学习到的权重按当前因子预缩放存储，后续衰减不会将其放大。 |
| 发布说明修正 | v0.9.3 页面不再声称其 tag 无法到达的图谱工作；恢复后的改动在本版落地。 |

衰减修正影响的是排序质量，而不只是速度。置信度收缩把配对权重与固定先验比较，因此直接读预缩放的存储值会让置信度不再随时间衰减，使陈旧证据保持与新鲜证据相同的分数。关联度是比值，缩放因子相互抵消，保持不变。

## 升级与重连

使用带版本的[发布下载](https://github.com/francis-du/wcode/releases/tag/v0.9.4)与对应 SHA256SUMS 做固定版本升级。现有 `wcode update` 命令会选取最新稳定版，没有 `--version` 选项。

替换安装后，请在检查完进行中的工作之后重连 MCP Host 或安排服务重启。源码发布不会替换已在运行的进程。请检查新启动可执行文件的版本与其配置路径。

## 验证身份

发布工作流记录确切提交，运行三平台测试与独立源码包检查、依赖审计、Design/可追溯性检查、真实 WebKit 矩阵以及全部 300 个不同对抗轮次。发布另外构建平台归档并校验全新下载。GitHub release 链接指向真实完成的运行；较早的绿色候选不能验证较新的提交。

WTeam 部署、数据库迁移、身份配置与已安装服务的升级有各自的验收步骤。

## 命令发现与有界执行

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 在不启动运行时的情况下检查命令目录。使用 `agent_context` 开始编码；`balanced`、`fast` 与 `light` 预设保留其执行与授权边界。被动检查使用 `--read-only --no-exec --no-semantic`。

命令策略与授权默认宽松。`--no-exec` 覆盖会话命令授权，显式硬化开关在安全参考中说明，而不是由默认值暗示。

对于被打断或不完整的检查，请保留 `timed_out`、`output_incomplete` 与原始任务 ID，并在请求另一次执行之前先读取其结果。维护者门禁包括 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 与当前的在线审计。JavaScript 回归使用 Node 24。
