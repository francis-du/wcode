# wcode v0.9.8

本版补上设计一致性矩阵与它背后数据之间的缺口，并清除一系列在视图切换和工作区切换后残留的陈旧控件状态。

| 变更 | 用户可见行为 |
| --- | --- |
| 设计一致性有了数据来源 | 项目快照现在携带已声明的验收标准与约束、认领偏离的收敛计划、回应某条偏离的计划的实时执行状态、review 截断标记、运行中的构建版本，以及逐检查的验收行。在此之前，浏览器测试的 fixture 是手工塞进这些字段的，因此真实会话中的验收行与约束行其实是死代码：每条受影响需求都读成"没有收敛计划引用此偏离"，每个约束都读成"未声明"，导航范围也永远不会报告 review 不完整。 |
| 验收下钻 | 当前验证计划要求的检查，或已声明验收标准点名的检查，各自独占一行，显示声明它的验收标准、mapped/executed/outcome/freshness 状态、结论来自哪条证据、适用于哪个代码与设计版本，以及在哪条策略下产生。没有观测值的检查保持 `unknown`/`missing` 而不是消失，因此未执行的项会和失败的项并列可见；在两次计划之间，仅被验收标准声明、尚无计划要求的检查同样可见。没有任何检查引用的已声明标准，仍然作为"缺少验收项"单独成行。 |
| 诚实的逐检查耗时 | 验证报告把每个检查的排队等待与执行耗时分开。有界的 Web 投影丢掉了这两个字段，而报告渲染器一直在打印它们，于是每个检查都显示成"排队 0 ms · 执行 0 ms"。现在缺失的耗时显示为未知，而不是伪造的零。 |
| 首页状态入口 | 首页观测面新增工作队列入口，在运行时状态旁边给出未完成与阻塞计数，并提供会话状态、已批准策略的作用范围与过期时间，以及显式的"已请求授权"状态。执行状态不可用与检查点缺失不再混为一谈。 |
| 覆盖率先给出分子与分母 | 依赖覆盖、变更收敛覆盖与上下文预算各自报告自己的计数，因此百分比再也不能脱离它来源的数值被阅读。运行偏离百分比始终与其自身的观测值、期望值与单位并列。 |
| 控件状态跟随工作区 | 需求筛选按钮与列表实际使用的筛选保持一致；系统地图的缩放读数与适配/全图控件随工作区重置；代码图谱的全屏状态与检查器不再跟着操作者进入下一个工作区。 |
| 任务范围隔离 | 抽屉的任务选择随任务范围一起清除，某个任务保留的输出不会再出现在另一个任务的标题下。观测的任务变化时，保留输出的查询条件会被清空。 |
| 变更读取加了保护 | 变更列表、验收摘要与需求渲染器不再假设 project 的每个字段都存在，因此部分或缓存的快照会退化为显式的空状态，而不是抛错。 |
| 会话调查记录 | 抽屉记录本次会话自己的调查路径——视图切换与对象选择，去重后上限 100 条，并明确标注截断。不足一分钟的时长以秒显示。该记录明确只属于本次会话，不是持久基线。 |
| 依赖覆盖上报 | 一致性视图用自身的计数说明依赖覆盖，把已确认的偏离边与已观测边总数分开，绝不把未观测到的已声明依赖呈现为缺少实现。 |
| 中文化 | 剩余的约束观测状态与监视器标签现在以简体中文渲染，中文会话不再混杂语言。bundle 查找的每个文案键都已有简体中文覆盖。 |
| Agent skill 对齐 | 内置 agent skill 命名为 readiness pack 实际发出的并行策略（`parallel_required`/`single_lane`），而不是代码中根本不存在的值。 |

新增的载荷字段都是附加的：较旧的客户端会忽略它们，现有调用的结构没有变化。

## 升级与重连

使用带版本的[发布下载](https://github.com/francis-du/wcode/releases/tag/v0.9.8)以及对应的 SHA256SUMS 做固定版本升级。现有 `wcode update` 命令会选择最新的稳定版本，它没有 `--version` 选项。

替换安装文件之后，请重新连接 MCP Host，或在检查完正在进行的任务后安排服务重启。源码发布不会替换已在运行的进程。请检查新启动可执行文件的版本及其配置路径。

## 验证身份

发布工作流会记录确切提交，运行三平台测试与独立源码包检查、依赖审计、Design/traceability 检查、真实 WebKit 矩阵以及全部 300 个不同的对抗轮次。发布阶段还会构建各平台归档并校验全新下载。GitHub Release 链接指向实际完成的运行；较早的绿色候选不能证明较新的提交。

WTeam 部署、数据库迁移、身份配置与已安装服务的升级有各自的验收步骤。

## 命令发现与有界执行

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 可以在不启动运行时的情况下检查命令目录。编码工作从 `agent_context` 开始；`balanced`、`fast` 与 `light` 预设保持各自的执行与授权边界。被动检查使用 `--read-only --no-exec --no-semantic`。

命令策略与授权默认是宽松的。`--no-exec` 会覆盖会话级命令授权，显式加固标志记录在安全参考中，而不是由默认值暗示。

对于中断或不完整的检查，请保留 `timed_out`、`output_incomplete` 与原始任务 ID。在请求再次执行之前，先读取它的结果。维护者门禁包括 `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings` 与当前的在线审计。JavaScript 回归使用 Node 24。
