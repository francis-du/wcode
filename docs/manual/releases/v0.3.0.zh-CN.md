# wcode v0.3.0

v0.3.0 把原有的安全 Workspace 与 Coding Harness 扩展成一套 Product Scope-aware Software Intelligence Runtime，并把 Desired State 到安全实现、验证证据和 Reconciliation 的路径连成完整闭环。

## Product Scope

新增统一的 12 个 Product Scope，用于源码架构、`scope_status`、`software_context`、Semantic Scope、MCP Tool Metadata、Project Context 与 Agent 指引。

## Workspace 与 Scheduler

- 文件写入继续使用 Workspace Root、SHA 前置条件和原子提交。
- 模型请求的非默认裸可执行程序名可以进入按 Workspace 隔离的 Pending Authorization。
- TUI 与受保护 WebUI 都支持选择性批准/拒绝。
- `parallel_tools` 使用可复用的资源依赖 Scheduler，而不是简单“并发执行全部”。
- 独立任务并发，冲突路径按依赖顺序执行。
- 同文件 Edit 只有在同一 SHA 且范围不冲突时才会合并。
- 默认并行度按 CPU 自适应，Harness 仍保留明确上限。

## Software Intelligence

Design State、Actual State、Syntax/Semantic Graph、Semantic Registry、Traceability、Drift、Impact 与 Risk 通过 Harness 连接起来。

`software_context` 可以先按 Product Scope 收窄，再进入源码导航；Graph History/Query/Diff 保留 Provider、Precision 和 Revision Provenance。

## Project Observatory

受保护 WebUI 改成 Requirement-first：

```text
Desired State → Actual State → Change → Proof → Convergence
```

每个 Requirement 展示 Component、当前实现、Acceptance/Verification、约束、ADR、Git 改动和收敛 Blocker。Proof 只统计与当前 Code + Design Revision 一致的 Evidence。

## Verification 与 Evidence

- Medium 及以上 Risk 增加独立 Maintainability Review。
- Property / Mutation / Fuzz / Runtime-Canary 使用跨语言 Executor Registry。
- Evidence 继续按 Producer fail-closed 聚合。
- Reconciliation Execution 可持久化并按依赖推进。

## MCP 与 Agent

- HTTP + OAuth 与本地 stdio 共用一套 MCP Core。
- 暴露 Tools、Prompts、Resources 与 Durable Tasks。
- Agent Plugin 导出保持非执行：不带 Hook、脚本、凭据或隐式 Workspace。
- OAuth 保留 PKCE、Resource Binding、DCR 兼容与 Origin 校验。

## 语言质量

语言支持改为显式能力矩阵，不再用一个布尔值描述。Syntax、Semantic、Format、Lint、Type/Static、Test、Security 和高级 Verification Stage 分别展示真实覆盖与 Gap。

## Design State

`design_init` 保持稀疏，只创建 Project/Product；没有真实内容时不会预建空的 Requirement/Component/Constraint/Acceptance/Decision 文件。

## 升级后建议

```text
design_status
traceability_status
review_changes
verify_project
```

发布仍以实际 CI/Release Evidence 为准，不以这份说明本身作为“已经通过”的证明。
