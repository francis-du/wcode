# wcode v0.3.0

v0.3.0 把原有 Control-plane Primitive 连接成一套 Product Scope-aware Software Intelligence Runtime，并收紧从 Desired State 到安全实现、Verification Evidence 与 Reconciliation 的路径。

## Product Scope

wcode 新增统一的 Product Scope Registry，覆盖 `runtime`、`integrations`、`workspace`、`design`、`graph`、`semantics`、`traceability`、`risk`、`verification`、`evidence`、`reconciliation`、`experience`。

Registry 不只是 Metadata，它驱动：

- Source Architecture 与 Convention Classification；
- Scoped `software_context`；
- Scoped Semantic Query，同时保留 Freeform Business Scope；
- `project_context` Capability Discovery；
- MCP Tool `_meta.dev.wcode/productScopes`；
- MCP Resource `wcode://runtime/product-scopes`；
- `scope_status` 的 Repository Audit；
- Agent / Skill Workflow；
- Design State Component 与 Acceptance Chain。

## Workspace 与 Scheduler

- Workspace Coding Primitive 继续保持 Root-scoped、SHA-guarded 与 Atomic。
- Destructive Action 使用精确 Dynamic Authorization，并在需要时使用 One-shot Grant。
- Model 请求的裸可执行程序名可以产生按 Workspace 隔离的 `CommandAccess`；Operator 可以在 TUI 或受保护 Project Observatory 中批准/拒绝。Shell Interpreter 与带路径 Program Name 继续硬拦。
- `parallel_tools` 使用可复用 Resource Scheduler，而不是只读 Fan-out 特例。
- Scheduler 显式建模 Read、Write、Create、Move Source、Move Destination、Delete。
- 独立工作可以 Fan-out；冲突资源按依赖排序。自适应默认并行能力为 CPU×12，并限制在 96–192；显式 Harness 最大值仍为 256。
- 同文件 `apply_edits` 只有在使用同一个已观测 SHA、编辑不重叠且能明确定位时才允许 Coalesce。
- Interactive Coding Write 继续保留同目录 Atomic Replacement 与 SHA/Path Safety，但不再每次小编辑都强制完整 Data+Directory fsync；`project_context` 并行 Convention/Language Quality Scan，Exact Search 流式遍历并行 Worker，Bounded Read 避免整文件 Line Vector，Multi-edit 共享 Line Index，请求/响应字节指标使用 Streaming Writer 避免额外 JSON Allocation。

## Software Intelligence

- Design State、Actual State、Syntax/Semantic Graph Fact、Semantic Registry、Traceability、Drift、Impact、Risk 通过 Harness 连成一体。
- Software Context 可在广泛读取源码前按 Product Scope 收窄。
- Semantic Scope 是持久且有行为意义的：请求 Scope 会过滤 Scoped Fact，Unscoped Fact 保持 Global。
- Semantic Provider 明确暴露 Precision，所有索引语言都保留真实 Provider / Fallback 路径。
- Language Quality Matrix 把支持拆成 Syntax、Semantic、Format、Lint、Type/Static、Test、Security 和高级 Verification Stage；Repository-declared / Native Tool 优先，缺失维度保持可见 Gap。
- `language_quality_run` 只运行检测到、仓库声明、可用、Check-only 的 Provider，并通过 Trusted Authorization Boundary 记录当前 Revision Evidence，不暴露 Formatter/Fixer Write Mode。
- Composite Graph History / Query / Diff 保留 Provider、Precision 与 Revision Provenance。

## Project Observatory

- 受保护 `/intelligence` WebUI 以 Requirement 为入口，并围绕 **Desired State → Actual State → Change → Proof → Convergence** 组织，而不是把通用 Software Graph 当主 Ball/Node Canvas。
- Requirement Board 展示 Feature Intent、Component Responsibility / Dependency、当前 Implementation Symbol / File、Acceptance / Verification、Constraint / ADR，并给出 `stable`、`changing`、`needs_convergence`、`incomplete` 状态与有界 Blocker。
- Proof 是 Revision-exact：只统计 Code 与 Design Revision 同当前仓库一致的 Evidence。
- Runtime 会重新生成有界 Software Graph，并比较声明的 Component Dependency 与代码观测到的 Call / Import / Reference / Runtime Relationship，同时保留 Provider / Precision，不冒充 Compiler Certainty。
- Repository 与 Feature Statistic 包含 Source File/Line/Byte、Implementation Line、Symbol/Call Edge、Language / Product Scope Distribution，以及当前 Git Addition/Deletion 与受影响 Requirement。
- Meaningful、去重的 Software Graph Snapshot 继续作为 Architecture History；UI 展示 Revision Time、Node/Edge `+ / - / ~` Delta 与可归因 Changed Path。
- 同一 Operator Surface 提供 Language Quality Matrix。

## Verification 与 Evidence

- Risk-adaptive Verification Mesh 组合有界 Deterministic Check、独立 Review、Property/Mutation/Fuzz/Runtime-Canary Stage Evidence，以及必要时的 HumanApproval。
- Structural Maintainability 成为一等 Approval Gate：`review_changes` 产生 1k Boundary、Concentrated Growth、Cross-Product-Scope Deterministic Signal；Medium 及以上 Risk Plan 包含盲审 `maintainability_review` Job，Correctness Evidence 不能替代它。
- Stage Aggregation 按 Producer Fail-closed；一个 Producer 的 Pass 不能隐藏另一个 Producer 的 Fail。
- Evidence 持久、Workspace-scoped 且带 Provenance。
- Reconciliation Execution 持久且依赖感知；Verification 与 HumanApproval 仍是 System Evidence Gate，不是模型可 Claim 的普通工作。

## MCP、Agent 与 Connector

- Modern 与受支持 Compatibility MCP Revision 共用一套 Runtime。
- MCP 暴露 Tools、Prompts、Resources 与 Durable Owner-scoped Tasks。
- OAuth / Connector 保留 PKCE、Protected Resource Metadata、Resource Binding、有界 DCR Metadata 与安全 Web/Native Redirect Profile。
- HTTP MCP Surface 保留显式 Origin Validation。
- Local stdio 与 Portable Coding-agent Skill Export 均受支持。
- Portable Skill 遵循 Agentic Engineering：短常驻地图、Progressive Disclosure、隔离 Worker、Deterministic Policy Gate、Revision-exact Evidence；Model Consensus 不替代 Proof。
- Agent 可通过 Tool Metadata 或 Product Scope MCP Resource 发现 Scope。

## Convention 与 Architecture Governance

- Convention Policy 覆盖全部 22 种索引语言，不强行发明统一命名风格。
- Convention Status 报告 File Naming、Architecture Domain、Product Scope Mapping、Unmapped/Unclassified Source、Flat Rust Growth、Oversized Module。
- Source Code 按 wcode Product Scope 组织，而不是继续平铺技术层增长。
- 大型 Runtime / Workspace / Intelligence / MCP / Experience 职责拆成有界 Module，同时保持外部 Crate/Module Contract；Ratatui Monitor 也把 Lifecycle/Main Layout 与 Setup/Activity/Intelligence/Help/Footer Rendering 分离。

## Design State

- `design_init` 保持 Desired State 稀疏且有意义：初始化只创建 `.wcode/project.yaml` 与 `design/product.yaml`；Requirement/Component/Constraint/Acceptance/Decision Collection 在有真实内容前保持缺省，而不是写出空 `[]`。
- Runtime Evidence、Verification、Graph、Semantic、Reconciliation、MCP Task State 继续存放在用户级 wcode State Directory，不污染 Repository `.wcode/`。

当时工作树中的 Design State 把已实现 Product Scope 能力映射到真实 Implementation Symbol 与 Acceptance Test。发布 Tag 必须重新验证这些事实，Future-only Placeholder 不应被当作已实现能力。

## 升级

使用仓库安装脚本或对应平台 Release Artifact 安装 v0.3.0。Repository 内 `.wcode/` Design State 保持不变；Evidence、Verification State、Semantic Fact、Graph/Provider History、Reconciliation State 与 MCP Task Snapshot 保存在按 Canonical Workspace Root 隔离的用户级状态目录中。升级后使用 `design_status`、`traceability_status`、`review_changes` 与 `verify_project` 验证工作树。

## Release Gate

v0.3.0 只有在 Locked Full Gate 通过后才可发布：Formatting、Type Check、Test、Clippy `-D warnings`、Optimized Release Build，以及有效 Design State 与可解析 Traceability。Quality Workflow 运行 `wcode intelligence --check --json`，使 Design、三条 Traceability、显式声明的 Canonical Product Scope Mapping 与 Required Convention Policy 真正成为 Gate，而不只是文档说明。第三方 Workspace 不会因为没有采用 wcode 自身源码布局而被强制进入同一 Product Scope Gate。
