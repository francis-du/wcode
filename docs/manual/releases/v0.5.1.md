# wcode v0.5.1

v0.5.1 is a stability and operator-experience release. It keeps wcode fast during active work, but prevents unattended background activity, language servers, compiler descendants, and long-lived caches from holding a machine at high CPU or memory for hours. It also makes the protected browser surfaces practical on 320–430px phones without changing Workspace, authorization, MCP, or tunnel contracts.

## Burst-friendly resource governance

- The default Harness still exposes 32 tool slots so independent I/O and repository reads can fan out.
- CPU-heavy internal sections may use short multi-core bursts, with up to four bounded CPU lanes on typical hosts.
- Interactive work receives a larger burst/debt window and a sustained target around one core instead of being forced into the 10% background budget.
- Unattended maintenance uses the configured background target, 10% by default, and yields whenever foreground CPU work is active.
- Sustained process pressure adds bounded admission delay instead of freezing every new tool until the machine becomes idle.
- CPU accounting now separates foreground and background credit, rechecks credit after queueing, and avoids occupying a CPU lane while sleeping for budget recovery.
- The runtime lowers its process priority and exposes current, smoothed, and budget values through the TUI and health/capability surfaces.

The configured CPU percentage is a cooperative sustained-load target, not a ban on short peaks. A search, index build, or verification step may briefly use several cores; the governor intervenes when that load persists.

## Memory, semantic, and subprocess stability

- Resident memory uses a 512 MiB soft budget by default, with cold-cache trimming at elevated pressure and temporary headroom before new work is paused.
- Non-aggressive trimming keeps a warm AST, Repo Map, project-profile, and LSP working set instead of throwing away every useful cache.
- Tree-sitter AST entries no longer retain an extra full source-text copy, and warm LSP document tracking keeps revision/end-position data rather than duplicating complete files.
- Automatic semantic discovery groups files by language before provider resolution, avoiding repeated PATH scans for every source file.
- Discovery scans a wider bounded candidate window so Rust projects are not missed merely because other files sort first, while provider input remains capped.
- Background semantic workers pause under foreground or memory pressure, contain worker panics, and restart cleanly instead of silently disappearing.
- LSP framing now bounds response headers as well as response bodies.
- Governed commands and language servers use owned process groups on Unix. Timeout, cancellation, dropped futures, session eviction, and shutdown terminate the full descendant tree rather than leaving compilers or analyzers running.

## Mobile WebUI

The Project Observatory, Setup Hub, and OAuth pages now share a phone-safe layout model:

- `viewport-fit=cover`, dynamic viewport units, and safe-area padding support notched phones and home indicators.
- Inputs use mobile-safe sizing, and buttons/selects provide touch targets suitable for one-handed use.
- The Observatory control bar becomes a predictable grid instead of wrapping into narrow unusable rows.
- Architecture metrics, legends, and the component inspector stack cleanly; the SVG keeps readable node dimensions and scrolls to the selected component instead of shrinking the whole graph.
- Requirements and convergence steps become horizontally scrollable snap lists on narrow screens.
- Change and quality tables remain readable through card/scroll treatments, long paths wrap or truncate safely, and project trees reduce indentation on small displays.
- Access management becomes an accessible full-screen mobile panel with background-scroll locking, focus restoration, Escape handling, and keyboard-safe input spacing.
- Setup Hub stops health polling while the page is hidden, reducing mobile battery and network use.
- OAuth success, error, and pairing pages preserve browser zoom and handle long endpoints without horizontal page overflow.

## Compatibility and safety

There is no Workspace or Design State migration.

- The MCP protocol, OAuth/PKCE flow, exact command authorization, Workspace isolation, and protected WebUI token model are unchanged.
- `--tunnel-provider auto` still starts all candidate providers, retains every instance-verified tunnel, retries failed providers independently, and promotes another live tunnel if the primary disappears.
- Resource pressure never removes tunnel capability or converts the multi-provider runtime into a first-success race.
- Missing or untrusted semantic providers continue to fall back explicitly to Tree-sitter syntax precision.
- The package, marketplace, Claude, Codex, and ZCode plugin manifests remain version-locked to the crate.

## Upgrade

Install or upgrade with the normal installer:

```bash
curl -fsSL https://raw.githubusercontent.com/francis-du/wcode/main/install.sh | sh
```

Then restart any already-running runtime so the new governor and browser assets are loaded:

```bash
wcode restart
```

The defaults are designed to remain responsive without additional flags. Operators can still tune sustained background CPU, memory, and tool concurrency with the existing runtime options.

## Release gates

The tagged revision is required to pass:

```text
git diff --check
cargo check --locked
cargo fmt --check
cargo test --locked
cargo clippy --locked -- -D warnings
cargo build --release --locked
```

The GitHub release workflow repeats governance and quality checks, tests Linux/macOS/Windows, builds optimized platform archives, validates installers and binary version output, and publishes SHA-256 checksums with the release assets.
