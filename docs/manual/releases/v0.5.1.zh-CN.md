# wcode v0.5.1

v0.5.1 重点解决运行稳定性和移动端操作体验。前台真正工作时仍然保持高并发与短时多核性能，但无人值守后台任务、Language Server、编译器后代进程和长期缓存不再持续数小时占满 CPU 或内存。受保护的浏览器界面也完成了 320–430px 手机适配，同时不改变 Workspace、授权、MCP 或隧道契约。

## 突发友好的资源治理

- Harness 默认仍提供 32 个工具槽位，互不冲突的 I/O 与仓库读取可以并发执行。
- 内部 CPU 密集区段允许短时多核突发，常见机器上最多使用 4 条有界 CPU Lane。
- 交互任务拥有更大的突发与透支窗口，持续目标约为一个核心，不再被强行压进 10% 的后台预算。
- 无人值守维护任务使用配置的后台目标，默认 10%，并在前台 CPU 工作出现时主动让路。
- 进程持续高负载时只增加有界的 Admission Delay，不会把所有新工具冻结到机器完全空闲。
- CPU 记账现在分离前台与后台额度，排队后重新检查额度，并避免任务在等待预算恢复时占住 CPU Lane。
- Runtime 会降低自身进程优先级，并在 TUI、Health 与 Capability 中暴露瞬时值、平滑值和预算值。

这里的 CPU 百分比是协作式的持续负载目标，不是禁止短时峰值。Search、Index Build 或 Verification 可以短暂使用多个核心；只有负载持续存在时 Governor 才会介入。

## 内存、语义与子进程稳定性

- Resident Memory 默认使用 512 MiB 软预算；压力升高时先清理冷缓存，并在暂停新任务前保留临时峰值空间。
- 非激进回收会保留一组热 AST、Repo Map、Project Profile 和 LSP Working Set，不再把全部有效缓存一次清空。
- Tree-sitter AST Entry 不再额外长期保存完整源码副本；Warm LSP Document Tracking 只保留 Revision 与结束位置等必要信息。
- Automatic Semantic Discovery 会先按语言聚合文件再解析 Provider，避免对每个源码文件重复扫描 PATH。
- Discovery 使用更宽但仍有上限的候选窗口，Rust 文件不会仅因排序靠后而永远无法发现，同时 Provider 输入数量继续受限。
- 后台 Semantic Worker 在前台或内存压力下暂停，Worker Panic 会被隔离并重新启动，不会悄悄永久退出。
- LSP Framing 现在同时限制 Header 和 Body 大小。
- Unix 上受管命令与 Language Server 使用独立进程组；Timeout、Cancellation、Future Drop、Session Eviction 和 Shutdown 都会清理整棵后代进程树，不再遗留编译器或 Analyzer。

## 移动端 WebUI

Project Observatory、Setup Hub 与 OAuth 页面现在使用统一的手机安全布局：

- `viewport-fit=cover`、动态 Viewport Unit 与 Safe Area Padding 支持刘海屏和底部 Home Indicator。
- Input 使用移动端安全字号，Button 与 Select 提供适合单手操作的触控区域。
- Observatory 顶部控制区切换为稳定网格，不再在窄屏随机折行并互相挤压。
- 架构指标、图例和 Component Inspector 会顺序堆叠；SVG 保持可读节点尺寸并自动滚动到选中组件，而不是把整张图缩到无法阅读。
- Requirement 与 Convergence Step 在窄屏下变成支持吸附的横向列表。
- Change 与 Quality Table 使用卡片或横向滚动处理；长路径可以安全换行或截断；Project Tree 在小屏减少缩进。
- Access Management 在触摸设备上变成可访问的全屏面板，支持背景滚动锁、焦点恢复、Escape 关闭和软键盘安全间距。
- Setup Hub 在页面进入后台后停止 Health Polling，减少手机耗电与网络请求。
- OAuth 成功页、错误页和配对页保留浏览器缩放能力，长 Endpoint 不再撑破整个页面。

## 兼容性与安全边界

本版本不需要迁移 Workspace 或 Design State。

- MCP 协议、OAuth/PKCE、精确命令授权、Workspace 隔离和受保护 WebUI Token 模型保持不变。
- `--tunnel-provider auto` 仍会启动所有候选 Provider，保留每一条通过当前实例验证的隧道，独立重试失败 Provider，并在主隧道消失时提升其他可用隧道。
- 资源压力不会删除隧道能力，也不会把多 Provider Runtime 改成“首个成功即取消其他任务”。
- 缺失或未受信任的 Semantic Provider 继续明确回退为 Tree-sitter Syntax Precision。
- Crate、Marketplace、Claude、Codex 与 ZCode Plugin Manifest 继续和版本号严格一致。

## 升级

使用现有安装器安装或升级：

```bash
curl -fsSL https://raw.githubusercontent.com/francis-du/wcode/main/install.sh | sh
```

已经运行的 Runtime 需要重启，才能加载新的 Governor 和浏览器资源：

```bash
wcode restart
```

默认参数已经兼顾响应速度和持续资源占用；仍可通过现有 Runtime 参数调整后台 CPU、内存和工具并发。

## 发布门禁

Tagged Revision 必须通过：

```text
git diff --check
cargo check --locked
cargo fmt --check
cargo test --locked
cargo clippy --locked -- -D warnings
cargo build --release --locked
```

GitHub Release Workflow 会再次执行治理与质量检查，在 Linux、macOS 和 Windows 上运行测试，构建优化后的平台包，验证安装器和二进制版本输出，并随 Release Asset 发布 SHA-256 校验文件。
