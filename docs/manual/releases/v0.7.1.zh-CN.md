# v0.7.1 — 稳定隧道、实时项目加载与更强并行执行

v0.7.1 是一次稳定性与吞吐量修复版本。先提交并 Push 发布候选；只有该 Commit 的普通 CI 全部通过后，才创建 `v0.7.1` Tag。由 Tag 触发的跨平台打包与正式发布仍属于后续独立门禁。

## Tunnel、Host Trust 与网络恢复

Tunnel 生命周期改为真实状态机，不再把一次健康探测失败直接等同于 Endpoint 死亡。Standby 可以进入 suspect／quarantined 状态而不立即 Kill Provider Process，也不会立刻 unregister Host。只要 Stable Alias 仍然能够命中当前 wcode Instance，就继续保留；Provider Process 退出与公网 Endpoint 失效也不再被混为一谈。

公网 Health Check 现在对短时网络抖动有容错：正常链路仍只做一次快速 Probe；只有失败时才追加两次短间隔确认，全部失败后才记作一次真实 Failure。恢复探测使用快速节奏，Stable Host 不会因为瞬时丢包立刻失去 Trust；持续故障才进入有界 Backoff，并加入 Provider-specific Jitter，避免重连风暴。

Tailscale Funnel 继续作为首选 Stable 零配置入口。Microsoft Dev Tunnels 新增为显式 Persistent Provider，通过已经存在的 Tunnel ID 启动；账户登录、Tunnel 创建和端口配置仍由操作者负责，因此不会塞进 `auto`。临时 Cloudflare、localhost.run、Pinggy 继续作为可用 fallback，但不会伪装成 Durable Identity。

## WebUI 项目加载恢复实时体验

Engineering Observatory 的项目状态改为 stale-while-revalidate。只要某个项目已经有可用 Snapshot，切换时就立即渲染最近快照，同时在后台按 Revision 异步刷新；不再先清空整个页面，再同步等待完整 Observatory 重建。

Revision、Project Snapshot 与 Activity Refresh 被拆开，页面先展示可用状态，再逐步收敛到最新 Revision。所有缓存仍绑定 Project Generation 与 Revision，迟到响应不能覆盖更新后的项目选择。

## 写代码更快，并行能力变成强约束

Parallel-first 现在是 Canonical Engineering Constraint，不再只是 Prompt 建议。互相独立的 Discovery、Read、File-local Edit 和 Verification Lane 默认必须 Fan-out；只有真实数据依赖或路径依赖才能串行。`agent_context` 会把这条约束带给后续编码 Agent。

Scheduler 为纯只读 Fan-out 增加 Fast Path，跳过不必要的 Pairwise Conflict Graph。Workspace Revision 正常路径复用一次文件扫描同时计算 Code 与 Design Revision。前台资源模型更强调真实吞吐：最多 32 Tool Slot、32 个有界 File-I/O Lane、最多 8 个 Lightweight Probe Process、自适应 4–8 Tokio Worker；Heavy Child Process 根据内存与 CPU Thread Headroom 计算，而不是固定在很低的上限。后台持续 CPU Budget 仍单独治理。

`balanced`、`fast`、`light` 三档继续保留，它们提供的是有界容量，而不是无限并发承诺。

## 所有语言的正常开发工具不再反复授权

22 个已索引语言的常用开发工具链现在使用命令级 Autonomous Policy。只要参数保持在 Hardened Shape 内，Compile、Test、Lint、Format、Typecheck、Build、Dependency Maintenance 与仓库声明的 Verification Runner 都可以直接执行，不再反复弹人工授权。

硬边界没有放松：Shell、任意 Inline Eval、Credential Redirect、Host-wide Toolchain Mutation、Force／History Rewrite、Release Publication、破坏性 Infrastructure Action、Compiler／Plugin／Agent Injection 与危险 Path Escape 仍会阻断或单独授权。仅查看模式仍然是：

```text
--read-only --no-exec --no-semantic
```

## `semantic_auto` 不再反复启动假 Provider

当 PATH 中的 `rust-analyzer` 只是 rustup Proxy，而当前 Workspace Toolchain 实际没有安装 `rust-analyzer` Component 时，`semantic_auto` 不再把它标成 launch-ready。Discovery 会验证 Proxy 是否真正可用，并短时缓存 Viability；不可用时直接诚实降级，而不是循环 Spawn 已知失败的 Server 并持续报错。

Warm Semantic Session、Syntax Fallback，以及非 Hardened Provider 的显式授权策略保持不变。Provider Failure 仍区分 Discovery、Authorization、Spawn、Initialize、Protocol 与 Live 状态。

## Diagnostics 与兼容性

命令超时和取消继续返回 `timed_out` 与 `output_incomplete`；取消仍不代表回滚，也不会自动 Replay。OAuth、Workspace Isolation、Design State、Evidence、Repository SHA Guard 与 No-shell Execution 与 0.7.0 保持兼容。

使用 `wcode help-all`、`wcode help-all setup` 与 `wcode help-all --json` 查看由真实 Parser 定义的完整 CLI Surface，不执行被查询命令。

Cargo、Cargo.lock 与六份 Plugin／Marketplace Manifest 统一为 0.7.1。CI 继续显式安装 Node 24 执行 Observatory JavaScript 行为回归，并在 Release Packaging 前运行 RustSec Dependency Audit。

## 验证与发布门禁

Push 0.7.1 Release Candidate 前执行锁定依赖的本地完整门禁：

```text
git diff --check
cargo check --locked
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo build --release --locked
```

同时检查 Design State、Product Scope 与 Repository Convention。Commit Push 后，等待该精确 Commit 的 CI 全绿；只有这时才创建 `v0.7.1`。Tag 触发的 Release Workflow 再执行 Linux／macOS／Windows Build、Smoke、Signing／Packaging 与 Publication Gate。CI 未通过前不要创建或移动 Tag。
