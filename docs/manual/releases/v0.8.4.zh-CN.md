# v0.8.4 — Scope 隔离的并发 Writer 与统一 MCP Transport 协议策略

v0.8.4 继续推进无需 IDE 的工程运行时，重点补上安全的并发实现能力：当已批准的 Reconciliation Plan 为不同任务声明明确且互不重叠的写入 Scope 时，多个已认证 Agent 可以在同一个 Git mutation domain 内并发修改。同时，stdio 与 HTTP 统一到一套 MCP 协议时代判断逻辑，避免不同 Transport 各自维护规则后逐渐漂移。

## Scope 隔离的并发 Writer

- 已批准的 Design／Implementation Task 可以声明规范化的 Workspace 相对 `write_scopes`。
- 只有当多个 Scope 按路径相等／祖先／后代关系完全不重叠时，不同 MCP Owner 才能在同一个 Git mutation domain 内同时持有 Writer Lease。
- 没有 Scope 的旧任务继续保持整域独占，兼容之前的安全模型。
- 一个 MCP Owner 同时只能持有一个 Writer Lease，防止多个 Task Scope 被合并成 Owner 级的大范围写权限。
- 文件创建、修改、移动、删除都要同时通过 Writer Scope 与原有 SHA precondition。
- 会影响整个 Workspace 的命令仍要求整域 Writer；Scoped Writer 不能运行这类宽泛副作用命令。
- 嵌套 Workspace 共用同一个 mutation-domain 路径空间；Linked Worktree 继续作为更强的隔离边界。

## 稳定的远程 Writer 身份

- OAuth Owner 从“按 Client Registration”改为“按 Authorization Grant”隔离；同一个客户端应用发起的两次独立授权会得到不同 Writer Owner。
- Refresh Rotation、重连和进程重启都会保持同一个 Grant Owner。
- 旧持久化 Token 没有 Owner ID 时继续使用原来的 Client-bound 兼容行为。
- 持久化 Owner ID 格式异常时加载直接 fail-closed。

## 一套 MCP Transport 协议策略

- stdio 与 HTTP 共用同一个 Payload 级协议选择策略。
- `server/discover` 与现代 `_meta` 的协议时代判断在不同 Transport 上保持一致。
- HTTP 继续保留 Header 级 Transport 校验，但 modern body 不允许被冲突的 legacy protocol header 静默降级。
- Header 与 Body 不一致继续 fail-closed。

## Reconciliation 与恢复

- Reconciliation Execution 使用事务式持久化更新，两个并发 Scoped Claim 不会互相覆盖。
- Writer Status 可以同时暴露多个 active/pending Owner 及其脱敏 Scope，不暴露 Reservation Token。
- Submit／Failure 只释放匹配 Owner／Plan／Task 的 Lease。
- Durable Writer Claim 会持久化不透明的 Owner Binding；进程重启后，只有同一个已认证 Owner、Executor 和显式 Task 才能重新认领，旧版无 Binding 或身份不匹配的 Claim 继续 fail-closed。
- Durable Task 一旦不再处于 `Claimed`，对应 Runtime Lease 会立即失去写权限，即使 Submit 后的 Lease 释放动作尚未完成。

## 稳定的运行时与发现契约

主要的有界编码入口继续是 `agent_context`。资源预设仍为 `balanced`、`fast`、`light`，JavaScript 行为 CI 使用 Node 24。命令结果继续显式暴露 `timed_out` 与 `output_incomplete`，不会把有界执行失败包装成成功。

CLI 发现继续保持无副作用：

```text
wcode help-all
wcode help-all setup
wcode help-all --json
```

强化后的纯检查组合仍为 `--read-only --no-exec --no-semantic`。最终 Rust 发布验证包含：

```text
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```
