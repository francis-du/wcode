# v0.6 — Parallel-first Agent 与可授权项目命令

wcode 0.6 的重点，是让 Coding Agent 少猜仓库结构，并在安全边界内更主动地并行完成独立工作。

## 重点变化

- `agent_context` 现在返回明确的 Parallel-first 执行契约：候选 Dependency Lane、推荐并发数、立即发起顶层并行调用的指令，以及仍然必须串行的少数条件。
- Task-ready Context 会更明确地携带 Minimal-change Strategy、Complexity Budget、Active Worklist、Hot Source、Semantic Provider Readiness 和绑定 Revision 的可编辑文件。
- Semantic Runtime 统一为 LSP Server Discovery、Binary Identity、有界 Warm Session、Source Revision 同步；没有 Automatic Safety Profile 的 Server 会 Fail Closed 并进入精确授权。
- 常见本地探查命令减少打断。未被策略专门识别或会执行仓库代码、但仍通过全部硬安全边界的操作，不再永久拒绝，而是生成精确 `RiskyExecution` 请求。
- 授权仍绑定当前 Workspace、Program、Arguments 和 Working Directory。Shell、Protected Path、Workspace Escape、凭据/配置重定向、Host-wide Tool Mutation、Package Publication/Ownership 与破坏性基础设施操作继续阻断。
- Plugin Skill 与文档会明确要求有能力的 Host 立即并行发起独立 Discovery、Read、Review、Check 和不重叠 Edit，而不只是泛泛提示“可以并行”。

## 为什么重要

模型只能基于它拿到的上下文和执行契约行动。v0.6 让这两部分更可执行：仓库会告诉 Agent 哪些工作现在就应并行、哪些必须串行、哪些 Evidence 仍然有效，以及何时必须由用户而不是模型批准一个精确指纹绑定的操作。

## 升级

```bash
wcode update
```
