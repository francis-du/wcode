# 前沿工程与能力路线图

## 状态

本轮核查日期为 2026-09-10，研究内容与[此前的改进](../research-upgrades/)分开记录，不把旧论文重新包装成新发现。下文已实现改动已纳入 [v0.6.2 发布准备](../releases/v0.6.2/)，后面的路线图内容仍未实现。源码测试通过，不会自动更新正在运行的 MCP 进程或其工具声明。

实现范围现已增加下文的持久任务式项目验证。选择性上下文执行与完整、有界的验证计划继续保留；后面的独立智能体与通用写操作恢复仍属于路线图，不是已完成功能。本轮没有引入外部模型、嵌入服务、神经裁剪器、生产依赖、自动权限授予或新的 MCP 输入参数。

## 已实现：选择性上下文执行

原来 `agent_context` 会先做普通的全仓符号发现，再解析已经明确的文件位置，最后用定位结果替换刚检索出的候选。即使路径不存在，也可能先把无关文件加入索引，再返回没有目标。

现在先通过工作区保护解析定位点，再把已有符号传给统一的软件上下文构建器。仓库指引、Design State、已确认语义、追踪关系、测试引用、已知风险、持久 Worklist 和 SHA 前置条件继续保留。只有存在明确定位点时，跳过重复的词法发现；明确但不可访问的位置也不会触发无关全仓搜索。

简单、未指定产品范围的位置查询返回 `repo_map.deferred: true`：表示仓库图扩展暂缓，不是假称不存在关系。查询调用方、影响范围、架构，或者显式指定 Product Scopes 时，继续执行图扩展；普通符号查询保持原发现流程。语义提供者数据保留原来的来源和新鲜度检查。

例如 `src/runtime/worker.rs:120` 能先提供所需原文，而不必先排名无关仓库图。跨文件任务仍应请求需要的关系。设计追踪和语义提供者数据可能合理地读取其他文件，所以这不是“任何位置查询都只访问一个文件”的承诺。

本地回归样例在一个目标旁放置 128 个无关文件。修改前，目标冷查询在观察时保留了 30 个索引文件记录；缺失位置样例在随后读取对照大纲后保留了 129 个。这是索引缓存占用，不是累计解析次数。新验收目标是两种样例都只保留一个目标记录，且目标的冷、热查询保留准确行号、SHA 和原文。测试打印的单次耗时仅用于诊断，不是统计受控的延迟基准。

另外验证普通符号与调用关系仍可发现，指引与设计测试引用保留，以及 Python、TypeScript、Go 和 JSON 在 1,000、4,000 Token 估算预算下的原文与 SHA。Rust 定位、路径和 SHA 保护沿用已有回归。Token 数仍以序列化字节数除以四估算，不是模型提供商的真实分词结果。

## 已实现：完整、有界的验证计划

旧验证计划会静默取前八项。Rust、Node、Python、Go、Make 混合样例推导出十六项，原来的完整诊断却只覆盖八项；这可能漏掉测试或构建，仍将已执行前缀描述成全量检查。

现在先构造并排序完整计划，总计划上限为 32。超限时在派发前明确返回 `no checks executed`，而不是静默丢掉检查。这是计划大小限制，不是新的并发设置；原有信号量、阶段顺序、快速失败和绑定版本的 Evidence 继续生效。

十六项样例撤销临时工作区的程序执行许可，用来验证真实调度和结果记账，但不启动语言工具链。完整诊断必须包含全部十六个 ID，并按预期的授权边界报告失败，没有跳过项。这不能证明十六个外部工具都已安装或通过。另一个超限样例要求没有派发、没有批准请求、没有 Evidence。

## 已实现：断线后可查询的项目验证

`verify_project` 现在复用已有持久 Tasks 运行时。现代 `2026-07-28` 请求声明 `io.modelcontextprotocol/tasks` 时，服务端先持久保存任务，再返回 `taskId`，不必等待验证执行额度。客户端保留该 ID，以同一认证所有者调用 `tasks/get`，并遵守 `pollIntervalMs`。未声明扩展或使用旧协议的客户端，继续获取同步结果。没有新增 `async` 工具参数或模型可见工具，采用的是 [MCP Tasks 扩展](https://tasks.extensions.modelcontextprotocol.io/)，不依赖一条长连接始终不断。

创建请求结束后，已受理的工作者仍由任务运行时管理。明确取消会停止排队检查；即使客户端不轮询，单调时钟截止时间也会取消未完成工作。过期和工作者故障记录为持久失败，不误报参数错误或验证通过。已经启动的阻塞操作仍不承诺回滚。进程重启后，中断任务明确失败，不会自动重跑；已经完成的结果仍可读取。

`completed` 表示底层工具返回了结果，不代表检查通过。调用者必须读取 `result.isError` 与 `result.structuredContent.passed`。重复轮询、重新打开已完成记录都返回原结果，不增加验证执行或 Evidence。普通与持久任务入口共享严格的工作区解析；错误路由和验证参数在创建任务、工作者或授权请求前拒绝。

测试覆盖临时 Git 仓库的真实验证、成功与失败报告、执行额度耗尽、创建请求结束、重复查询、新运行时读取、其他所有者查询与取消、取消后不生成 Evidence、同步兼容，以及完全不轮询时的过期取消。这些是本地协议与运行时样例，不是已部署网络或跨平台基准。

限制：尚未实现写操作恰好执行一次、操作重放日志、中断工作者接管，或者创建响应连同 `taskId` 一起丢失时的恢复。不能为了轮询而重发修改或 `verify_project`；保留任务 ID 是前提。依赖此行为前，仍需分别确认运行时已更新以及宿主支持此扩展。

## 功能替代需要补齐什么

[Codex CLI 官方文档](https://developers.openai.com/codex/cli/features/)描述了交互编程循环、审查、会话恢复、委派及 MCP 集成；[Claude Code 子智能体文档](https://code.claude.com/docs/en/sub-agents)描述了独立上下文、工具与模型配置、权限和工作树隔离，并对插件提供的定义设有不同支持规则。这些需要逐项验收，不能因为暴露一个同名工具就判定等价。

跨宿主插件与独立编程智能体是不同交付形态。建议采用共享仓库运行时加薄的可选智能体宿主，而不是在第二套系统里重写编辑、授权、索引和验证。提供商许可、认证及不同模型的行为，需要分别做集成决策。

| 建议工作：本轮未实现 | 可执行验收目标 |
| --- | --- |
| 多提供商交互主循环与流式模型适配 | 完成理解、编辑、测试任务，保留工具调用身份，支持用户中断；注入 429、断连、半截流式响应时不虚报成功。至少在两个真实配置的提供商上跑同一流程。 |
| 持久操作记录与恢复 | 明确区分准备、开始、完成、结果未知。断连读取可重试，写入必须先核对已发生效果再决定是否重试；重放对话不能重放写入或发布。 |
| 隔离并行与检查点 | 给工作者明确基线和互不重叠的职责，返回补丁后受控合并，检测冲突；隔离目录消失时禁止退回主工作树。回滚和取消测试必须保留用户未完成改动。 |
| 进程会话、应用验收与调试 | 管理进程树、端口和有界增量输出，取消后终止子进程；通过声明的测试、浏览器和调试适配器验收应用。PTY 或 Shell 适配必须单独设计沙箱及批准，不能绕过当前无 Shell 策略。 |
| 有效权限而非反复打断 | 区分已知只读检查、可精确批准的修改、非法或越界请求；展示真实操作和作用范围，保留拒绝及客户端所有者检查。宿主表单和批量批准需要协议、界面测试，不靠静默 Full Access 替代。 |
| 独立正确性评测与开发者采用 | 固定模型做跨仓库、跨语言配对试验，隔离测试，公开兼容矩阵，保证安装复现和失败恢复。观察首任务完成率与真实重复使用，不编造受欢迎程度。 |

上表是建议路线图，不是已经实现的功能列表。单独标注“已实现”的章节描述已经交付的源码改动；其余验收目标仍是建议，不表示已经完整替代 Codex 或 Claude Code，也不意味着本地测试能证明全球排名。

## 评估方法

配对实验使用相同模型及提供商版本、提示词、仓库版本、依赖锁文件、时间和 Token 预算、硬件。分开报告冷、热索引及缓存；记录工具发现、往返次数、模型可见字节数、可获得的真实 Token、延迟、定位质量与隐藏测试任务成功率。覆盖缺失位置、大型单体仓库、冲突写入、拒绝授权、中断和提供商不可用。

标准补丁、较晚 Git 历史和隐藏测试置于智能体不可访问区域。禁止检索任务答案，但允许任务明确许可的正常文档。各工具使用相同隔离评测器，保留失败样例，并对重复试验报告置信区间。改掉测试、遗漏门禁或结果未知，都不能算任务通过。

当前验收使用 `review_changes`、`verify_project(level="full")`、`cargo clippy --locked --all-targets -- -D warnings`、Design 校验和同版本测试／构建 Evidence。源码布局检查约束模块大小。新进程真实 MCP 冒烟与 Linux、macOS、Windows CI 仍是独立发布要求；本文本身不是当前构建通过的证明。
