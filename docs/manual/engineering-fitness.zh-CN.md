# WCode Engineering Fitness

WCode Engineering Fitness（工程适应度）是 wcode 不依赖模型的测量层，评估由 wcode 直接负责的确定性仓库工程属性。它不是编码模型排行榜，也不声称模型一定能解决某个任务。

## 为什么叫“Engineering Fitness”

“Benchmark”容易被理解成端到端模型排名，“Capability Suite”则容易暗示单一、不透明的能力分数。工程适应度把每个版本视为可重复检查的工程系统：检索质量、语义精度、上下文效率、编辑就绪程度、缺陷相关证据、稳健性与成本分别衡量。

## 测量契约

每个任务冻结仓库版本、任务文本、Gold Evidence（标准证据集）和评估器版本。标准证据集列出必需及有用的源码身份，例如路径、限定符号名、关系和验证目标。评估器将可观察的 wcode 输出与标准证据集比较。参考补丁、未来历史和隐藏评估数据不得暴露给被测系统。

长期测量维度如下。具体已执行范围和未测项目见下文；这张表不代表所有维度已经实现。

| 维度 | 确定性证据 |
| --- | --- |
| 检索 | 必需证据召回率、前 K 项召回与排序、无关结果比例 |
| 语义 | 对照已知图的定义、引用、调用者、被调用者和实现关系精度与召回率 |
| 上下文 | 固定字节、token、行数预算下的标准证据覆盖、响应大小及冷暖状态行为 |
| 编辑就绪 | 精确目标身份、当前 SHA、可写目标与已映射的验证证据 |
| 缺陷相关证据 | 为经审阅的变异样例提供根因、影响和测试证据；不冒充自主发现缺陷 |
| 稳健性 | 旧版本写入拒绝、失效处理、部分结果如实报告、授权与工作区边界 |
| 成本 | 可观测的墙钟时间、调用与往返次数、序列化字节、估算 token、缓存、索引、LSP 工作和资源消耗 |

不要将这些维度压缩成单一版本分数。更快但标准证据召回更低的结果是可见回归，不应隐藏在平均值里。

## 评估层级

**Fitness checks（适应度检查）**是适合正常 CI 的确定性检查。正确性断言属于硬性门禁；有噪声的墙钟测量默认仅作描述，除非受控性能任务建立了具有统计依据的阈值。

**Fitness trials（适应度测量）**是显式执行的 release 配置测量。已有 `fast_context_benchmark`、`repo_rank_release_cost_comparison` 和 `competitive_io_benchmark` 仍属于阶段级测量，保留各自限制说明。它们是工程适应度的输入，不是模型正确率结论。

**Agent evaluation（智能体评估）**是独立的未来层。当具备模型预算时，可在同一冻结任务上对比固定模型搭配基线工具与 wcode 的结果。不得仅凭工程适应度推断智能体任务成功率。

## 运行检查和测量

日常确定性检查：

```sh
cargo test --locked --lib engineering_fitness_ -- --nocapture
```

显式运行优化构建下的测量并生成报告：

```sh
cargo test --release --locked --lib engineering_fitness_trial -- --ignored --nocapture --test-threads=1
```

命令末尾的 `FITNESS_REPORT` 返回实际 JSON/Markdown 路径，形如 `target/engineering-fitness-<时间戳>-<进程号>.json`。报告通过 Workspace 原子创建，不覆盖历史报告，并拒绝路径与符号链接逃逸。没有模型 API 调用，但仍消耗本地编译、CPU、内存和磁盘资源。

**测试通过表示测量逻辑和安全约束通过，不表示被测查询全部成功。** `errors`、`query_errors` 和逐次错误记录表示工具请求失败；失败请求的 Gold 仍在召回率分母中，命中记零。预热失败单独记录，不伪装成成功预热，也不悄悄扩大预算重试。硬断言保护评分逻辑、成功响应的预算上限和安全控制，不要求检索能力必须达到 100%。

## 已实现的场景与指标

当前有 60 个合成开发场景：Rust、Go、TypeScript、Python 覆盖明确符号、单目标、自然语言、调用者与调用链、路径和影响查询，再加同名符号路径消歧、四目标、中文路径与 CRLF、缺失目标、只读、10 个不同的 ownership guard 变异证据场景，以及 640 个干扰文件。

四语言翻译共享同一个生命周期行为家族，**不是 60 个独立真实项目，也不是隐藏泛化成绩**。Gold 仅存在于评测器，不写进被测临时 Workspace。明确符号任务允许查询包含符号名；自然语言任务不插入答案名称。删 guard 的场景只测缺陷相关源码是否交付，不测自主找 bug，也不冒充 mutation testing 的检出率。

60 场景 × 3 预算（1,000 / 2,000 / 4,000）× 冷暖两种状态，产生 360 个测量单元。普通检查每单元一个样本；显式 trial 每单元 7 个样本，即 2,520 次计量查询，另外记录 180 次预热。重复样本不是独立任务或工程迭代轮数。

| 已实现指标 | 含义 |
| --- | --- |
| Required Recall、Recall@5/@10、NDCG@10 | 路径与限定符号匹配；排序为 targets、repo-map、hot source 的去重交付流，不是内部候选排名 |
| Non-Gold Symbol Fraction | 已交付身份中，不在该任务人工标注的 required/useful 集合内的比例。`required` 表示完成任务必须交付的证据；`useful` 表示与任务直接相关但不是必需的邻接证据，例如 caller/callee 对中的另一端，或验证该行为的回归测试。其余身份仍按 Non-Gold 计量；通用模块/重导出 filler 不会为了美化分数被提升为 useful。它不是整个上下文的无关 token 占比。 |
| Complete Body Recall | Gold 所需完整源码是否以原始字节交付，且 SHA、路径、行号、redacted 状态正确 |
| All Required Edit Inputs | 所有必要目标、当前 SHA、完整源码与可写条件同时具备；不包含独立验证映射或执行成功 |
| Reported Edit Ready | 工具自报状态，单独保留，不充当上一个指标的裁判 |
| Syntax Graph | 四个简单调用图的边匹配，始终标注 Tree-sitter / syntax |
| Cost | 序列化字节、bytes/4 估算 token、各次耗时及冷暖分位数 |

9 个真实控制场景包括四语言语法图，以及 guarded edit/缓存刷新、只读拒写、同 SHA 并发写入、Workspace 边界、部分图覆盖如实报告。评分器另有同名错路径、重复命中、空分母、陈旧或缺失 SHA、脱敏正文、正文捏造/缺失、错误行号、CRLF 与失败分母等反例测试。

## 如何解读

同样的符号召回率不代表同样的源码覆盖。只找到函数名但没给正文，不能算完整源码交付。工具表示至少一个目标能改，也不能代替“所有必要目标均已具备修改输入”。空分母写 `null`，不是 100%。

`cold` 只表示新的 ToolHarness，不清理操作系统文件缓存或进程级语言配置；`warm` 表示同一 Harness 在相同查询预热后再运行。计时不包含编译、临时仓库准备、Harness 构造、评分和报告写入。7 个样本的最近秩 p95 就是最大值，不是可靠的长尾估计。共享开发机器的时延只是本地观察，CI 不设置墙钟阈值。

每份 JSON 包含语料与评测器指纹、执行测试二进制指纹、Git HEAD、dirty 状态、运行前后源码快照指纹及环境。运行前后的源码一致不等于证明编译输入一致，因此另外保留真实二进制指纹；并发修改必须使 `source_stable_during_run` 显示 false。

第二版评分使用 path+symbol 与原始源码校验，不能直接和旧版按名字匹配的分数比较。版本对照应固定语料、评分协议、构建模式、预算、机器和缓存定义，分别比较相同场景；不能只比较混合任务的总耗时。

## 反例检查与第三版测量契约

反例分别检查 wcode 和评分器，不修改冻结语料来美化优化结果。独立网络协议样例检查九个真实调用者不得被丢弃、有连接但与任务断开的图分量不得充当相关证据；另外以 48 个种子与顺序组合检查传递关系保留，并保留无明确目标时的探索结果。同一个 Workspace 的冷暖对照逐项检查 Gold 正文，不仅比较数量。

将明确目标的 RepoMap 上限从 12 缩到 6 未通过九调用者反例，因此保留原有有界容量，改为按任务证据和图可达性筛选。查询还有自然语言限定词时，精确缓存命中不足以跳过检索。上述检查仅说明对应样例的行为，不证明任意仓库都能完整检索。

第三版契约以评测请求的预算为准，禁止通过工具自行报告更高上限绕过验收。失败的可回答任务在 NDCG 平均值中记零；`ranking_attempts` 与 `noise_response_samples` 明确不同分母。未定义的百分比在 Markdown 中显示 `N/A`，对应 JSON 的 `null`。60 个 case 的成员集合和 required Gold 保持冻结；useful 由评测器独立人工标注并通过回归测试锁定，使直接任务关系和行为专项测试不会被误判为噪声，同时无关 wrapper/re-export 仍保持 Non-Gold。这个比例因此是相对于标注集的指标，仍不能直接叫“无关 token 比例”。JSON row 保留精确 `non_gold_identities`，Markdown 的逐 case 表同时展示 NDCG@10 与 Non-Gold 便于诊断。JSON 容器结构仍为第二版，测量契约版本与评测器指纹标明评分口径变化；只要 evaluator 标注或失败分母发生变化，旧报告都应重新评分后再数值对比。

## 紧预算正文交付

独立的报文解码样例检查：在 Rust、Go、TypeScript、Python 四种语言下，2K 请求应交付短目标函数及跨文件调用者的原始正文与匹配文件 SHA。只读工作区保留可读证据，但不获得写权限。另一个三正文样例验证关联补全不会停在已经交付的正文，也不会挤掉已选中的排序正文。

运行时在 2K 下准备两份排序正文，并允许有界关联正文补全，最终序列化预算上限不变。重复签名和调用摘要先于正文与文件前置条件被压缩。长正文反例覆盖 CRLF/Unicode、1K–4K 预算和 1/4 个 Harness 槽位；2K 冷暖检查逐项拒绝 Gold 证据丢失。这不承诺任意长函数都能装入小预算，冻结的 60 题与 Contract v3 评分保持不变。

## 交付缺口与源码字节指标

报告新增 `breakdown.language`、`breakdown.category`、`breakdown.target_count` 和 `breakdown.misses`。所有分组复用同一聚合逻辑，失败请求不消失。每次得分保留 `delivery`：最终未交付身份、已有身份但缺完整正文、缺当前文件 SHA、不可用的写入条件。这些标记可以重叠；只读状态不是一次写入失败。最终未交付身份也不等于已经证明内部检索漏掉了它。

`complete_gold_density` 用已校验完整必要片段的原始 UTF-8 字节区间并集，除以序列化响应字节。同文件重复、嵌套或重叠 Gold 只计一次；重复返回正文不会增加分子。部分、捏造、脱敏或陈旧正文不获得完整片段字节分。该指标仅统计实际可用响应，并公开样本数与字节分母，必须与错误数和召回一起看。它的补集不是噪声比例：安全元数据、未标注但有用的上下文、部分源码都不在分子里。`fresh_sha_recall` 将失败请求记零；`complete_bodies_per_1k_budget_tokens` 使用全部可回答请求的分配预算，不冒充供应方真实 token 用量。

`raw_required_source_bytes` 只是未压缩原始源码的预算下界。超过 `4 × 请求预算` 可证明按当前 bytes/4 契约装不下原文；低于该值不代表加上 JSON 和必要元数据后一定可行。无答案或无效标注显示不可用，长正文反例检查该区别。

不调用模型，保存每个测量单元一次采样的诊断快照：

```sh
cargo test --locked --lib engineering_fitness_diagnostic_snapshot -- --ignored --nocapture --test-threads=1
```

快照输出实际新建的 JSON/Markdown 路径及 1K cold 缺口清单。完整 trial 仍每单元采样七次。上述属于附加交付指标第二版，冻结 60 题与 Contract v3 主评分保持不变。

独立 1K 反例覆盖同文件/三文件的三个短函数、跨文件调用者、明确指定模块、同名源码与测试定义、超预算 UTF-8/CRLF 正文及十二个转义查询变体。运行时在 1K 下也有界准备相关正文对，先压缩重复调度、排序与匹配签名说明，保留正文对应的现有文件 SHA/只读信息。临时查询回显保守地不占最终装包预算，并在最终字节校验前删除；它不能扩大真实响应上限。显式目标和长正文截断规则仍受保护。

## 多目标同名竞争与正文状态

独立报文样例新增四语言三段调用链，以及四个函数分别与模块声明同名的 Rust 四文件任务。候选选择先为每个请求名称保留一个定义，再容纳重复匹配；普通实现查询优先函数，明确查询模块时保留模块。该规则不增加候选上限，也不冒充无歧义的语义解析。

紧预算下，只有同 ID、同路径、当前 SHA 的完整未脱敏正文已经携带准确行号时，目标摘要才可省略重复的类型、语言、行号，并从 `provenance_defaults.targets` 继承相同来源与精度。缺失、陈旧、不匹配或部分证据不能触发该压缩，显式来源覆盖值保持不变。正文随后必须让位时，将原始坐标还给目标用于后续读取。空的可选区块和末级选择说明先于正文被裁剪，最终响应仍受原始字节上限限制。

交付指标第二版将每个必要身份划分为完整正文、正文缺失、经验证的原文部分交付、不可用正文证据。部分交付必须匹配当前 SHA、原文和实际行号，与标注片段有重叠，并明确未脱敏；它不获得完整正文或完整片段字节分。有效完整副本优先于无效重复副本。查询失败另记为 `unobserved_body_due_to_error_count`，不伪装成成功请求中的正文缺失。JSON 和 Markdown 保留全部五类计数，它们的总和应等于必要身份分母。

## 尚未测量

真实 LSP 的 definition/references/implementation 准确率、完整 MCP 网络链路、独立测试映射质量、模型理解、自主找 bug、生成补丁正确率和 CPU/RSS 均不在本轮测量中。现有 fast-context、repo-rank 和 IO 微测量保留独立入口，没有冒充已由本报告统一执行。
