# 换模型后仍然可用的失败记忆

已验证的共同变更历史用于改善代码检索，故意排除失败修改；它并不能告诉下一模型为何安全编辑或验证失败。本次源码实现复用本地工程历史，记录有界的原生失败类别，再通过 `agent_context` 和带范围的 Worker 交接召回固定纠错提示。

类别涵盖旧 SHA、缺少原生批准、受保护路径、源码行数上限、验证失败、超时、旧 revision 和发现不完整。类别来自原生工具处理，不允许模型提交任意指令作为记忆。不把错误原文、命令输出、源码正文、提示词或推理写进经验。尚不能识别的诊断保持未分类；这一层不会自动推导所有编译器错误或业务缺陷的修复方案。

每条召回规则显示观察次数和是否重复发生。检索结合任务关键词、当前仍可读取的影响路径，以及当前 Project Profile 发现的原生检查 ID。因此，新 Harness 或会话中的普通查询，也能召回没有路径元数据的相关原生失败，不必在查询中写出检查名。检查 ID 只负责选择历史建议，不证明修复或当前验证。最多两条；1,000-token 预算最多一条。已删除路径不会被提升。同项目的新 Harness 或 Workspace 会读取已有历史，其他项目相互隔离。最多保留 512 条工程里程碑；每类原生失败保留最近两个不同事件，避免后续成功读取冲掉旧教训。次数仅代表保留历史，不是终身累计。历史损坏或扫描不完整明确标注。规范文件名、记录内容身份和事件去重防止复制旧记录放大重复次数。

UTF-8 根目录沿用现有存储标识；其他根目录使用平台原生的无损编码，不回退到可能共享的有损标识。旧的非 UTF-8 历史不自动导入，因为其项目归属可能已经混淆。单个运行进程内串行化历史追加和读取，并对旧的超量记录执行有界恢复；这里不承诺跨进程事务。读取失败保持可见，超出当前时钟五分钟的未来记录不参与召回，并标记覆盖不完整。

这是历史建议。原有 SHA 守卫、受保护路径、原生人工批准和确定性验证继续负责执行约束。一条旧记录不证明当前 revision 仍然失败，后来一次成功也不证明旧问题已修复。仓库本地 `.wcode/failure-rules.yaml` 的 literal 已通过真实 MCP journal 回调匹配原生 `payload.error`，复制前按 UTF-8 字节限制为 4,096 字节；参数、stdout 和 stderr 不作为匹配输入，错误原文不落盘。重复里程碑 ID 不增加观察次数。这些仓库规则是不可信的历史建议，不是操作者已批准的 Policy。模型修复方案和因果修复声明仍需要独立证明；同检查的恢复关联不证明原因。这里不保证所有模型都服从提示。

同期修复把多 Agent 交接中的易变遥测移到 MCP `_meta`，保留模型正文里的源码、SHA、revision、租约和权限；并发 Project Profile 复用前也会比对有效权限。内部缓存命中、响应字节、token 估算和供应商实际 cached tokens 分开衡量，目前不声称账单下降。

可运行聚焦 `failure_memory_`、`context_lessons_`、journal、`convention_cache::` 与 Worker Handoff 测试，再使用原生 `review_changes` 和 `verify_project`。源码测试通过不证明此前运行的旧服务进程已经加载新行为。
