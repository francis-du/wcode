# 只读代码变更

下一版实现中，进入**当前变更**并点击文件路径，可以在同一工作区打开只读统一差异，不需要切到 IDE，也不会变成编辑器。支持 **HEAD → 工作树**、**HEAD → 暂存区**、**暂存区 → 工作树**三个比较层。左侧行号对应改前，右侧对应改后；新增和删除同时保留符号与主题颜色。

读取前后观测 HEAD、所选文件的暂存身份及当前文件 SHA。切换比较层时沿用已读取的快照身份；身份发生变化时不返回混合版本补丁，需显式重新读取。快照仅是有界观测，不是事务或持续实时证明。项目刷新、刷新失败、缓存恢复和工作区切换会使详情失效。源码不放入项目快照缓存或本地存储。

未跟踪文件明确显示为源码预览，不伪造已提交基线。所选层差异为空，不代表其他层没有改动。二进制、不可用、脱敏和截断分别说明，不能当成完整代码。补丁上限为 64 KiB；未跟踪源码使用既有 1,000 行读取窗口；浏览器最多绘制 1,500 行并标记截断。服务端还会基于实际返回的变更行生成有界、类型化的改前/改后行区间，不把 hunk 上下文算作变化；相邻变更行会合并，范围覆盖不完整时仍明确标记。浏览器会在变更区间、映射符号起止行及影响关系行/列字段中保持这些坐标的 JSON 整数类型；数字字符串或其他可强制转换的值会直接使载荷失效，不会被转换成源码导航坐标。这些坐标现在会进入有界的改前/改后 Tree-sitter 映射。对同一路径存在基线的跟踪文件，工作层/暂存层会读取精确捕获的 HEAD 源码，未暂存层读取精确捕获的 index 源码，并且只把实际返回的改前变更行映射到基线定义；改后侧保留独立源码身份，暂存层直接解析捕获的 index blob，不会套用更新后的未暂存工作树，工作树映射仍要求匹配已捕获的工作树 SHA。两侧分别展示，每侧最多 128 个符号；脱敏源码不生成符号元数据，变更或 outline 覆盖有界时明确标记 partial。若 outline 的符号列表结构不完整，或某个已声明定义缺失/携带非法行范围或 Tree-sitter 语法身份，该不可用行会被丢弃，但整个符号映射必须保持 `partial=true`，不能把剩余定义冒充完整覆盖。纯新增或纯删除的函数体修改可能让存续函数只在一侧出现变更行重叠，因此仅当精确另一侧快照中 Tree-sitter 能找到唯一且非空限定名与类型都相同的定义时，才补一个仅用于对照展示的 counterpart；每个映射符号都必须携带布尔型 `counterpart_only`；字段缺失或类型错误时浏览器会拒绝该载荷。浏览器不会只相信这个标志：每个符号的 `changed_ranges` 必须与该符号 Tree-sitter 行范围和同侧捕获变更行范围的交集精确一致；直接变更行必须至少有一个精确交集，counterpart-only 必须没有交集且范围列表为空。范围缺失、多余、越出符号范围、顺序错误或与标志自相矛盾都会使载荷 fail-closed，避免把文件级变化提升为函数本体变化。值为 `true` 的行会明确标成**配对对应定义 · 无变更行重叠**，且不携带变更行范围；歧义或缺失时保持为空。仅配对的改后行保持纯展示：不能像直接变更定义那样打开 Code Graph，也不能请求影响分析。真正与变更行直接重叠、且带有返回 `changed_ranges` 的改前/改后定义还会提供**定位变更行**：它只在当前同一份捕获 diff 内跳到对应侧可见的变更行，并在滚动前重新校验当前路径、快照、侧别/节点成员关系和行范围包含关系。counterpart-only 行故意不提供该动作；这只是补丁内导航，不是历史源码读取或语义证明。对唯一的同限定名 + 同类型改前/改后配对，检查器还可以在两侧签名都未脱敏时报告 Tree-sitter 精确签名文本“已变化/未变化”。当改前/改后的精确语法 outline 都完整时，同一语法身份规则还会把有重叠变更的定义保守标为：另一侧恰好一个同身份定义时为“已修改”，另一侧没有同身份定义时为该字面路径内“新增/移除”，歧义身份保持未知。这些都只是语法级观察，不是语义签名、API 兼容性判断、语义影响或重命名证明。精确暂存/index 快照的字节若与当前工作树不同，其符号也只展示，不允许点击跳入代表当前工作树的 Code Graph。第一阶段仍禁用重命名推断，只展示字面路径内的增加和删除，不声称已配对跨文件重命名。

后端复用 Workspace 的受保护路径、符号链接校验和固定形状的 Git 受控执行。当前要求仓库已有 HEAD 且目标父目录可访问；整个目录被删除、合并冲突的暂存条目、子模块、任意提交范围及完整历史源码浏览尚未纳入这一阶段。路径或仓库状态不可用会明确失败，不会变成工作树干净。接口不接收任意命令、提交表达式、写请求或批准。

代码图谱现在补上下一段窄而真实的导航：选中一个已存储图谱节点后，可以打开由该节点自身路径和行范围决定的只读源码窗口。从工作树变更符号发起导航时，浏览器会先确认请求的 Tree-sitter 节点仍属于当前 change-detail 的同一快照、同一工作树 SHA 且 `source_state=worktree` 的符号映射；暂存、过期或不在当前映射中的语法节点会在进入代码图前 fail-closed。通过该检查后，聚焦请求还会携带 change-detail 捕获的精确代码 + Design 版本。服务端会在构建图谱前校验该版本，为这一匹配仓库状态重建当前图谱，并在构建完成后再次校验仓库版本；版本不符或并发漂移会返回 stale-change 冲突，而不是静默跳到更新后的代码。浏览器只提交节点 ID 和图谱快照 ID；服务端从已存储图谱解析路径，经 Workspace 保护边界读取，并且只有当前源码 SHA 仍与节点捕获的源码身份一致时才返回内容。若已经变化则明确返回源码过期冲突，不会静默跳到新版本。源码窗口最多 240 行，脱敏和截断保持可见；即使文件以换行符结尾，渲染出的行号也不会超出服务端返回的起止范围。若响应声明的行区间、焦点范围或源码实际行数彼此不一致，浏览器会直接拒绝该载荷，而不是静默显示不完整源码。它也不会把 Tree-sitter 的语法关系提升成语义证明。

对于由当前工作树精确字节支撑的改后定义，**解释影响**会再次校验同一个变更快照，再针对该变化符号调用语义导航。在任何影响请求发出前，浏览器还必须确认符号映射的路径与快照 ID 仍与当前渲染的 change-detail 一致、映射源码 SHA 仍等于已捕获工作树 SHA，并且所选节点仍是直接命中变更行的改后定义。服务端在精确快照重新映射后也独立执行同一边界：即使 Tree-sitter 节点 ID 相同，只要当前改后符号不是明确的 `counterpart_only=false` 直接变更定义，就不能进入语义导航。变更符号进入 Code Graph、请求影响以及降级语法调用方下钻这三个动作边界都会在执行前重新运行完整符号映射校验，包括与捕获变更行的精确交集；因此内存中后来被修改、过期、跨文件或源码身份不匹配的映射不能被提升成函数级导航，会在不发请求、不跳图谱的情况下 fail-closed。影响请求返回后，浏览器还会针对仍然当前的 change-detail 路径、快照和工作树字节再次执行直接变更符号映射校验；如果映射在请求飞行期间已经变化，关系响应会被拒绝，不能把调用方、引用或实现重新挂到一个已不再满足“直接变更”条件的符号上。请求还会携带 change-detail 捕获的精确全仓库代码 + Design 版本；起始版本不一致会直接拒绝，并且服务端会在跨文件语义/搜索工作完成后再次校验整个仓库版本，确认未漂移后才返回关系。存在可用语言服务器时，可以返回语义级入向调用、引用和实现；语言服务器不可用时，面板会明确说明，并降级为有界的 Tree-sitter 入向调用候选与单独展示的有界精确文本匹配，不会伪造语义引用或实现。文本匹配携带被扫描源码的 SHA 与有界摘录，但它只表示“文本提及”，不是调用方、引用、语义证明或 Verification Evidence。若降级后的 Tree-sitter 调用方保留了具体语法图节点 ID，只有当该调用方节点仍存在于同一所选变更符号和同一快照对应的已接受入向调用结果中时，才可以继续点击进入同一捕获版本绑定的 Code Graph，再下钻到受保护的只读源码预览；导航按这份关系结果校验，而不是按变更文件自身的符号列表校验；浏览器会将这种可导航项明确标成“在代码图中打开 · 语法节点”，只含语义关系的行仍保持仅展示。这个节点 ID 只表示导航来源，不增加任何语义证明强度。实时语义级入向调用、引用和实现不会携带 Tree-sitter 图节点 ID：若语义导航输出混入这类语法身份，服务端会在发布影响结果前判定为无效，浏览器也会独立拒绝试图把它重新混入语义关系的载荷。每类关系/搜索最多 24 条；关系/搜索行格式无效或达到关系上限时，服务端会丢弃不可用行并强制保留 `partial=true`，不会把剩余子集冒充完整结果。若已返回的入向调用、引用、实现或精确搜索集合本身不是数组，也属于畸形载荷并强制 `partial=true`，不能把错误结构解释成“完整但为空”。语义影响中任何必需关系集合缺失、原始 `queried` 覆盖没有精确包含 Impact 所需的 `references`、`implementations`、`calls` 三类查询、实时提供器缺失/畸形 `unsupported` 或 `failures` 结果数组，或对任一 Impact 子查询报告不支持/失败时，都必须保持 `partial=true`；只有对应查询被明确记录为已执行，且两个结果数组都存在并确认没有失败或不支持时，空的语义关系数组才表示完整的“未观测到”。如果提供器声明支持调用层级，`prepareCallHierarchy` 只有在恰好返回一个结构有效的可查询项时，WCode 才会把 `calls` 视为可继续查询。返回 0 个或多个候选都会记录为失败/歧义覆盖，不能任意选择第一个目标。这个唯一项必须具备调用层级协议要求的 name、kind、URI、range 与 selectionRange 结构后才会继续查询，并且两个 range 都必须包含有序的整数型 start/end line 与 character 坐标，start 不能晚于 end；selectionRange 还必须完整包含在外层 range 内。真正发出调用层级查询前，WCode 还会把该 prepared item 绑定到原始请求：URI 必须精确等于被查询文档，selectionRange 必须按 LSP 半开区间语义包含原始查询位置（`start <= position < end`）；查询位置恰好等于 selectionRange 的排他 end 时必须视为位于符号外，并且两个 range 的端点都必须按已协商的位置编码精确落在该源码内。即使结构本身合法，只要它指向另一个文档/符号，或坐标无法映射到请求源码，也会记录为失败的 `calls` 覆盖，而不是“没有调用方”的证据。空 range、坐标不完整、反向 range 或越出外层 range 的 selectionRange 都属于畸形。因此缺失、歧义或畸形的 prepared item 都会让空的入向调用数组保持 partial，不能冒充“已完整确认没有调用方”。语言服务器返回的关系位置还必须携带目标源码上的合法有序 range 结构：已出现的 `selectionRange`、`range`、`targetSelectionRange` 或 `targetRange` 都必须包含整数型 start/end 坐标，且 start 不晚于 end；两个端点都必须按已协商的位置编码精确落到源码。普通 Location 与 LocationLink 的线协议身份不能混用：一行只能由 `uri` 或 `targetUri` 其中一个标识；target-link 必须同时提供 `targetRange` 与 `targetSelectionRange`，且 selection 必须完整包含在 target range 内，普通 `uri` 位置则不能再夹带 target-range 字段。身份混合或自相矛盾的关系会被丢弃，并保持覆盖不完整。调用层级关系项还必须更严格地满足完整 CallHierarchyItem 结构：返回的 `from`/`to` 项都必须包含 name、kind、URI、range 与 selectionRange，且 selectionRange 必须完整落在 range 内；畸形项会被丢弃并保持覆盖不完整。每个关系还必须携带非空 `fromRanges` 数组；其中每个调用点范围都必须有序、完整位于真实调用者符号 range 内（入向调用使用返回的 `from` 项，出向调用使用原始 prepared 源项），并按协商位置编码精确落入调用者源码。缺失、畸形、越出调用者范围或越出源码的调用点范围会丢弃该关系并保持覆盖不完整。UTF-8 偏移不能切开码点或越过逻辑行尾，UTF-16 偏移不能切开码点或越过逻辑行尾，UTF-32 字符索引不能越过逻辑行尾；CRLF 源码中的尾随回车 `\r` 属于换行序列，不是可寻址的 LSP 字符，任何把它当作行内字符的位置都会被拒绝。非法或越出源码的 range 会被丢弃并保持覆盖不完整，而不是被钳制、舍入或只信任其中一个端点。在降级路径中，`syntax_calls.incoming_calls` 缺失、为 null 或结构无效，以及 `keyword_matches` 缺失或非数组时，也必须保持 `partial=true`；某类回退关系不可用不等于“完整但为空”。截断与脱敏标志同样是类型化元数据：已出现但不是布尔值的截断标志必须保守维持 partial；精确搜索行的 `redacted` 若类型异常，则该行不得作为普通源码文本展示，并同时把覆盖标为 partial。降级精确文本匹配若路径为空、行号非正或扫描源码 SHA 无效，也会被视为畸形行并明确使覆盖变为 partial，而不是静默消失。降级 Tree-sitter 调用方若提供了非空但非法的 `node_id`，服务端丢弃这个不可用导航身份时也必须强制 `partial=true`，不能把剩余关系冒充完整。影响关系的行号和列号都必须是从 1 开始的整数，0 或可强制转换的字符串坐标会由浏览器 fail-closed。覆盖不完整时明确显示为“关系有界或不完整”，不称为“证据”。面板会明确标出所选变更符号，并把入向调用方、引用、实现、精确文本匹配分别展示，避免把不同含义合并在一起。服务端会先校验原始语义导航来源：已出现的 `degraded` 字段必须是布尔值，类型异常时不能静默按未降级语义结果处理；运行时真实降级路由 `degraded_syntax_and_keyword_search` 只有在语法来源一致时才被接受，并规范化为公开的 `routing=syntax-degraded`；降级结果若夹带语义引用或实现则判定为无效，而不是静默丢弃后继续。服务端只接受运行时真实语义路由 `cross_file_semantic`，并规范化为浏览器公开的 `routing=lsp`；原始 `lsp` 不作为运行时语义来源接受。原始语义导航 path 也必须存在且精确等于当前所选变更路径，不能把另一个文件产生的关系重新贴到当前变更上。返回的语义导航 selector 还必须继续绑定所选直接变更定义：selector 的源码 revision 必须等于捕获的工作树 SHA，解析出的起始行必须等于所选变更符号行，且解析名称必须精确等于所选变更符号选择器。对实时语义结果，provider 返回的查询行与列也必须存在，并与 selector 的行列精确一致；若 provider 来自另一条路径、实际查询或解析到了另一位置、解析成另一名称，或查询/selector 身份不完整，则直接判定影响不可用，不能重新贴到请求符号上。浏览器会拒绝自相矛盾的精度元数据：语法回退只有在 `provider=tree-sitter+search`、`routing=syntax-degraded`、`degraded_from=lsp` 全部一致且不携带语义引用/实现时才接受；语义结果必须使用 `routing=lsp`，并保留运行时真实 LSP 身份 `provider=lsp:<provider-id>`；任意非 LSP provider 名称以及专属于语法回退的 `provider=tree-sitter+search` 都会被拒绝，且语义结果不能同时声称已降级、携带降级搜索匹配或 Tree-sitter 节点 ID。实时语义输出只标记为“关系”，不称为 Verification Evidence。若精确暂存/index 快照与工作树字节不同，则不能使用这个面向当前工作树的影响动作。

集合型 LSP 导航响应同样按协议形状 fail-closed：references 只接受数组或 `null`；definition 和 implementation 只额外允许单个直接 `Location` 归一化为一项数组。在这一边界，普通直接 `Location` 必须严格是 `uri` + `range` 线协议形状；若对象同时携带 `selectionRange`，它既不是普通 Location，也不会被借用 CallHierarchyItem 的形状而接受，调用层级项自己的 `selectionRange` 仍走独立严格校验。集合型响应若返回单个对象，或协议要求 link 数组时返回单个 `LocationLink`，都会被拒绝并保持语义覆盖不完整，不会发布伪造关系。

变更详情现在还会在文件/符号读取前后捕获权威的全仓库代码 + Design 版本。如果响应完成前仓库版本发生变化，请求会 fail-closed，不会把某个文件快照和另一份仓库字节对应的证据拼在一起。内联验证面板只有在当前已加载 proof 的代码版本和 Design 版本都与该捕获版本精确一致时，才展示项目级有效 Verification Evidence；版本不匹配、历史通过和测试映射都会被隐藏，不会冒充当前证明。浏览器还会对 proof 自身的矛盾元数据 fail-closed：有效结果分类计数必须等于声明总数，返回条目数/截断状态必须符合最多 24 条的边界约定，当前版本证据分类计数必须可对账，验证计划 ready + blocked 必须等于当前计划总数，验收汇总的 total/mapped/executed/passed/fresh 必须都是非负整数，mapped 与 executed 不能超过 total，passed 与 fresh 不能超过 executed，证据条目结果也必须属于已知状态。合法 proof 还会直接展示验收的已映射/已执行/已通过/当前版本计数；“当前版本”只表示与本次捕获 revision 一致的新鲜度，不是额外的通过结论。Project Observatory 和其中的 RiskStatus 现在都会携带构建它们时使用的精确代码 + Design 版本，并且 Observatory 在缓存或返回快照前会再次校验仓库版本。只有本次变更捕获版本、Project Observatory 版本、proof 版本和 RiskStatus 版本四者完全一致时，检查器才展示有界项目风险；Observatory 或独立风险评估期间发生仓库漂移会 fail-closed，项目/proof/risk 任一版本过期或不匹配都会隐藏风险。结构化风险与缺陷候选仍只是上下文，启发式候选会明确标记，绝不会提升为 Verification Evidence。证据计数、计划就绪度与风险上下文都只是项目级结论，不代表某个所选函数本身正确或错误。

这是不打开 IDE 审查变更的一个可用环节。重命名配对与符号级验证归因仍是独立后续工作；能看到补丁、语法/语义影响关系或源码/调用关系图不等于变更正确或测试充分。
