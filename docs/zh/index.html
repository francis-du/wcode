01 · 快速开始

在准备授权的仓库里启动。

wcode 会发现根目录下的项目边界，并把它们作为彼此隔离的子空间；本地和远程客户端使用同一套受控工具。

1

安装

curl -fsSL https://raw.githubusercontent.com/francis-du/wcode/main/install.sh | sh

适用于 macOS 与 Linux；Windows 可使用仓库中的 PowerShell 安装脚本。

2

启动运行时

wcode --workspace "$PWD"

TUI 会立即显示当前 MCP 地址、隧道、OAuth 会话、待授权请求和各子空间的任务。

3

配置本地客户端

wcode --workspace "$PWD" agent-plugin --install-all --dry-run

先看计划，再去掉 --dry-run 执行。网页客户端使用当前 HTTPS /mcp 地址，并在浏览器完成 OAuth。

通过 HTTPS 连接 Grok

启动 wcode，按 O 打开设置中心，复制当前 /mcp 地址并完成 OAuth。

wcode -w "$PWD"
本地和远程分开配置

Claude Code 可使用项目内 stdio；Claude 网页连接器使用当前 HTTPS 地址和 OAuth。

wcode -w "$PWD"
先确认客户端能力

账户级连接器不能由仓库代为安装。设置中心会显示连接地址和仍需在客户端完成的步骤。

wcode -w "$PWD"
按客户端选择传输方式

本地优先 stdio，远程优先 Streamable HTTP。旧客户端可使用 /sse 与 POST /message；网络连接仍须通过 OAuth。

wcode -w "$PWD"
真实界面

连接、任务和授权放在一张主屏。

TUI 固定展示当前入口、OAuth、四项运行指标、子空间活动和 30 秒吞吐；更细的访问控制与项目状态留在受保护的 WebUI。

02 · 客户端

按客户端能力选择传输方式。

本地 MCP：stdio。远程首选：/mcp 上的 Streamable HTTP + OAuth。旧客户端兼容：/sse 加 POST /message。三种方式共用同一套 Harness 和 Workspace 策略。具体步骤见 集成文档 ↗。

“已验证配置格式”只表示 wcode 能安全合并项目文件，不代表该客户端的每个版本都完成过 OAuth 端到端测试。未知或带注释的配置结构会保持原样。

03 · 软件智能

把需求、设计、实现、变更和证据放进同一个可观测项目。

现在同时支持 MCP、本地 CLI（wcode intelligence / wcode verification）、实时 TUI（I）以及受本机高熵 UI Token 保护的项目观测台（W）。WebUI 以需求和功能点为中心，对照组件设计与当前代码实时生成的实现/依赖关系，并把验收验证、ADR、代码统计、Git 改动与架构版本映射回每个功能；通用软件图谱继续作为底层智能能力，而不是主界面的球图。

01

定义目标状态

在仓库中加入 .wcode/project.yaml 与 .wcode/design/，把需求、组件、约束、验收条件和决策变成结构化设计状态。

02

按功能点观察实现

项目观测台展开“需求 → 组件 → 当前实现 → 验收/验证”，并对照声明依赖和代码依赖；同时显示每个功能的代码规模、全仓语言/产品范围统计、当前 Git 改动和架构版本。

03

分析变更

实现后依次使用 review_changes、drift_status、impact_analysis、risk_status。变更审查还会对 1k 行阈值跨越、单文件集中增长和大规模跨范围改动产生有界的可维护性信号。

04

验证并留下证据

verification_plan 创建独立盲审任务；中等及以上风险会加入单独的 maintainability_review，正确性审查不能替代它。跨语言属性测试、变异测试、模糊测试和运行时执行器写入真实阶段证据；verify_project 写入确定性证据。

推荐调用顺序

Coding 从 agent_context(goal, scopes=...) 开始，并按 readiness / next_actions 执行。普通定位继续走低成本的 find_symbol / search_code；只有 Readiness 推荐跨文件 Reference、Caller、Implementation、Rename Impact 等语义关系时才调用 semantic_navigation。Scope / Design / Project 等 Broad Context 只在任务确实需要时加载。改完后先执行 review_changes 与 verify_project，再按风险补 Drift / Impact / Risk / 独立 Maintainability Review / Evidence。产品范围文档 ↗ · 可维护性策略 ↗

证据、验证、语义事实、图谱提供方版本/历史、收敛计划、MCP 任务与执行状态都按工作区持久化，运行时重启后仍可恢复。

22 种索引语言现在每一种都恰好拥有一个经过测试的 Canonical LSP Launch Profile，而且每个 Profile 都会真实 Spawn stdio Mock LSP 并完成 Initialize Handshake；PHP、Python、Ruby 保留显式 Installed-provider Alternate。Warm Session 会遵守每个 Server 声明的 Full/Incremental/None Document Sync Contract；后台 Graph Indexing 与前台 semantic_navigation 复用同一个 Session。Stale Semantic Fact 自动退出消费链，普通定位仍默认走 Syntax/Search。

属性测试、变异测试、模糊测试和运行时金丝雀使用跨语言执行器注册表，并按执行方采用失败关闭方式聚合证据。支持 MCP 2026 Tasks 扩展的客户端可把语义刷新和阶段执行作为可持久轮询任务执行；旧客户端或未显式启用的请求保持同步路径。

01

协议双栈 + Tasks

支持 MCP 2026 无状态请求、Header 路由、缓存提示，以及显式启用的 io.modelcontextprotocol/tasks 长任务；2024/2025 或未声明 Tasks 的客户端继续使用原同步路径。

02

标准 OAuth

客户端从 401 Bearer Challenge 发现元数据，通过 PKCE 与 DCR 完成浏览器授权。

03

有界并行

全局信号量反映真实任务；路径资源调度器会在执行前识别读写冲突、父子目录依赖、移动/删除关系。同一文件、同一 SHA 且范围不冲突的编辑可以安全合并。

04

精确上下文

优先使用符号、项目上下文和批量检索，减少无意义整文件输入。

05 · 连接流程

OAuth 是 MCP 体验的一部分。

无需把长期 API Key 粘贴到任意第三方客户端。兼容客户端可直接从受保护的 MCP 地址发现授权服务器。

MCP 客户端wcode /mcpwcode OAuth浏览器
1 · 发现POST /mcp401 + resource_metadata
2 · 元数据/.well-known/…
3 · 注册POST /register · DCR
4 · 授权/authorize + PKCE六位验证码
5 · TokenPOST /token
6 · 使用工具Bearer + POST /mcptools/list · tools/call
为什么仍支持 DCR？

新版 MCP 更偏向 Client ID Metadata Document，但保留 DCR 兼容路径。wcode 默认不抓取任意客户端提供的元数据 URL，以免新增 SSRF 和出站网络信任边界。

06 · 安全模型

权限本身就是产品能力。

模型不会继承整台电脑。路径、写入、命令、OAuth Token 和并发任务都经过明确边界。

⌂

工作区隔离

模型只能看到 --workspace 指定的根目录；绝对路径、父级穿越、符号链接别名、过宽根目录和凭据路径默认拒绝。

↻

防止陈旧写入

编辑依赖 SHA-256 前置条件，写入保持原子和有界。删除走单独授权路径：只允许在本地 TUI 或受保护 WebUI 精确一次性批准后删除一个普通文件或空目录。

⌘

默认不使用 Shell

命令以参数数组执行。高风险仓库操作默认失败关闭：操作者可以在本地 TUI 或受保护 WebUI 对精确操作做会话授权后重试；模型请求的非默认裸可执行程序名也会进入按工作区管理的待授权列表；--allow-risky-exec 是更宽的进程级预授权。

◉

OAuth + 配对

PKCE 保护授权码；重定向地址受限；访问 Token 绑定资源；刷新 Token 轮换。

◎

来源校验

请求包含 Origin 时必须匹配配置的公网 MCP 来源，降低 DNS Rebinding 风险。

≋

真实可观测

TUI 显示真实排队、运行、完成、失败和槽位占用，不模拟智能体活动。

常见问题

为什么需要公网 URL？

Grok、Claude 等网页客户端从平台服务器发起连接，无法访问你的 localhost。wcode 默认创建可自动切换服务商的临时 HTTPS 隧道，也支持 --public-url。

重启后 OAuth 会话还在吗？

会。Client 注册和 Token 按配置的 Workspace 根目录保存，重启后重新载入。新隧道仍须通过当前实例健康校验，授权页也只使用客户端实际打开的域名。

隧道会绕过认证吗？

不会。隧道只提供可达性；MCP 端点仍需要 OAuth。

wcode 会绕过平台额度或订阅吗？

不会。模型调用仍受平台订阅、额度、令牌、消息数、速率或自备密钥账单约束。

为什么不是所有平台都显示原生支持？

部分平台只说明支持远程 HTTP/SSE，没有说明 OAuth 发现流程。wcode 不会静默降低认证要求。
